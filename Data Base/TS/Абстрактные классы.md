**Абстрактный класс** — это базовый класс (шаблон), от которого можно наследоваться, но **нельзя создать его прямой экземпляр** (через `new`). 

Он нужен для того, чтобы вынести общую логику для группы родственных классов, а также заставить эти классы реализовать определенные методы.

**Аналогия:** 
Абстрактный класс — это чертеж автомобиля с уже установленным двигателем, но без кузова. Вы не можете выехать на чертеже на дорогу (нельзя сделать `new`), но вы можете взять этот чертеж, достроить кузов (наследоваться) и получить готовую машину (седан, грузовик и т.д.).

### Главные правила абстрактных классов

1. Объявляются с помощью ключевого слова `abstract`.
2. Нельзя создать экземпляр: `new MyAbstractClass()` выдаст ошибку.
3. Могут содержать **обычные методы** (с реализацией) — они достанутся наследникам "как есть".
4. Могут содержать **абстрактные методы** (без реализации) — наследники **обязаны** написать для них код.

### Базовый пример

Давай посмотрим, как это работает на классическом примере с животными:

```typescript
// 1. Создаем абстрактный класс
abstract class Animal {
  constructor(public name: string) {}

  // Обычный метод (есть реализация). Наследники получат его бесплатно.
  move(): void {
    console.log(`${this.name} передвигается...`);
  }

  // Абстрактный метод (НЕТ реализации). Наследники ОБЯЗАНЫ его написать.
  abstract makeSound(): void;
}

// const pet = new Animal("Зверь"); // ОШИБКА! Нельзя создать экземпляр абстрактного класса

// 2. Наследуемся от абстрактного класса
class Dog extends Animal {
  // Мы обязаны реализовать makeSound, иначе TypeScript выдаст ошибку
  makeSound(): void {
    console.log("Гав-гав!");
  }
}

class Cat extends Animal {
  makeSound(): void {
    console.log("Мяу!");
  }
}

const myDog = new Dog("Рекс");
myDog.move();      // Выведет: Рекс передвигается... (метод из базового класса)
myDog.makeSound(); // Выведет: Гав-гав! (метод из класса Dog)
```

### Реальный пример из Frontend-разработки

Где это применяется на практике? Например, при создании сервисов для работы с API. У вас может быть базовый класс, который умеет делать запросы и обрабатывать ошибки, а конкретные классы будут указывать URL и специфичную логику.

```typescript
// Базовый абстрактный класс для работы с сетью
abstract class ApiService {
  protected baseUrl = "https://api.example.com";

  // Общий метод для всех сервисов (например, обработка ошибок)
  protected async fetchWithHandling(endpoint: string, options?: RequestInit) {
    try {
      const response = await fetch(`${this.baseUrl}${endpoint}`, options);
      if (!response.ok) throw new Error("Сетевая ошибка");
      return await response.json();
    } catch (error) {
      this.logError(error);
      throw error;
    }
  }

  private logError(error: any) {
    console.error(`[API Error]:`, error);
  }

  // Абстрактный метод: каждый сервис должен сам знать, как получить свои данные
  abstract getAll(): Promise<any[]>;
}

// Конкретный сервис для пользователей
class UserApiService extends ApiService {
  // Обязаны реализовать getAll
  async getAll(): Promise<any[]> {
    // Используем готовый метод из абстрактного класса
    return this.fetchWithHandling("/users");
  }

  // Можем добавлять свои специфичные методы
  async getUserById(id: number) {
    return this.fetchWithHandling(`/users/${id}`);
  }
}

const userService = new UserApiService();
userService.getAll().then(users => console.log(users));
```

### 🔥 Главный вопрос с собеседования: Абстрактный класс VS Интерфейс

Это спрашивают в 90% случаев, когда речь заходит об ООП в TypeScript.

| Характеристика | Interface (Интерфейс) | Abstract Class (Абстрактный класс) |
| :--- | :--- | :--- |
| **Реализация методов** | ❌ Не может содержать реализацию (только описание типов). | ✅ Может содержать готовую логику (обычные методы). |
| **Множественное наследование** | ✅ Класс может реализовать (`implements`) **много** интерфейсов. | ❌ Класс может наследоваться (`extends`) только от **одного** абстрактного класса. |
| **Модификаторы доступа** | ❌ Не поддерживает `private`, `protected` (всё публичное). | ✅ Поддерживает `public`, `private`, `protected`. |
| **Что остается в JS коде?** | ❌ Ничего. Интерфейсы существуют только в TS и удаляются при компиляции. | ✅ Превращается в обычный класс (функцию-конструктор) в JavaScript. |

**Когда что использовать?**
*   Используйте **интерфейс**, если вам нужно просто описать "форму" объекта или контракта (например, `Props` в React или структуру данных от сервера).
*   Используйте **абстрактный класс**, если у вас есть **общий код** (реализация), который вы хотите переиспользовать в нескольких родственных классах.

---
### Чек-лист для повторения перед собеседованием:
1. **Что это?** Класс-шаблон, от которого можно наследоваться, но нельзя создать экземпляр (`new`).
2. **Ключевое слово:** `abstract`.
3. **Абстрактные методы:** Методы без тела, которые классы-наследники **обязаны** реализовать.
4. **Обычные методы:** Могут быть внутри абстрактного класса, наследники получают их автоматически.
5. **Отличие от интерфейса:** Абстрактный класс может содержать реализацию кода и модификаторы доступа (`protected`/`private`), но наследоваться можно только от одного класса. Интерфейс — это просто контракт без логики, и их можно имплементировать сколько угодно.
