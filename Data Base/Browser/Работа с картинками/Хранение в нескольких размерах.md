### Суть концепции

Хранение изображений в нескольких размерах — это практика подготовки нескольких версий одной и той же картинки с разным разрешением (шириной в пикселях) для оптимизации доставки контента.

### Для чего это нужно (Как работает)

У пользователей могут быть совершенно разные устройства:
1. Мобильный телефон с шириной экрана 375px.
2. Ноутбук с шириной 1440px.
3. Устройства с экранами повышенной плотности пикселей (Retina-дисплеи, плотность 2x, 3x).

Если мы загрузим на сервер одну гигантскую картинку (например, 3000px в ширину), десктоп ее покажет нормально. Но мобильный телефон скачает огромный файл (скажем, 2 МБ) только для того, чтобы сжать его до 300px ширины экрана. Это колоссальная трата трафика и батареи.

Решение: мы генерируем несколько вариантов, например:
- `hero-small.jpg` (400px)
- `hero-medium.jpg` (800px)
- `hero-large.jpg` (1600px)

Браузер сам выберет и скачает подходящий файл.

### Примеры использования

Реализуется это с помощью атрибутов `srcset` и `sizes` (см. `[[Атрибуты srcset и sizes]]`) на теге `<img>`:

```html
<!-- Пример для экранов с разной плотностью пикселей (Retina) -->
<img 
  src="logo-1x.png" 
  srcset="logo-1x.png 1x, logo-2x.png 2x, logo-3x.png 3x" 
  alt="Логотип"
>
```

```html
<!-- Пример для адаптивной верстки (разная ширина экранов) -->
<img 
  src="photo-large.jpg" 
  srcset="photo-small.jpg 400w, photo-medium.jpg 800w, photo-large.jpg 1600w" 
  sizes="(max-width: 600px) 100vw, 50vw"
  alt="Фото"
>
```

### Частые ошибки

1. **Ручная нарезка картинок:** Разработчик не должен вручную создавать 5 версий каждой картинки в фотошопе. Это должно быть автоматизировано через CDN (многие CDN умеют менять размер на лету через параметры URL, например `image.jpg?w=400`), либо через плагины сборщика (webpack/vite).
2. **Забытый `src`:** Атрибут `src` обязателен как фолбэк для браузеров, которые не понимают `srcset` (хотя сейчас таких почти не осталось), или если ни одно условие из `srcset` не сработало.
