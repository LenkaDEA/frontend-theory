### Что такое код-сплиттинг (Code Splitting)

Код-сплиттинг — это техника разделения одного большого бандла (файла со всем скомпилированным кодом) на несколько более мелких файлов (чанков), которые могут загружаться параллельно или по требованию (ленивая загрузка). Это значительно уменьшает время первичной загрузки страницы.

### Как работает в Webpack

Webpack собирает граф зависимостей. Без код-сплиттинга всё собирается в один `main.js`. С помощью код-сплиттинга Webpack понимает, где можно "разорвать" граф и вынести часть кода в отдельный файл.

В Webpack есть три основных подхода к разделению кода:
1. **Точки входа (Entry Points):** Ручное разделение кода через настройку `entry`.
2. **Предотвращение дублирования (Prevent Duplication):** Использование `SplitChunksPlugin` для вынесения общих зависимостей (например, библиотек из `node_modules`) в отдельный чанк (vendor chunk).
3. **Динамические импорты (Dynamic Imports):** Разделение кода внутри самих модулей с помощью синтаксиса `import()`.

### Примеры использования

#### Разделение через SplitChunksPlugin (выделение vendor)

Позволяет закэшировать тяжелые библиотеки (React, Vue, lodash), которые редко меняются, отдельно от кода приложения.

```javascript
// webpack.config.js
module.exports = {
  optimization: {
    splitChunks: {
      chunks: 'all', // применять для синхронных и асинхронных чанков
      cacheGroups: {
        vendor: {
          test: /[\\/]node_modules[\\/]/,
          name: 'vendors',
          chunks: 'all',
        },
      },
    },
  },
};
```

#### Динамические импорты (Lazy Loading)

См. также: [[Разделение кода (code splitting) через динамические импорты]] и [[Lazy loading маршрутов]].

```javascript
// Код будет вынесен в отдельный чанк и загружен только при клике
button.addEventListener('click', () => {
  import('./heavy-module.js')
    .then((module) => {
      module.doSomethingHeavy();
    })
    .catch((err) => console.log('Chunk loading failed'));
});
```

### Частые ошибки

1. **Слишком много мелких чанков:** Излишнее разделение (например, каждый крошечный компонент в свой чанк) может ухудшить производительность из-за накладных расходов на HTTP-запросы (особенно в HTTP/1.1).
2. **Дублирование кода в чанках:** Если не настроить `SplitChunksPlugin`, одна и та же библиотека (например, `lodash`) может попасть в несколько разных чанков, увеличивая общий объем загружаемого кода.
3. **Некорректная обработка ошибок:** При ленивой загрузке файлов по сети всегда нужно предусматривать вариант, что сеть может пропасть (обработка `catch` при `import()`).
