### Что такое предзагрузка ресурсов (Resource Hints)

Предзагрузка ресурсов — это механизмы (Resource Hints), с помощью которых разработчик может дать браузеру подсказки о том, какие ресурсы (скрипты, стили, шрифты, картинки) или соединения понадобятся в ближайшее время. Браузер начинает их загрузку или подготовку заранее в фоновом режиме, что ускоряет отображение контента.

### Основные механизмы

1. **`preload`**: Директива для загрузки критически важных ресурсов для текущей страницы, которые понадобятся в самом начале загрузки, но браузер может обнаружить их поздно (например, шрифты или картинки внутри CSS).
2. **`prefetch`**: Директива для ресурсов, которые понадобятся на *следующей* странице (или при следующем действии пользователя). Браузер загрузит их с низким приоритетом в свободное время.
3. **`preconnect`**: Указывает браузеру заранее установить соединение (DNS, TCP, TLS handshake) со сторонним доменом (например, с API или CDN), откуда скоро будут запрашиваться ресурсы.
4. **`dns-prefetch`**: Более легкий вариант `preconnect`, выполняет только резолв доменного имени в IP-адрес.

### Примеры использования

Реализуется с помощью тега `<link>` в `<head>` документа:

```html
<!-- Предзагрузка критического шрифта (атрибуты as и crossorigin обязательны) -->
<link rel="preload" href="/fonts/my-font.woff2" as="font" type="font/woff2" crossorigin="anonymous">

<!-- Предзагрузка важной картинки для LCP (Largest Contentful Paint) -->
<link rel="preload" href="/hero-image.jpg" as="image">

<!-- Подготовка к переходу на другую страницу -->
<link rel="prefetch" href="/next-page-bundle.js" as="script">

<!-- Заранее устанавливаем соединение с API сервером -->
<link rel="preconnect" href="https://api.my-app.com">
```

### Частые ошибки

1. **Забытый атрибут `as` или `crossorigin` для шрифтов:** Если использовать `preload` для шрифтов без атрибута `crossorigin`, браузер загрузит шрифт дважды (один раз через preload анонимно, второй раз — когда найдет его в CSS). Атрибут `as` также критичен для правильной приоритизации загрузки.
2. **Чрезмерное использование `preload`:** Если предзагружать слишком много ресурсов, это создаст конкуренцию за канал связи, и по-настоящему критичные ресурсы (например, основной CSS) будут загружаться дольше. `preload` нужен только для самого важного.
3. **Путаница между `preload` и `prefetch`:** Использование `prefetch` для ресурсов текущей страницы приведет к тому, что они загрузятся слишком поздно (так как у `prefetch` низкий приоритет), а `preload` для следующей страницы потратит трафик пользователя прямо сейчас на то, что ему пока не нужно.
