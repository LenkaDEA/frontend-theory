### Что такое минификация

Минификация — это процесс уменьшения размера исходного кода путем удаления ненужных символов (пробелов, переносов строк, комментариев) и сокращения имен переменных и функций без изменения функциональности кода. Это позволяет ускорить загрузку скриптов и стилей в браузере.

### Принцип работы в Webpack

В контексте Webpack минификация обычно происходит на этапе сборки (build) для production окружения. Webpack использует плагины для анализа AST (Абстрактного синтаксического дерева) кода и его трансформации в более компактный вид. 

По умолчанию, начиная с версии 4, Webpack автоматически минифицирует JavaScript код в режиме `mode: 'production'` с помощью встроенного плагина `TerserPlugin`. Для минификации CSS требуется отдельный плагин.

### Примеры использования

Настройка минификации в `webpack.config.js`:

```javascript
const TerserPlugin = require("terser-webpack-plugin");
const CssMinimizerPlugin = require("css-minimizer-webpack-plugin");

module.exports = {
  mode: 'production', // Включает встроенную минификацию JS
  optimization: {
    minimize: true,
    minimizer: [
      // Тонкая настройка минификации JS
      new TerserPlugin({
        terserOptions: {
          compress: {
            drop_console: true, // удаляет console.log
          },
        },
      }),
      // Минификация CSS (требует MiniCssExtractPlugin)
      new CssMinimizerPlugin(),
    ],
  },
};
```

### Частые ошибки

1. **Включение минификации в development-режиме:** Минификация — ресурсоемкий процесс. Если включить её во время разработки, сборка и пересборка (HMR) будут сильно тормозить.
2. **Отсутствие Source Maps на проде при ошибках:** Минифицированный код невозможно читать и отлаживать. Для мониторинга ошибок (например, в Sentry) необходимо генерировать Source Maps, но не загружать их для обычных пользователей (использовать `devtool: 'hidden-source-map'`).
3. **Поломка кода после агрессивной минификации:** Иногда минификаторы могут слишком агрессивно переименовывать переменные (mangling) в сторонних библиотеках или ломать логику, если она полагается на имена функций (например, `Function.name`).
