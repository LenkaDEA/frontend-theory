### Что такое CDN (Content Delivery Network)

CDN (сеть доставки контента) — это географически распределенная сеть серверов (называемых Edge Servers или периферийными серверами), которые хранят кэшированные копии статических ресурсов (картинки, JS, CSS, шрифты, видео). 

### Принцип работы

Обычно сервер вашего приложения (Origin Server) находится в определенной локации (например, во Франкфурте). Если пользователь из Токио запрашивает сайт, данные идут через полмира, что вызывает большую задержку (ping / latency).

При использовании CDN контент кэшируется на сотнях серверов по всему миру. Когда пользователь делает запрос, DNS направляет его к **ближайшему к нему серверу CDN**. 
Это дает два главных преимущества:
1. **Снижение задержки (Latency):** Ресурсы отдаются с сервера, который физически находится в том же городе или стране.
2. **Разгрузка Origin сервера:** Сервер приложения больше не тратит ресурсы на отдачу статики, CDN берет эту нагрузку на себя.

### Примеры использования

Обычно CDN настраивается так: вы загружаете статику на S3 bucket (Origin), к которому привязан CDN провайдер (Cloudflare, Amazon CloudFront, Akamai). В HTML вы указываете ссылки на домен CDN.

```html
<!-- Использование публичной CDN для популярных библиотек -->
<script src="https://cdnjs.cloudflare.com/ajax/libs/react/18.2.0/umd/react.production.min.js"></script>

<!-- Раздача статики своего приложения через свой CDN -->
<link rel="stylesheet" href="https://cdn.my-app.com/assets/main.css">
```

### Частые ошибки и нюансы

1. **Инвалидация кэша (Cache Invalidation):** Самая частая проблема с CDN — пользователи видят старую версию сайта. Для решения этой проблемы к именам файлов при сборке добавляют хэш (например, `main.a3b4c1.js`). Таким образом, каждый новый билд создает уникальные имена файлов, и CDN загружает их как новые.
2. **Проблемы с CORS:** Если ваши ресурсы (например, шрифты или данные) раздаются с домена `cdn.my-app.com`, а сайт находится на `my-app.com`, шрифты могут не загрузиться из-за политики CORS (Cross-Origin Resource Sharing). Необходимо правильно настроить заголовки на стороне CDN (`Access-Control-Allow-Origin`).
3. **Использование CDN для динамических данных:** CDN отлично работает для статики, но кэширование динамических API-ответов на CDN (краевое кэширование) требует очень осторожной настройки, иначе пользователи могут увидеть чужие личные данные.
