**Бесконечный скролл (Infinite Scroll)** — это паттерн пользовательского интерфейса (UI), при котором контент подгружается непрерывно по мере того, как пользователь прокручивает страницу вниз. Это избавляет от необходимости использовать классическую пагинацию (кнопки «1, 2, 3... Следующая»).

**Цель:** Удержание внимания пользователя (как в лентах соцсетей) и обеспечение бесшовного UX.

---

### 2. Как это работает в браузере (Под капотом)

Исторически существовало два подхода к реализации. На собеседовании важно упомянуть оба, чтобы показать кругозор, но акцент сделать на современном.

#### Подход 1: Событие `scroll` (Устаревший и медленный)
Раньше разработчики вешали обработчик на событие `window.addEventListener('scroll', ...)`. 
Внутри обработчика происходили математические вычисления:
`Высота окна + Текущая прокрутка >= Общая высота документа - Порог (offset)`
*   **Почему это плохо:** Событие `scroll` срабатывает десятки раз в секунду (синхронно в главном потоке). Чтение свойств вроде `offsetHeight` или `scrollTop` вызывает **Layout Thrashing** (принудительный перерасчет макета страницы браузером). Это сильно бьет по производительности (FPS падает, страница "лагает"). Приходилось использовать `throttle` или `debounce`, но это лишь костыль.

#### Подход 2: `Intersection Observer API` (Современный стандарт)
Это встроенный в браузер API, который позволяет асинхронно наблюдать за пересечением одного элемента (target) с другим (или с видимой областью браузера — viewport).
*   **Как это работает:** 
    1. Мы создаем пустой `<div>` (его часто называют *sentinel* или *trigger*) и помещаем его в самый конец нашего списка элементов.
    2. Мы просим `IntersectionObserver` следить за этим `<div>`.
    3. Как только пользователь доскролливает до конца списка, этот `<div>` появляется в зоне видимости (viewport).
    4. Браузер **асинхронно** (не блокируя главный поток рендеринга) вызывает наш callback.
    5. В callback мы делаем запрос к API за новой порцией данных.
*   **Почему это хорошо:** Никаких вычислений высоты, никаких тормозов при скролле. Браузер сам на уровне C++ движка максимально оптимизированно вычисляет пересечения.

### 3. Примеры реализации (React и Vue + TypeScript)

Здесь мы реализуем современный подход с `IntersectionObserver`.

#### Пример на React (с использованием кастомного хука)
В React лучше всего вынести логику обсервера в `useEffect`, привязанный к `ref` элемента-триггера.

```tsx
import { useState, useEffect, useRef, useCallback } from 'react';

interface Item {
  id: string;
  title: string;
}

export const InfiniteScrollList = () => {
  const [items, setItems] = useState<Item[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  const [hasMore, setHasMore] = useState(true);
  const [page, setPage] = useState(1);

  // Ссылка на невидимый элемент в конце списка
  const observerTarget = useRef<HTMLDivElement | null>(null);

  const fetchItems = async (pageNumber: number) => {
    setIsLoading(true);
    try {
      // Имитация запроса к API
      const response = await fetch(`/api/items?page=${pageNumber}`);
      const data: Item[] = await response.json();
      
      setItems((prev) => [...prev, ...data]);
      if (data.length === 0) setHasMore(false); // Если данных больше нет
    } catch (error) {
      console.error("Ошибка загрузки", error);
    } finally {
      setIsLoading(false);
    }
  };

  useEffect(() => {
    // Если грузим или данных больше нет - не создаем обсервер
    if (isLoading || !hasMore) return;

    const observer = new IntersectionObserver(
      (entries) => {
        // Если элемент-триггер появился в зоне видимости
        if (entries[0].isIntersecting) {
          setPage((prev) => prev + 1);
        }
      },
      { threshold: 1.0 } // Сработает, когда элемент полностью появится
    );

    if (observerTarget.current) {
      observer.observe(observerTarget.current);
    }

    // Очистка при размонтировании или изменении зависимостей
    return () => observer.disconnect();
  }, [isLoading, hasMore]); // Пересоздаем обсервер, чтобы у него были актуальные стейты

  // Эффект для загрузки данных при изменении страницы
  useEffect(() => {
    fetchItems(page);
  }, [page]);

  return (
    <div>
      <ul>
        {items.map((item) => (
          <li key={item.id}>{item.title}</li>
        ))}
      </ul>
      
      {/* Тот самый элемент-триггер */}
      <div ref={observerTarget} style={{ height: '20px', background: 'transparent' }}>
        {isLoading && <p>Загрузка...</p>}
      </div>
      
      {!hasMore && <p>Вы просмотрели все элементы!</p>}
    </div>
  );
};
```

#### Пример на Vue 3 (Composition API + `<script setup>`)

Во Vue логика очень похожа, мы используем `ref` для доступа к DOM и хуки жизненного цикла.

```vue
<template>
  <div>
    <ul>
      <li v-for="item in items" :key="item.id">{{ item.title }}</li>
    </ul>
    
    <!-- Элемент-триггер -->
    <div ref="observerTarget" class="observer-target">
      <p v-if="isLoading">Загрузка...</p>
    </div>
    
    <p v-if="!hasMore">Вы просмотрели все элементы!</p>
  </div>
</template>

<script setup lang="ts">
import { ref, onMounted, onUnmounted, watch } from 'vue';

interface Item {
  id: string;
  title: string;
}

const items = ref<Item[]>([]);
const isLoading = ref(false);
const hasMore = ref(true);
const page = ref(1);

const observerTarget = ref<HTMLElement | null>(null);
let observer: IntersectionObserver | null = null;

const fetchItems = async (pageNumber: number) => {
  isLoading.value = true;
  try {
    const response = await fetch(`/api/items?page=${pageNumber}`);
    const data: Item[] = await response.json();
    
    items.value.push(...data);
    if (data.length === 0) hasMore.value = false;
  } catch (error) {
    console.error("Ошибка загрузки", error);
  } finally {
    isLoading.value = false;
  }
};

// Загружаем первую страницу
fetchItems(page.value);

onMounted(() => {
  observer = new IntersectionObserver((entries) => {
    // Проверяем пересечение, а также флаги, чтобы не спамить запросами
    if (entries[0].isIntersecting && !isLoading.value && hasMore.value) {
      page.value++;
      fetchItems(page.value);
    }
  }, { threshold: 1.0 });

  if (observerTarget.value) {
    observer.observe(observerTarget.value);
  }
});

onUnmounted(() => {
  if (observer) {
    observer.disconnect();
  }
});
</script>

<style scoped>
.observer-target {
  height: 20px;
}
</style>
```

### 4. Тонкие моменты и ошибки новичков (Что ценят на собеседованиях)

Если ты расскажешь про эти нюансы, интервьюер поймет, что у тебя есть реальный опыт, а не просто теория:

1. **Race Conditions (Состояние гонки) и спам запросами:**
   * *Ошибка:* Забыть проверить флаг `isLoading`. Пользователь быстро скроллит, триггер пересекается несколько раз, на бэкенд улетает 5 одинаковых запросов за `page=2`.
   * *Решение:* Строгая проверка `if (isIntersecting && !isLoading && hasMore)`.
2. **Утечки памяти (Memory Leaks):**
   * *Ошибка:* Забыть вызвать `observer.disconnect()` при размонтировании компонента.
   * *Решение:* Всегда возвращать функцию очистки в `useEffect` (React) или использовать `onUnmounted` (Vue).
3. **Проблема футера (UX ошибка):**
   * *Ошибка:* Сделать бесконечный скролл на странице, где в самом низу есть важный Footer (контакты, ссылки). Пользователь пытается доскроллить до футера, но контент постоянно отодвигает его вниз. Это бесит.
   * *Решение:* Либо убрать футер с таких страниц, либо после 3-4 автоматических подгрузок показывать кнопку «Загрузить еще».
4. **Сброс скролла при возврате (Scroll Restoration):**
   * *Нюанс:* Пользователь проскроллил 10 страниц, кликнул на товар, перешел на другую страницу, нажал кнопку "Назад" в браузере... и оказался на самом верху списка.
   * *Решение:* Кешировать данные (например, через React Query / Vue Query / Redux / Pinia) и восстанавливать позицию скролла.
5. **Проблема разрастания DOM (DOM Bloat):**
   * *Самая критичная проблема:* Если пользователь проскроллит 100 страниц по 20 элементов, в DOM-дереве окажется 2000 `<li>` элементов. Браузеру придется хранить их все в памяти, рассчитывать для них стили и макет. Страница начнет жестко тормозить, потреблять гигабайты ОЗУ и в итоге вкладка может упасть (Crash).
   * *Решение:* **Виртуализация (Virtualization) / Windowing**.
