**Виртуализация списка (Virtualization / Windowing)** — это техника оптимизации рендеринга больших списков данных. Суть в том, чтобы рендерить в DOM-дерево **только те элементы, которые сейчас видны пользователю на экране** (плюс небольшой запас сверху и снизу для плавности), а остальные элементы заменять пустым пространством, имитирующим их высоту.

**Цель:** Поддерживать стабильный FPS и низкое потребление памяти (RAM), независимо от того, в списке 100 элементов или 1 000 000. В DOM всегда будет находиться фиксированное, небольшое количество узлов (например, 15-20).

### 2. Как это работает в браузере (Под капотом)

Чтобы понять виртуализацию, нужно представить себе "окно" (window), которое скользит по огромному списку данных.

**Основные концепции механики:**

1.  **Контейнер с фиксированной высотой и скроллом:**
    У нас есть внешний `div` (контейнер), которому мы задаем фиксированную высоту (например, `500px`) и `overflow-y: auto`. Именно его мы будем скроллить.

2.  **Внутренний "призрак" (Inner Container):**
    Внутри контейнера лежит еще один `div`. Его высота равна **общей высоте всех элементов списка**, даже тех, которые не отрендерены.
    *Зачем?* Чтобы у внешнего контейнера появился правильный ползунок скролла (scroll thumb). Если элементов 10 000, а высота каждого 50px, высота "призрака" будет 500 000px.

3.  **Вычисление видимых индексов (Math Magic):**
    Когда мы скроллим внешний контейнер, мы слушаем событие `scroll` (здесь оно оправдано, так как нам нужно реагировать на каждый пиксель) и читаем свойство `scrollTop` (на сколько пикселей мы проскроллили вниз).
    *   **Начальный индекс (`startIndex`):** `Math.floor(scrollTop / itemHeight)`
    *   **Конечный индекс (`endIndex`):** `startIndex + Math.ceil(containerHeight / itemHeight)`
    *   *Пример:* Если мы проскроллили 1000px вниз, а высота элемента 50px, значит мы пропустили ровно 20 элементов (`1000 / 50`). Наш `startIndex` = 20. Если высота контейнера 500px, в него влезет 10 элементов (`500 / 50`). Наш `endIndex` = 30.

4.  **Абсолютное позиционирование (или `transform: translateY`):**
    Мы берем данные из массива от `startIndex` до `endIndex`, рендерим их в DOM, но чтобы они не "улетели" вверх (ведь предыдущих элементов в DOM нет), мы сдвигаем их вниз на расстояние, равное высоте пропущенных элементов.
    *Сдвиг (Offset):* `startIndex * itemHeight`.

**Итог:** Пользователь скроллит, ползунок двигается как обычно, но внутри DOM-дерева элементы просто перерисовываются и сдвигаются вниз/вверх, создавая иллюзию огромного списка.

### 3. Примеры использования (React и Vue)

Писать виртуализацию с нуля в продакшене — плохая идея (слишком много краевых случаев). В 99% случаев используют готовые библиотеки.

#### React: `react-window` (или `react-virtualized`)
Библиотека от создателя Redux (Brian Vaughn). `react-window` — это современная, легковесная версия.

```tsx
import { FixedSizeList as List } from 'react-window';

// Массив из 1000 элементов
const items = Array.from({ length: 1000 }).map((_, i) => `Элемент ${i}`);

// Компонент, который отвечает за рендер ОДНОЙ строки
// react-window передает сюда index и style (который содержит позиционирование)
const Row = ({ index, style }: { index: number, style: React.CSSProperties }) => (
  <div style={style}>
    {items[index]}
  </div>
);

export const VirtualizedList = () => (
  <List
    height={500}       // Высота видимого окна (контейнера)
    itemCount={1000}   // Общее количество элементов
    itemSize={50}      // Высота одного элемента (фиксированная)
    width={300}        // Ширина списка
  >
    {Row}
  </List>
);
```
*Что происходит под капотом `react-window`:* Он сам вычисляет `startIndex`, `endIndex`, берет нужный кусок массива и применяет к `Row` стили вида `position: absolute; top: 1000px;`.

#### Vue 3: `vue-virtual-scroller`
Популярное решение для экосистемы Vue.

```vue
<template>
  <!-- RecycleScroller - компонент для элементов одинаковой высоты -->
  <RecycleScroller
    class="scroller"
    :items="items"
    :item-size="50"
    key-field="id"
    v-slot="{ item }"
  >
    <div class="row">
      {{ item.title }}
    </div>
  </RecycleScroller>
</template>

<script setup lang="ts">
import { ref } from 'vue';
// Импорт компонента и стилей (обычно делается глобально, но для примера здесь)
import { RecycleScroller } from 'vue-virtual-scroller';
import 'vue-virtual-scroller/dist/vue-virtual-scroller.css';

const items = ref(
  Array.from({ length: 1000 }).map((_, i) => ({
    id: i,
    title: `Элемент ${i}`
  }))
);
</script>

<style scoped>
.scroller {
  height: 500px; /* Обязательно задать высоту контейнеру */
}
.row {
  height: 50px;
}
</style>
```

### 4. Тонкие моменты и нюансы (Вопросы на "засыпку")

На собеседовании обязательно спросят про сложности виртуализации. Вот главные из них:

1.  **Динамическая высота элементов (Dynamic Height):**
    *   *Проблема:* В примерах выше высота элемента фиксирована (`itemSize={50}`). А что если это лента Twitter или комментарии, где высота текста заранее неизвестна? Формула `Math.floor(scrollTop / itemHeight)` ломается.
    *   *Решение:* Использовать компоненты для динамической высоты (например, `VariableSizeList` в react-window или `DynamicScroller` во Vue).
    *   *Как они работают:* Они рендерят элементы "вслепую" где-то за экраном, измеряют их реальную высоту через `ResizeObserver` или `getBoundingClientRect()`, кэшируют эту высоту и затем пересчитывают позиции всех последующих элементов. Это сложнее и медленнее, чем фиксированная высота.

2.  **Overscan (Запасные элементы):**
    *   *Проблема:* Если рендерить *только* видимые элементы, при быстром скролле пользователь увидит белые пустые места (браузер не успеет отрендерить новые узлы).
    *   *Решение:* Рендерить несколько элементов за пределами видимости сверху и снизу. В `react-window` за это отвечает проп `overscanCount` (например, `overscanCount={5}`).

3.  **Потеря фокуса и состояния внутри элементов:**
    *   *Проблема:* Если внутри виртуализированного списка есть `<input>` и пользователь ввел туда текст, а затем проскроллил так, что `input` ушел из DOM (размонтировался), то при возврате назад состояние `input` будет потеряно (он смонтируется заново пустым).
    *   *Решение:* Хранить состояние (введенный текст) не локально в компоненте строки, а в глобальном стейте (или в стейте родителя) по ID элемента.

4.  **Связка: Бесконечный скролл + Виртуализация:**
    *   *Нюанс:* Как объединить подгрузку данных с виртуализацией?
    *   *Решение:* Библиотеки виртуализации предоставляют коллбэки (например, `onItemsRendered` в react-window). Когда `endIndex` приближается к длине текущего массива `items`, мы делаем API запрос за новой страницей. В экосистеме React для этого часто используют обертку `InfiniteLoader` из библиотеки `react-window-infinite-loader`.

### Резюме для собеседования

Если тебя попросят рассказать про эти темы, идеальный ответ строится так:
1.  "Бесконечный скролл нужен для UX. Раньше делали через событие `scroll`, сейчас — строго через `IntersectionObserver` для производительности."
2.  "Но если данных много, DOM раздуется. Поэтому бесконечный скролл всегда должен идти в паре с **виртуализацией**."
3.  "Виртуализация рендерит только видимое окно элементов, вычисляя индексы на основе скролла и сдвигая элементы абсолютно."
4.  "Самая большая боль виртуализации — элементы с динамической высотой, там приходится измерять и кэшировать размеры."
