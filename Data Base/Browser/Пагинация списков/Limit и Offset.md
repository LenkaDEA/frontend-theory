**Пагинация через Limit и Offset (Offset-based pagination)** — это самый старый, распространенный и интуитивно понятный способ постраничной навигации. 

Суть подхода заключается в том, что клиент (фронтенд) просит у сервера определенное количество записей (`limit`), начиная с определенного смещения от начала списка (`offset`).

*   **Limit (или `take`, `size`, `per_page`)**: Сколько элементов нужно вернуть (размер страницы).
*   **Offset (или `skip`)**: Сколько элементов нужно пропустить с начала списка, прежде чем начать возвращать данные.

---

### 2. Как это работает (Под капотом: Фронтенд + Бэкенд/БД)

#### На стороне Фронтенда
Фронтенд обычно оперирует понятием "Страница" (`page`). Чтобы превратить номер страницы в `limit` и `offset` для запроса, используется простая математика:

*   `limit` = размер страницы (константа, например, 10).
*   `offset` = `(page - 1) * limit`.

*Пример:*
*   Страница 1: `limit=10`, `offset=0` (пропускаем 0, берем первые 10).
*   Страница 2: `limit=10`, `offset=10` (пропускаем первые 10, берем следующие 10).
*   Страница 3: `limit=10`, `offset=20` (пропускаем первые 20, берем следующие 10).

#### На стороне Бэкенда и Базы Данных
Бэкенд получает эти параметры и транслирует их в SQL-запрос (или аналог в NoSQL).
В SQL (PostgreSQL, MySQL) это выглядит буквально так:
```sql
SELECT * FROM users 
ORDER BY created_at DESC 
LIMIT 10 OFFSET 20;
```
**Как база данных выполняет этот запрос (КРИТИЧЕСКИ ВАЖНО для понимания проблем):**
База данных **не может** просто "прыгнуть" к 21-й записи. Чтобы найти записи с 21 по 30, базе данных приходится:
1. Найти, отсортировать и прочитать в память первые 20 записей.
2. Отбросить их (пропустить).
3. Взять следующие 10 записей и вернуть их.

### 3. Примеры использования (React и Vue)

Реализация на фронтенде очень проста, так как состояние зависит только от номера текущей страницы.

#### Пример на React

```tsx
import { useState, useEffect } from 'react';

export const OffsetPagination = () => {
  const [items, setItems] = useState([]);
  const [page, setPage] = useState(1);
  const [totalPages, setTotalPages] = useState(0);
  const limit = 10;

  useEffect(() => {
    const fetchPage = async () => {
      const offset = (page - 1) * limit;
      // Запрос: /api/items?limit=10&offset=20
      const response = await fetch(`/api/items?limit=${limit}&offset=${offset}`);
      const data = await response.json();
      
      setItems(data.items);
      // Бэкенд обычно возвращает общее кол-во записей для расчета страниц
      setTotalPages(Math.ceil(data.totalCount / limit)); 
    };

    fetchPage();
  }, [page]); // Перезапрашиваем при смене страницы

  return (
    <div>
      <ul>
        {items.map(item => <li key={item.id}>{item.name}</li>)}
      </ul>
      
      {/* Кнопки пагинации */}
      <button 
        disabled={page === 1} 
        onClick={() => setPage(p => p - 1)}
      >
        Назад
      </button>
      
      <span>Страница {page} из {totalPages}</span>
      
      <button 
        disabled={page === totalPages} 
        onClick={() => setPage(p => p + 1)}
      >
        Вперед
      </button>
    </div>
  );
};
```

#### Пример на Vue 3

```vue
<template>
  <div>
    <ul>
      <li v-for="item in items" :key="item.id">{{ item.name }}</li>
    </ul>
    
    <button :disabled="page === 1" @click="page--">Назад</button>
    <span>Страница {{ page }} из {{ totalPages }}</span>
    <button :disabled="page === totalPages" @click="page++">Вперед</button>
  </div>
</template>

<script setup lang="ts">
import { ref, watch, computed } from 'vue';

const items = ref([]);
const page = ref(1);
const totalCount = ref(0);
const limit = 10;

const totalPages = computed(() => Math.ceil(totalCount.value / limit));

const fetchPage = async () => {
  const offset = (page.value - 1) * limit;
  const response = await fetch(`/api/items?limit=${limit}&offset=${offset}`);
  const data = await response.json();
  
  items.value = data.items;
  totalCount.value = data.totalCount;
};

// Следим за изменением страницы и делаем запрос
watch(page, fetchPage, { immediate: true });
</script>
```

### 4. Тонкие моменты и возможные проблемы (Почему от этого уходят)

На собеседовании это самая важная часть. У `limit/offset` есть две фатальные проблемы, из-за которых этот подход не используют в современных высоконагруженных приложениях (особенно для бесконечного скролла).

#### Проблема 1: Деградация производительности на больших смещениях (Deep Pagination)
Как мы выяснили в разделе "Под капотом", база данных сканирует и отбрасывает пропущенные строки.
*   Если клиент запрашивает первую страницу (`OFFSET 0`), БД читает 10 строк. Это мгновенно.
*   Если клиент запрашивает 10 000-ю страницу (`OFFSET 100000 LIMIT 10`), базе данных придется найти, прочитать и отсортировать **100 010 строк**, чтобы вернуть только последние 10.
*   *Следствие:* Чем дальше пользователь листает (или чем больше номер страницы он вводит), тем медленнее отвечает сервер. На миллионах записей запрос может положить базу данных.

#### Проблема 2: Проблема смещения данных (Data Drift / Inconsistency)
Это классический баг UI, который часто встречается при использовании `limit/offset` вместе с бесконечным скроллом.
*   *Сценарий (Дублирование):* 
    1. Пользователь загрузил Страницу 1 (записи с 1 по 10).
    2. В этот момент кто-то другой добавил в базу **новую** запись (она стала номером 1).
    3. Все старые записи сдвинулись вниз (бывшая 10-я стала 11-й).
    4. Пользователь скроллит вниз и запрашивает Страницу 2 (`OFFSET 10`).
    5. База пропускает первые 10 записей и возвращает записи с 11 по 20.
    6. *Итог:* Пользователь видит бывшую 10-ю запись **дважды** (в конце первой страницы и в начале второй).
*   *Сценарий (Пропуск):*
    1. Пользователь загрузил Страницу 1.
    2. Кто-то удалил запись номер 2.
    3. Записи сдвинулись вверх.
    4. Пользователь запрашивает Страницу 2 (`OFFSET 10`).
    5. *Итог:* Пользователь **никогда не увидит** бывшую 11-ю запись, так как она стала 10-й и попала в пропущенный `OFFSET`.

### Резюме по Limit/Offset

*   **Плюсы:** Легко реализовать, позволяет прыгать на любую конкретную страницу (например, сразу на 5-ю), легко посчитать общее количество страниц.
*   **Минусы:** Медленно работает на больших объемах данных, вызывает дублирование или пропуск элементов при добавлении/удалении данных в реальном времени.
*   **Где использовать:** В админках, таблицах с небольшим количеством данных, где нужна классическая пагинация с номерами страниц, и где данные редко меняются в реальном времени.
