JavaScript — это **однопоточный** язык программирования. У него только один поток выполнения и один Стек вызовов (Call Stack). Это значит, что он может выполнять только одну операцию за раз. Event Loop — это механизм, который позволяет JS выполнять неблокирующие (асинхронные) операции, несмотря на свою однопоточность.

Event Loop работает благодаря взаимодействию трех главных компонентов среды (браузера или Node.js):

#### 1. Стек вызовов (Call Stack)

- **Как работает:** Структура данных по принципу **LIFO** (Last In, First Out — последним пришел, первым ушел).
- **Зачем нужен:** Здесь выполняется весь твой синхронный код. Когда функция вызывается, она попадает наверх стека. Когда функция завершает работу, она удаляется из стека.
- _Что сказать на собесе:_ «Если в стек попадает тяжелая синхронная операция (например, огромный цикл `while`), стек блокируется, и интерфейс зависает. Чтобы этого избежать, мы используем асинхронность».

#### 2. Web API (или C++ API в Node.js)

- **Что это:** Это инструменты, которые предоставляет само окружение браузера (или Node.js), а не движок JavaScript (V8).
- **Зачем нужен:** Движок JS делегирует сюда долгие задачи. `setTimeout`, `setInterval`, запросы к серверу (`fetch`), обработчики событий DOM — всё это выполняется силами браузера, вне основного потока JS.
- _Как работает:_ Когда асинхронная задача в Web API завершается (например, таймер отсчитал время), Web API передает её callback-функцию в Очередь задач.

#### 3. Очередь задач (Task Queue / Callback Queue)

- **Как работает:** Структура данных по принципу **FIFO** (First In, First Out — первым пришел, первым ушел).
- **Зачем нужна:** Это зал ожидания. Сюда попадают callback-функции от Web API, которые уже готовы к выполнению, но ждут, пока освободится Стек вызовов.

---
### Алгоритм работы одного цикла (Tick) выглядит так:

1. **Выполнение синхронного кода:** Сначала выполняется всё, что попало в **Call Stack** из текущего скрипта.

2. **Микрозадачи (Microtasks):** Как только стек опустел, Event Loop обращается к очереди микрозадач.
    - **Важно:** Он выполняет **ВСЕ** задачи в этой очереди до победного конца. Если микрозадача добавляет новую микрозадачу, она тоже выполнится в этом же цикле. Стек не перейдет к следующему этапу, пока очередь микрозадач не обнулится.

3. **Отрисовка (Render):** Если браузер решит, что пора обновить экран (обычно каждые 16мс для 60fps), происходит перерисовка интерфейса. Это важный момент: отрисовка происходит **между** микро- и макрозадачами.

4. **Макрозадачи (Macrotasks/Tasks):** Event Loop берет **ровно одну** задачу из очереди макрозадач.

5. **Повтор:** После выполнения одной макрозадачи цикл возвращается к пункту 2 (проверка микрозадач).
#### Разница между очередями
| **Характеристика**     | **Микрозадачи (Microtasks)**                                                                          | **Макрозадачи (Macrotasks)**                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **Примеры**            | `Promise` (.then/catch/finally), `queueMicrotask`, `MutationObserver`, `process.nextTick` (в Node.js) | `setTimeout`, `setInterval`, запросы `fetch`/`XHR`, события DOM (click), `setImmediate` (Node.js) |
| **Приоритет**          | Выше. Выполняются сразу после синхронного кода.                                                       | Ниже. Ждут очистки очереди микрозадач.                                                            |
| **Количество за цикл** | **Все**, что есть в очереди на данный момент.                                                         | **Только одна** за один итерационный цикл.                                                        |

### 💡 Важные моменты (Киллер-фичи для собеседования):

- **«Event Loop — это часть JavaScript?»** Нет, это часть окружения (браузера или Node.js). Движок V8 (или другой) отвечает только за Call Stack и кучу (Memory Heap).
    
- **Подвох с `setTimeout(..., 0)`:** Если установить нулевой таймаут, код всё равно не выполнится мгновенно. Он покинет Call Stack, пройдет через Web API, встанет в Очередь и будет ждать, пока выполнится _весь_ оставшийся синхронный код (пока Call Stack не опустеет).
    
- **Однопоточность:** Обязательно делай акцент на том, что JS — однопоточный, но _окружение_ дает нам дополнительные потоки (Web API), что и делает возможной асинхронность.

### Тонкие моменты для Senior-интервью

1. **Блокировка потока микрозадачами:** Если ты напишешь рекурсивную функцию через микрозадачу (например, `const f = () => Promise.resolve().then(f)`), ты **намертво повесишь страницу**. Интерфейс не перерисуется (пункт 3 алгоритма никогда не наступит), так как очередь микрозадач никогда не опустеет. Рекурсивный `setTimeout` так не сделает, потому что он дает циклу завершиться.

2. **Зачем нужно разделение?** Микрозадачи нужны для того, чтобы быстро обновить состояние (state) программы до того, как браузер перерисует экран или пользователь совершит новое действие. Макрозадачи — для работы с внешним миром и планирования тяжелых кусков кода.

3. **UI Rendering:** На собеседовании могут спросить: "Где в этой схеме перерисовка?". Ответ: Браузер старается делать Render максимально эффективно. Он не будет делать его после каждой микрозадачи, а выберет момент после того, как микрозадачи выполнены, но перед следующей макрозадачей.
