### 1. Механика чейнинга (Chaining)

Главный секрет цепочек: **каждый метод `.then()`, `.catch()` или `.finally()` всегда возвращает НОВЫЙ промис.**

- Если обработчик возвращает **простое значение** (число, строку, объект), новый промис переходит в состояние `fulfilled` с этим значением.

- Если обработчик возвращает **другой промис**, выполнение цепочки «приостанавливается», пока этот внутренний промис не завершится (не зарезолвится). Это называется «выравниванием» (flattening).

- Если обработчик выбрасывает ошибку (`throw new Error()`), новый промис переходит в состояние `rejected`.

---
### 2. Разбор методов

#### `.then(onFulfilled, onRejected)`

Принимает две функции. На практике вторую (`onRejected`) используют редко, предпочитая `.catch()`.

- **Важно:** Если внутри `.then` произошла ошибка, она перейдет в ближайший по цепочке `.catch`.

#### `.catch(onRejected)`

Это фактически синтаксический сахар для `.then(null, onRejected)`.

- **Особенность:** Если `.catch` успешно обработал ошибку и не выбросил новую (через `throw`), цепочка «восстанавливается». Следующий за ним `.then()` будет выполнен успешно.

- _На собесе:_ «Как продолжить цепочку после ошибки? — Просто верните значение из `.catch`, и следующий `.then` его получит».

#### `.finally(onFinally)`

Выполняется всегда, независимо от того, успешно завершился промис или с ошибкой.

- **Особенности (важно для Senior):**
    
    1. Не принимает никаких аргументов (не знает, был успех или ошибка).
    
    2. **Пропускает результат дальше.** Если до `.finally` был результат `42`, то следующий после него `.then` получит `42`.
    
    3. Если `.finally` выбрасывает ошибку, то именно эта ошибка пойдет дальше по цепочке, «затирая» предыдущие результаты.

### 3. Тонкие моменты для интервью

#### Проблема «Промисного ада» (Promise Hell)

Даже с промисами можно накосячить, если вкладывать их друг в друга вместо того, чтобы возвращать:

```JavaScript
// ПЛОХО (вложенность)
fetchUser().then(user => {
  fetchPosts(user.id).then(posts => {
    // ...
  })
})

// ХОРОШО (плоская цепочка)
fetchUser()
  .then(user => fetchPosts(user.id)) // Возвращаем промис!
  .then(posts => {
    // Работаем с постами
  })
```

#### Что если .then ничего не возвращает?

Если функция в `.then` не содержит `return`, она неявно возвращает `undefined`. Следующий `.then` в цепочке получит `undefined` в качестве аргумента.

#### Порядок выполнения при ошибке

```JavaScript
Promise.reject('error')
  .then(() => console.log('1')) // Пропустится
  .catch(() => console.log('2')) // Выполнится (2)
  .then(() => console.log('3'))  // Выполнится (3), так как catch "починил" цепочку
```

### 💡 Чек-лист для ответа:

1. **Возвращаемое значение:** Каждый шаг создает новый промис.

2. **Обработка ошибок:** Ошибка «всплывает» до ближайшего `.catch`.

3. **Восстановление:** `.catch` возвращает управление в основной поток, если не выбросил новую ошибку.

4. **Finally:** Используется для очистки ресурсов (loading = false, закрытие соединений), не влияет на результат (кроме случаев `throw`).
