### 1. Микрозадачи (Microtasks)

Это «срочные» задачи. Они имеют высший приоритет над макрозадачами.

- **Источник:** `Promise` (обработчики `.then`, `.catch`, `.finally`), `queueMicrotask()`, `MutationObserver`.

- **Особенность выполнения:** Очередь микрозадач должна быть очищена **полностью** прежде чем Event Loop перейдет к чему-то другому.

- **Нюанс:** Если в процессе выполнения микрозадачи в очередь добавляется новая микрозадача, она тоже будет выполнена в этом же цикле. Это может привести к бесконечному циклу, который «заморозит» интерфейс.

### 2. Макрозадачи (Macrotasks)

Это более «тяжелые» или внешние задачи.

- **Источник:** `setTimeout`, `setInterval`, `setImmediate` (только Node.js), события DOM (клик, скролл), сетевые запросы (`fetch`), парсинг HTML.
    
- **Особенность выполнения:** За один цикл (Tick) Event Loop берет **только одну** макрозадачу из начала очереди. После её завершения он обязан проверить очередь микрозадач, и только потом возьмется за вторую макрозадачу.
#### Сравнение для шпаргалки

|**Характеристика**|**Микрозадачи**|**Макрозадачи**|
|---|---|---|
|**Когда выполняются**|Сразу после текущего синхронного кода|После микрозадач и (возможно) отрисовки|
|**Приоритет**|Высокий|Низкий|
|**Количество за цикл**|Вся очередь целиком|Ровно одна задача|
|**Блокировка UI**|Могут заблокировать (если рекурсивны)|Обычно не блокируют, так как дают браузеру «дышать»|
### Коварные вопросы на собеседовании

#### 1. «Что произойдет с `render` (отрисовкой)?»

Браузер делает перерисовку экрана (Rendering) **между** макрозадачами, но **после** того, как выполнена вся очередь микрозадач.

- _Вывод:_ Если ты хочешь сделать тяжелое вычисление и не «повесить» счетчик кадров (FPS), лучше разбить его на части через `setTimeout`, а не через `Promise`.

#### 2. `queueMicrotask` vs `Promise.resolve().then()`

Функционально они идентичны — оба добавляют задачу в очередь микрозадач. Однако `queueMicrotask()` — это современный API, созданный специально для этого, он выглядит чище и не создает лишний объект промиса в памяти.

#### 3. Порядок выполнения (Классическая задачка)

Попробуй предсказать вывод:

```JavaScript
console.log('Начало');

setTimeout(() => {
  console.log('Таймаут');
}, 0);

Promise.resolve().then(() => {
  console.log('Промис 1');
}).then(() => {
  console.log('Промис 2');
});

console.log('Конец');
```

**Разбор:**
1. Синхронно: `Начало`, `Конец`.
2. Очередь микрозадач: `Промис 1`, затем `Промис 2` (потому что очередь чистится до конца).
3. Очередь макрозадач: `Таймаут`.

### Зачем нам `queueMicrotask` на реальном проекте?

Представь ситуацию: у тебя есть функция, которая иногда возвращает данные из кэша (синхронно), а иногда делает запрос (асинхронно).

```JavaScript
function getData(url) {
  if (cache[url]) {
    // Если вернуть просто return cache[url], это будет синхронно.
    // Если обернуть в queueMicrotask, мы гарантируем асинхронное поведение
    // в обоих случаях, что делает поток данных предсказуемым.
    queueMicrotask(() => callback(cache[url]));
    return;
  }
  fetch(url).then(callback);
}
```

Это позволяет избежать багов, когда код после вызова функции выполняется в разном порядке в зависимости от наличия кэша.
