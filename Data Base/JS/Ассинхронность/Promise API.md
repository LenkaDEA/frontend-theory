### 1. Promise.all(iterable) — «Все или ничего»

- **Логика:** Ждет выполнения всех промисов.

- **Результат:** Массив результатов в том же порядке, в котором передавали промисы.

- **Ошибка (Fail-fast):** Если **хотя бы один** промис упадет, `Promise.all` мгновенно отклоняется с этой ошибкой. Остальные промисы продолжают выполняться «в фоне», но их результат уже не важен.

- **Senior-нюанс:** Если передать пустой массив `[]`, он выполнится синхронно и вернет пустой массив.


### 2. Promise.allSettled(iterable) — «До победного конца»

- **Логика:** Ждет завершения всех промисов, независимо от того, упали они или выполнились.

- **Результат:** Массив объектов со статусами:

    - `{ status: 'fulfilled', value: ... }`
    
    - `{ status: 'rejected', reason: ... }`
    
- **Зачем нужен:** Когда задачи независимы. Например, загружаем 5 виджетов: если один упал, остальные 4 всё равно нужно показать.

### 3. Promise.race(iterable) — «Кто первый, тот и папа»

- **Логика:** Ждет первый «осевший» (settled) промис.

- **Результат:** Либо успех, либо ошибка первого завершившегося промиса.

- **Применение:** Паттерн «Таймаут». Запускаем запрос к API и одновременно `setTimeout`, который кидает ошибку. Кто быстрее — тот и результат.

### 4. Promise.any(iterable) — «Первый успешный»

- **Логика:** Ждет первый **успешно** выполненный промис.

- **Ошибка:** Если **все** промисы упали, возвращает специальный объект `AggregateError`, который содержит массив всех ошибок.

- **Отличие от .race:** `.race` упадет, если самый быстрый промис упал. `.any` будет ждать первого успешного, даже если до него упали все остальные.

#### Сводная таблица для подготовки
| **Метод**        | **Что возвращает при успехе** | **Что происходит при первой ошибке**        |
| ---------------- | ----------------------------- | ------------------------------------------- |
| **`all`**        | Массив всех значений          | Сразу падает (Reject)                       |
| **`allSettled`** | Массив объектов со статусами  | Ничего, ждет всех                           |
| **`race`**       | Первое значение (быстрейшее)  | Сразу падает, если ошибка была первой       |
| **`any`**        | Первое успешное значение      | Игнорирует, пока есть шансы на успех других |

### Тонкие вопросы «на засыпку»:

1. **«Что будет, если в `Promise.all` передать не промисы, а обычные значения?»**

    - _Ответ:_ Он автоматически обернет их в `Promise.resolve()` и вернет в итоговом массиве в тех же позициях.

2. **«Как отменить оставшиеся запросы в `Promise.all`, если один упал?»**

    - _Ответ:_ Нативно — никак. Промисы нельзя «убить». Но можно использовать `AbortController`, чтобы прервать сетевые запросы внутри этих промисов.

3. **«В каком порядке будут лежать результаты в `Promise.all`, если второй промис выполнился быстрее первого?»**

    - _Ответ:_ Порядок в итоговом массиве всегда соответствует порядку в исходном итерируемом объекте, независимо от времени выполнения.


---

### Пример использования (Senior-style):

Реализация таймаута через `Promise.race`:

```JavaScript
const fetchWithTimeout = (url, ms) => {
  return Promise.race([
    fetch(url),
    new Promise((_, reject) => 
      setTimeout(() => reject(new Error('Timeout!')), ms)
    )
  ]);
};
```
