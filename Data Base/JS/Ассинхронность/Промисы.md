Это объект, представляющий результат асинхронной операции, который будет доступен «когда-то в будущем». Это «обещание» вернуть значение или ошибку.

---
### Три состояния Промиса

В любой момент времени промис находится в одном из трёх состояний:

1. **`pending` (ожидание):** Исходное состояние. Операция ещё не завершена, результат неизвестен.

2. **`fulfilled` (исполнено):** Операция завершена успешно. У промиса появилось значение (`value`).

3. **`rejected` (отклонено):** Произошла ошибка. У промиса появилась причина отказа (`reason` или `error`).


**Важный термин:** Когда промис переходит из `pending` в `fulfilled` или `rejected`, говорят, что он **settled** (осел/завершился). Обратного пути нет.

---
### Механика работы (Executor)

Промис создается через конструктор, который принимает функцию-исполнитель (**executor**). Она выполняется **синхронно** и сразу.


```JavaScript
const myPromise = new Promise((resolve, reject) => {
  // Этот код выполняется СРАЗУ (синхронно)
  const success = true;

  if (success) {
    resolve("Успех!"); // Переводит в fulfilled
  } else {
    reject(new Error("Ошибка")); // Переводит в rejected
  }
});
```

---

### Ключевые особенности для Senior-интервью:

#### 1. Иimmutable (Неизменяемость)

Как только промис перешел в состояние `fulfilled` или `rejected`, его состояние **не может измениться**.

- Если ты вызовешь `resolve()`, а следом `reject()`, сработает только первый вызов. Все остальные будут проигнорированы.

- Это гарантирует предсказуемость: результат асинхронной операции не изменится «под капотом» в процессе обработки.

#### 2. Промисы — это Микрозадачи

Даже если ты создаешь уже готовый промис через `Promise.resolve()`, его обработчики (`.then`) всё равно уйдут в **очередь микрозадач**.

```JavaScript
console.log(1);
Promise.resolve().then(() => console.log(2));
console.log(3);
// Вывод: 1, 3, 2
```

#### 3. Проблема "Проглоченных ошибок"

Если промис перешел в состояние `rejected`, а у него нет обработчика `.catch()` (или второго аргумента в `.then`), в браузере возникнет событие `unhandledrejection`. На реальных проектах это критично — такие ошибки «тихо» ломают логику, если их не логировать.

#### 4. Внутренние свойства

У объекта Promise есть скрытые свойства `[[PromiseState]]` и `[[PromiseResult]]`. Мы не можем получить к ним доступ напрямую через точку (например, `p.state`), мы можем только подписаться на изменения через методы `.then()`, `.catch()`, `.finally()`.

### Точки «засыпки» на собеседовании:

- **Вопрос:** "Что будет, если внутри `new Promise` не вызвать ни `resolve`, ни `reject`?"

	- **Ответ:** Промис навсегда останется в состоянии `pending`. Это может привести к утечке памяти, так как все обработчики `.then()`, привязанные к нему, будут вечно висеть в памяти, ожидая выполнения.

- **Вопрос:** "Можно ли отменить промис?"

	- **Ответ:** Нативный Promise в JS **нельзя отменить** (в отличие от библиотек типа Bluebird или RxJS Observables). Как только `executor` запущен, он дойдет до конца. Для имитации отмены обычно используют `AbortController` (особенно часто в связке с `fetch`).
