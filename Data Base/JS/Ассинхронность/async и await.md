### 1. Суть концепции

`async / await` — это синтаксический сахар над промисами. Он делает асинхронный код визуально похожим на синхронный, что упрощает чтение и поддержку.

- **`async`**: Ключевое слово перед функцией. Оно гарантирует, что функция **всегда возвращает промис**. Если ты вернешь обычное значение (например, `return 42`), JS автоматически обернет его в `Promise.resolve(42)`.

- **`await`**: Ключевое слово, которое можно использовать только внутри `async`-функции (и в top-level await в современных средах). Оно «приостанавливает» выполнение функции до тех пор, пока промис не перейдет в состояние _settled_.

---

### 2. Обработка ошибок

Вместо цепочек `.catch()`, в `async/await` используется стандартная конструкция **`try...catch...finally`**.

```JavaScript
async function fetchData() {
  try {
    const response = await fetch('/api/data');
    const data = await response.json();
    return data;
  } catch (error) {
    console.error("Ошибка сети или парсинга:", error);
  } finally {
    console.log("Запрос завершен");
  }
}
```

- **Senior-нюанс:** Помни, что если ты не обернешь `await` в `try/catch`, и промис упадет, ошибка «вылетит» из функции и станет `unhandled rejection`, если вызывающий код её не поймает.

### 3. "Под капотом": Async/Await и Генераторы

Частый вопрос на глубоких интервью: **«Как реализовать async/await, если бы их не было в языке?»** Ответ: Через **Генераторы** и функцию-хелпер (итератор).

`await` работает аналогично `yield`. Когда интерпретатор видит `await`, он «замораживает» контекст выполнения функции, сохраняет стек и возвращает управление в Event Loop. Когда промис разрешается, выполнение функции возобновляется с сохраненного места.

### 4. Типичные ловушки (То, на чем ловят Senior-ов)

#### А. "Waterfall" (Последовательное выполнение)

Многие новички пишут так:

```JavaScript
const user = await fetchUser(); // Ждем 1 сек
const posts = await fetchPosts(); // Ждем еще 1 сек
// Итого: 2 секунды
```

**Как надо:** Если запросы независимы, запускай их параллельно через `Promise.all`.

```JavaScript
const [user, posts] = await Promise.all([fetchUser(), fetchPosts()]);
// Итого: 1 секунда
```

#### Б. `await` в циклах

- **`for...of`**: Работает последовательно (ждет каждый `await`). Подходит, если важен порядок.

- **`array.forEach`**: **НЕ РАБОТАЕТ** с `await`. Цикл запустит все асинхронные операции и пойдет дальше, не дожидаясь их завершения.

- **`array.map`**: Если внутри `map` есть `async`, он вернет массив промисов. Чтобы дождаться их всех, нужно обернуть результат в `Promise.all(array.map(...))`.


---

### 5. Top-level await

Раньше `await` можно было использовать только внутри `async` функции. В современных браузерах и Node.js (начиная с v14.8.0 в модулях) можно писать `await` на верхнем уровне файла. Это полезно для инициализации баз данных или загрузки модулей.

### Сводная шпаргалка для ответа:

1. **Синтаксис:** Чище, чем цепочки `.then()`, избавляет от вложенности.

2. **Ошибки:** Используем понятный `try/catch`.

3. **Поток:** `await` не блокирует весь поток (Main Thread), он лишь приостанавливает выполнение конкретной функции, освобождая Call Stack для других задач.

4. **Производительность:** Следим, чтобы не создавать лишних «водопадов» там, где можно использовать параллелизм.
