### 1. Деструктуризация массивов

Здесь ключевое значение имеет **порядок (позиция)** элементов.

- **Пропуск элементов:** Если нам нужен только третий элемент, мы просто оставляем пустые места: `const [, , third] = [1, 2, 3];`.
- **Значения по умолчанию:** Помогают избежать `undefined`, если массив короче, чем мы ожидали: `const [id = 1] = [];`.
- **Трюк с обменом переменными:** Классика на интервью. Как поменять `a` и `b` местами без третьей переменной? `[a, b] = [b, a];`    
- **Rest-оператор:** Позволяет собрать «хвост» массива в отдельную переменную: `const [first, ...others] = [1, 2, 3, 4];`.

---

### 2. Деструктуризация объектов

Здесь важен не порядок, а **имена ключей**.

- **Переименование:** Очень полезно, когда приходят данные с «плохими» именами или нужно избежать конфликта имен: `const { first_name: firstName } = user;`
- **Вложенная деструктуризация:** Позволяет достать данные из глубин объекта за один проход: `const { address: { city } } = user;` _Внимание:_ Если `address` будет `undefined`, код упадет с ошибкой. На собеседованиях часто спрашивают, как это предотвратить (ответ: дефолтные значения или опциональная цепочка до деструктуризации).
- **Вычисляемые имена свойств:** Редкий, но эффектный кейс: `const key = 'id'; const { [key]: userId } = user;`

---

### 3. Деструктуризация в параметрах функций

Это то, что мы делаем в 99% React-компонентов. Вместо того чтобы писать `props.user.name`, мы пишем:

```JavaScript
const UserCard = ({ user: { name, age = 18 } }) => { ... }
```

Это делает интерфейс функции сразу понятным: мы видим, какие данные ей нужны для работы.

### Ловушки и важные моменты (Interview Highlights)

#### 1. null vs undefined

Дефолтные значения срабатывают **только если значение строго равно `undefined`**. Если в свойстве лежит `null`, дефолтное значение проигнорируется.

```JavaScript
const { size = 'medium' } = { size: null }; 
console.log(size); // null!
```

#### 2. Ошибка при деструктуризации null/undefined

Попытка деструктурировать `null` или `undefined` приведет к `TypeError`.

```JavaScript
const { x } = null; // Uncaught TypeError
```

На интервью могут попросить написать «безопасную» деструктуризацию. Обычно это делается через пустой объект по умолчанию: `const { x } = data || {};`

#### 3. Скобки при присваивании в уже объявленные переменные

Если переменные уже созданы, и ты хочешь деструктурировать в них объект, нужно обернуть все выражение в круглые скобки, иначе `{` в начале строки будет воспринято как начало блока кода.

```JavaScript
let name;
({ name } = { name: 'Elena' }); // Без скобок будет синтаксическая ошибка
```

### Senior-совет: Когда остановиться?

Не злоупотребляй глубокой деструктуризацией. Если тебе нужно достать данные на 4-5 уровне вложенности, это часто признак того, что данные стоит подготовить заранее (нормализовать). Код вроде `const { a: { b: { c: { d } } } } = data;` очень тяжело читать и еще тяжелее отлаживать.
