### 1. Мутирующие методы (Modify in-place)

Эти методы изменяют исходный массив. Они работают быстрее с точки зрения памяти (не создают копию), но опасны для предсказуемости кода.

- **Классика:** `push()`, `pop()`, `shift()`, `unshift()`.
- **Самый коварный:** `splice()`. Он вырезает/добавляет элементы и возвращает массив **удаленных** элементов, а не измененный исходный.
- **Сортировка:** `sort()` и `reverse()`. **Важно:** `sort()` по умолчанию сортирует элементы как строки (например, `10` пойдет перед `2`). Всегда нужно передавать callback `(a, b) => a - b`.
- **Заполнение:** `fill()`.

---

### 2. Немутирующие методы (Immutable / Return new array)

Эти методы не трогают оригинал, а возвращают новый массив. Это стандарт для функционального программирования и управления состоянием.

- **Трансформация:** `map()`, `filter()`, `concat()`, `flat()`, `flatMap()`.
- **Копирование подстроки:** `slice()`. Часто используется для создания поверхностной копии массива: `const copy = arr.slice()`.
- **Новинки (ES2023):** Чтобы не делать копию вручную перед сортировкой, добавили методы `toSorted()`, `toReversed()`, `toSpliced()` и `with()`. Они работают так же, как их мутирующие аналоги, но сразу возвращают новый массив.

### Важные нюансы для собеседования

#### 1. Ссылочная идентичность (Reference Equality)

Это то, на чем ловят мидлов.
```JavaScript
const a = [1, 2, 3];
const b = a.sort(); 
console.log(a === b); // true! Ссылка не изменилась.
```

Если ты используешь `sort()` в React, компонент не перерендерится, потому что для него `a` и `b` — это один и тот же объект в памяти.

#### 2. Особняком: `forEach`

Метод `forEach` ничего не возвращает (`undefined`). Он сам по себе не мутирует массив, но его часто используют для мутации элементов внутри цикла. На собеседованиях часто спрашивают: «Можно ли прервать `forEach`?». **Ответ: Нет.** Если нужно прерывание, используй `for...of` или `some()`/`every()`.

#### 3. Поверхностное копирование (Shallow Copy)

Помни, что немутирующие методы делают **поверхностную** копию. Если массив содержит объекты, то в новом массиве будут ссылки на те же самые объекты.

```JavaScript
const users = [{ name: 'Elena' }];
const newUsers = users.map(u => u);
newUsers[0].name = 'Ivan'; 
console.log(users[0].name); // 'Ivan' — объект внутри мутировал!
```

### Как запомнить, если путаешься?

Используй «правило чек-листа» при написании кода:

1. Если мне нужно изменить данные для отображения в UI — **только немутирующие**.
2. Если я работаю внутри функции с локальной переменной, которую никто больше не видит — можно **мутирующие** (это чуть быстрее).
3. Если нужно превратить мутирующий метод в безопасный — добавь spread: `[...arr].sort()`.


Суть `reduce` — **свёртка**. Мы берем массив (много значений) и «схлопываем» его в одно значение (это может быть число, строка, объект или даже другой массив).

**Синтаксис:** `array.reduce((acc, item, index, array) => { ... }, initialValue)`

1. **`acc` (accumulator):** Промежуточный результат, который передается от итерации к итерации.
2. **`item` (current):** Текущий элемент массива.
3. **`initialValue`:** То, с чего начинается работа. **Это самый важный момент.**

### Главные ловушки (То, что спросят на собеседовании)

#### 1. Что будет, если не передать `initialValue`?

Это классический вопрос «с подвохом».

- **Если `initialValue` есть:** Акумулятор (`acc`) равен этому значению, цикл начинается с **0-го** элемента массива.
- **Если `initialValue` НЕТ:** Акумулятор (`acc`) автоматически принимает значение **0-го** элемента, а цикл начинается сразу с **1-го** элемента.
- **Опасность:** Если массив пустой и нет `initialValue`, JS выбросит `TypeError`. **Всегда передавай начальное значение**, если не уверен(а) на 100%, что в массиве что-то есть.

#### 2. Реализация других методов через `reduce`

На интервью могут попросить написать `map` или `filter`, используя только `reduce`. Это проверяет понимание того, что `reduce` — база для всего.

```JavaScript
// Реализация filter через reduce
const filter = (arr, cb) => arr.reduce((acc, item) => {
  if (cb(item)) acc.push(item);
  return acc; // Всегда возвращай acc!
}, []);
```

#### 3. Сложные трансформации (Grouping)

Частый кейс — превратить список объектов в объект (хэш-мапу) для быстрого доступа по ID.

```JavaScript
const users = [{id: '1', name: 'Elena'}, {id: '2', name: 'Ivan'}];
const userMap = users.reduce((acc, user) => {
  acc[user.id] = user;
  return acc;
}, {});
```

### Senior-совет: Когда НЕ использовать `reduce`

Интервьюер может спросить: «А почему бы нам не делать всё через `reduce`?». **Твой ответ:** «Читаемость кода (Readability)».

- Если тебе нужно просто просуммировать числа — `reduce` идеален.
- Если нужно превратить массив в массив — используй `map`.
- Если нужно отфильтровать — `filter`.
- **Плохая практика:** Делать сложную логику внутри `reduce`, где внутри еще есть циклы или тяжелые условия. В 90% случаев это лучше разбить на цепочку `.filter().map()` или использовать обычный `for...of`.

**Почему?** Код читается чаще, чем пишется. Цепочка методов четко говорит о намерениях (сначала отфильтровали, потом изменили), а гигантский `reduce` заставляет другого разработчика вникать в детали реализации каждой итерации.

### Ответ на вопрос по React (из предыдущего блока)

Чтобы удалить элемент по индексу в React-стейт, не мутируя оригинал:

1. **`filter`**: `setItems(prev => prev.filter((_, i) => i !== indexToRemove))` — самый чистый и популярный вариант.
2. **`slice`**: `setItems(prev => [...prev.slice(0, index), ...prev.slice(index + 1)])` — чуть более громоздко, но работает быстро.
