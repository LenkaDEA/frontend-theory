Главное правило: **у стрелочных функций нет своего `this`**. Вообще. Совсем.

**1. Лексический контекст (Lexical this)** Стрелка не определяет `this` в момент вызова. Вместо этого она «захватывает» значение `this` из той области видимости, в которой она была **создана**.

- Обычная функция: `this` определяется тем, **как** вызвали.
- Стрелочная функция: `this` определяется тем, **где** написали код.

**2. Невозможность изменить контекст** Методы `call()`, `apply()` и `bind()` у стрелочных функций работают, но они **игнорируют** переданный контекст. Первый аргумент просто не будет учитываться.

- _На собесе могут спросить:_ «Можно ли переопределить `this` в стрелке?». Ответ: Нет, он фиксируется один раз при создании.

**3. Стрелка — это не конструктор** Стрелочные функции нельзя вызывать с ключевым словом `new`.

- У них нет внутреннего метода `[[Construct]]`.
- У них отсутствует свойство `prototype`.
- Попытка вызова `new () => {}` приведет к `TypeError`.

**4. Отсутствие объекта `arguments`** У стрелок также нет своего объекта `arguments`. Если ты обратишься к нему внутри стрелки, он возьмет его из ближайшей родительской обычной функции. В современном коде вместо этого используют rest-параметры `(...args)`.

---
### Коварный пример для самопроверки (часто дают на доске):

```JavaScript
const obj = {
  name: 'Elena',
  regular: function() {
    console.log('Regular:', this.name);
  },
  arrow: () => {
    console.log('Arrow:', this.name);
  }
};

obj.regular(); // 'Elena' (this — это obj)
obj.arrow();   // undefined (this — это глобальный объект/window, так как объект не создает область видимости)
```

> **Важный момент для Senior-позиции:** Стрелки идеально подходят для колбэков (внутри `setTimeout`, `map`, `filter`), когда нужно прокинуть `this` внутрь, не используя `.bind(this)` или `const self = this`.
