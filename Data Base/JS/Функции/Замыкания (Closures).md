**Замыкание** — это комбинация функции и лексического окружения, в котором эта функция была определена. Простыми словами: функция «запоминает» переменные из той области видимости, где она была создана, и может обращаться к ним даже после того, как внешняя функция завершила свое выполнение.

### Как это работает «под капотом»?

1. **Lexical Environment (Лексическое окружение):** Каждый раз при запуске функции или блока кода создается скрытый объект — лексическое окружение. Оно состоит из двух частей:
    - _Environment Record:_ объект, где хранятся все локальные переменные.
    - _Reference to outer environment:_ ссылка на внешнее (родительское) лексическое окружение.

2. **Скрытое свойство `[[Environment]]`:** Каждая функция при создании получает скрытое свойство `[[Environment]]`, которое хранит ссылку на то окружение, где функция была рождена. Именно благодаря этому ссылка на внешние переменные не теряется.

### Зачем нужны замыкания? (Практические примеры)

На собеседовании обязательно спросят: «А зачем нам это использовать в реальном коде?».

- **Инкапсуляция и приватные данные:** В JS долгое время не было приватных полей в классах (через `#`). Замыкания позволяли создавать переменные, доступ к которым есть только у определенных методов.

```JavaScript
function createCounter() {
  let count = 0; // Приватная переменная
  return {
	increment: () => ++count,
	getValue: () => count
  };
}
const counter = createCounter();
console.log(counter.increment()); // 1
```

- **Фабричные функции:** Создание функций с предустановленными параметрами.

- **Сохранение состояния в асинхронных операциях:** Например, в обработчиках событий или `setTimeout`.

### Классический вопрос: «Замыкание в цикле»

Это любимая ловушка интервьеров. Тебя могут попросить объяснить, что выведет этот код:

```JavaScript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 1000);
}
// Выведет: 3, 3, 3 (так как var имеет функциональную область видимости и к моменту вывода i уже равно 3)
```

**Как исправить?**

1. Использовать `let` вместо `var` (создается новая область видимости для каждой итерации).
2. Использовать IIFE (передавать `i` как аргумент).

### Важные нюансы (то, что спросит Senior):

- **Память:** Замыкания могут приводить к утечкам памяти, если внешние переменные больше не нужны, но функция-замыкание всё еще жива. Движки JS (V8) стараются оптимизировать это и удалять неиспользуемые переменные, но об этом риске стоит упомянуть.

- **Scope Chain (Цепочка областей видимости):** Если переменная не найдена в текущем окружении, поиск идет во внешнее, и так до глобального объекта. Если нигде не нашли — `ReferenceError`.

**Главный совет:** Если тебя просят дать определение, начни с фразы: _«Замыкание — это когда функция имеет доступ к переменным из своей внешней области видимости, даже если та уже прекратила выполнение»_. Это сразу покажет твое понимание сути.
