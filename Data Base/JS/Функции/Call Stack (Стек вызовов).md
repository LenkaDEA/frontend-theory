**Call Stack** — это механизм в движке JavaScript (например, V8), который отслеживает местоположение интерпретатора в коде. Он хранит информацию о том, какая функция выполняется в данный момент и какие функции вызываются внутри неё.

### Принцип работы: LIFO

Стек работает по принципу **LIFO** (Last In, First Out — «последним пришёл, первым ушёл»).

1. Когда мы вызываем функцию, она добавляется (push) в верхнюю часть стека.

2. Когда функция завершается, она удаляется (pop) из стека, и управление возвращается к той функции, которая была под ней.

### Как это выглядит в коде:

```JavaScript
function multiply(a, b) {
  return a * b;
}

function square(n) {
  return multiply(n, n);
}

function printSquare(n) {
  const result = square(n);
  console.log(result);
}

printSquare(4);
```

**Порядок в стеке:**
1. `printSquare(4)` попадает в стек.
2. Внутри вызывается `square(4)` — она кладется сверху.
3. Внутри вызывается `multiply(4, 4)` — она на самом верху.
4. `multiply` возвращает результат и **вылетает** из стека.
5. `square` завершается и **вылетает**.
6. `console.log` залетает, исполняется и вылетает.
7. `printSquare` вылетает. Стек пуст.

### Важные технические детали для собеседования

#### 1. Однопоточность (Single Threaded)

JavaScript имеет **один** Call Stack. Это означает, что он может делать только одно дело в единицу времени. Если стек занят тяжелыми вычислениями, браузер «фризит», так как не может отрисовать интерфейс или обработать клики.

#### 2. Stack Frame (Кадр стека)

Каждый элемент в стеке называется «кадром». Он содержит:

- Параметры функции.

- Локальные переменные.

- Адрес возврата (куда вернуться после завершения).

#### 3. Stack Overflow (Переполнение стека)

Происходит, когда стек превышает свой лимитированный размер (обычно из-за бесконечной рекурсии).

```JavaScript
function chicken() {
  return egg();
}
function egg() {
  return chicken();
}
chicken(); // Uncaught RangeError: Maximum call stack size exceeded
```

### Вопрос с подвохом: «Где здесь Call Stack?»

Интервьюер может спросить: _«Если JS однопоточный и у него один стек, как работают асинхронные функции (например, `setTimeout`)? Разве они не блокируют стек?»_

**Правильный ответ:** Асинхронные задачи (Web APIs в браузере) **не выполняются** в Call Stack. Они уходят во внешнюю среду, а когда они готовы, их колбэки попадают в **Task Queue**. И только когда Call Stack становится абсолютно **пустым**, Event Loop перебрасывает колбэк из очереди в стек.
