Различия между ними лучше всего запоминать по четырем критериям: **область видимости**, **переназначение**, **всплытие** и **глобальный объект**.

|**Характеристика**|**var**|**let**|**const**|
|---|---|---|---|
|**Область видимости**|Функциональная|Блочная|Блочная|
|**Переназначение**|Можно|Можно|**Нельзя**|
|**Переобъявление**|Можно в том же scope|Нельзя|Нельзя|
|**Hoisting (Всплытие)**|Да (`undefined`)|Да (впадает в TDZ)|Да (впадает в TDZ)|
|**Глобальный объект**|Создает свойство в `window`|Не создает|Не создает|
### 1. Temporal Dead Zone (Временная мертвая зона)

Это самый частый вопрос «на засыпку».

**TDZ** — это состояние переменной от начала выполнения блока кода до момента её фактического объявления в коде. В этот период переменная уже существует в памяти (благодаря поднятию), но к ней **нельзя обращаться**.

- Если ты обратишься к `let` или `const` до строки с объявлением — получишь `ReferenceError`.
- **Зачем это нужно?** Чтобы предотвратить использование переменных до их инициализации и сделать код более предсказуемым.

---

### 2. Нюансы `const`

Многие думают, что `const` делает значение неизменяемым. Это не так.

- **Для примитивов:** Значение действительно нельзя изменить.
- **Для объектов и массивов:** Нельзя изменить только **ссылку** на этот объект. Содержимое объекта (свойства, элементы массива) менять можно.

JavaScript

```js
const user = { name: 'Elena' };
user.name = 'Admin'; // Ок, мутируем объект
user = { name: 'New' }; // Ошибка! Пытаемся сменить ссылку
```

---

### 3. Глобальный объект (window/globalThis)

Переменные, объявленные через `var` в глобальной области видимости, автоматически становятся свойствами объекта `window` (в браузере). Переменные `let` и `const` туда не попадают. _Это еще одна причина, почему `var` считается плохой практикой — он «замусоривает» глобальное пространство имен._

---

### 🔥 Что точно спросят (Senior-вопросы)

**1. Почему `var` можно переобъявлять, а `let` нет?** Это заложено в спецификацию. `var` проектировался как «мягкий» инструмент, прощающий ошибки. `let` и `const` были созданы для написания более надежного кода, поэтому повторное объявление в том же блоке считается синтаксической ошибкой.

**2. Всплывают (Hoisting) ли `let` и `const` на самом деле?** **Да, всплывают.** Это технический нюанс. Движок JS узнает о них в момент создания лексического окружения (Lexical Environment). Разница с `var` только в том, что `var` сразу инициализируется значением `undefined`, а `let/const` остаются в состоянии «uninitialized», что и создает эффект TDZ.

**3. Что такое "Shadowing" (Затенение переменных)?** Это ситуация, когда переменная во внутренней области видимости имеет то же имя, что и во внешней. Внутренняя переменная «затеняет» внешнюю.

JavaScript

```js
const x = 10;
if (true) {
  const x = 20; // Это ок, это "затенение"
  console.log(x); // 20
}
```
