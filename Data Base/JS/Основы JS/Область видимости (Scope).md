В JavaScript есть 3 основных типа области видимости:

1. **Глобальная (Global Scope)**: Переменная объявлена вне любых функций и блоков. Доступна отовсюду (в браузере привязывается к объекту `window`, если объявлена через `var`).
2. **Функциональная (Function/Local Scope)**: Переменная объявлена внутри функции. Снаружи не видна. Это родная стихия для `var`.
3. **Блочная (Block Scope)**: Переменная объявлена внутри фигурных скобок `{ ... }` (в `if`, `for`, `while`). Работает **только** для `let` и `const`.

#### Как это работает под капотом: Лексическое окружение

Когда функция создается (именно пишется в коде, а не вызывается!), скрытый механизм JS создает для нее **Лексическое окружение (Lexical Environment)**. Оно состоит из двух частей:

- **Environment Record (Запись окружения)**: Объект в памяти, где хранятся все локальные переменные этой функции и `this`.
- **Reference to Outer (Ссылка на внешнее окружение)**: Ссылка на ту область видимости, где функция была физически _написана_ в коде.

#### Scope Chain (Цепочка областей видимости)

Если интерпретатор видит переменную, он ищет ее в текущем Environment Record. Если не находит — идет по ссылке `Reference to Outer` на уровень выше. И так до глобальной области. Если и там нет — падает с ошибкой `ReferenceError`. Важно: искать «вниз», во вложенные области видимости, движок не умеет.

### 🔥 Что точно спросят (Ключевые моменты)

**1. Лексическая (статическая) vs Динамическая область видимости** В JS область видимости лексическая. Это значит, что функция берет переменные из того места, где она была **объявлена**, а не откуда была вызвана. _Интервью-кейс:_

JavaScript

```js
let x = 10;
function foo() { console.log(x); }

function bar() {
  let x = 20;
  foo();
}
bar(); // Что выведет?
```

_Ответ:_ Выведет `10`, а не 20. Функция `foo` «запомнила» внешнее окружение в момент своего создания, где `x = 10`.

**2. Задача: Цикл `for` и асинхронность (`setTimeout`)** Это классика, которую дают на 8 из 10 собеседований.

JavaScript

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
```

_Вопрос:_ Что выведет код и почему? _Ответ:_ Выведет `3, 3, 3`. Так как `var` не имеет блочной области видимости, переменная `i` — одна-единственная на весь цикл (лежит в глобальной или функциональной области). К моменту, когда таймеры сработают (через 100мс), цикл уже мгновенно отработал, и `i` стало равно 3. _Как исправить?_ Заменить `var` на `let`. У `let` блочная видимость, поэтому для каждой итерации цикла создается _своя, новая_ переменная `i` со своим текущим значением, которую коллбэк `setTimeout` благополучно запоминает.

**3. Связь с [замыканиями](../Функции/Замыкания%20(Closures).md) (Closures)** Хотя тема замыканий часто идет отдельно, она неразрывно связана со Scope. Замыкание — это функция вместе со всеми внешними переменными, которые ей доступны. В JS **все функции являются замыканиями**. _Популярный вопрос:_ Может ли функция получить доступ к переменной из другой функции, которая уже завершила работу? _Ответ:_ Да. Если внутренняя функция была возвращена наружу (например, через `return`), ее скрытая ссылка `Reference to Outer` сохранит лексическое окружение внешней функции в памяти, и сборщик мусора его не уничтожит.
