**Hoisting (Всплытие)** — это механизм в JavaScript, при котором объявления переменных, функций и классов «поднимаются» в начало их области видимости на этапе компиляции (до фактического выполнения кода).

Важно понимать: физически код никуда не перемещается. Это особенность того, как движок (V8) создает **Lecxical Environment** (лексическое окружение) перед запуском скрипта.
### 1. Всплытие переменных

Здесь кроется главное различие между старым и новым стандартом JS.

- **`var`**: Всплывает и **инициализируется** значением `undefined`.

```js
console.log(a); // undefined (не ошибка!)
var a = 5;
```

- **`let` и `const`**: Всплывают, но **не инициализируются**. Они попадают в **TDZ (Temporal Dead Zone)**. До строки с объявлением они физически существуют в памяти, но доступ к ним закрыт.

```js
console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 10;
```

### 2. Всплытие функций

Это, пожалуй, самый важный аспект для структуры кода.

- **Function Declaration**: Всплывает **целиком** (и объявление, и тело функции). Её можно вызвать в любой части файла, даже до того, как она написана.
```js
sayHi(); // "Привет!" — работает!

function sayHi() {
  console.log("Привет!");
}
```

- **Function Expression** и **Arrow Functions**: Всплывают по правилам переменных, в которые они записаны.
```js
sayHello(); // TypeError: sayHello is not a function (если var)
// ReferenceError (если const/let)
  
var sayHello = function() { console.log("Hello!"); };
``` 

### 3. Всплытие классов

Классы в JS ведут себя так же, как `let` и `const`. Они всплывают, но обращение к ним до объявления вызовет `ReferenceError`. Это сделано для того, чтобы при наследовании (`extends`) базовый класс гарантированно был уже определен.

---

### 🔥 Что точно спросят (Ключевые моменты)

**1. Что всплывает выше: переменная или функция?** Если у переменной `var` и функции одинаковое имя, то **объявление функции имеет приоритет**.

```js
console.log(typeof foo); // "function"

var foo = 5;
function foo() {}
```

_Однако, если после объявления функции идет присваивание значения переменной (`foo = 5`), то значение перезапишется в процессе выполнения кода._

**2. Почему функции всплывают целиком, а переменные нет?** Это сделано для гибкости архитектуры (Mutual Recursion). Это позволяет функции А вызывать функцию Б, а функции Б вызывать функцию А, даже если одна из них определена ниже по коду.

**3. Как Hoisting влияет на производительность?** На самом деле, никак. Это просто этап работы парсера. Но для чистоты кода «хорошим тоном» считается:

1. Объявлять переменные в начале области видимости.
2. Использовать `const` и `let`, чтобы избегать багов с `undefined` из-за всплытия `var`.

---

### Резюме для заметок:

- **`var`** — всплывает, значение `undefined`.
- **`let / const / class`** — всплывают, но находятся в TDZ (ошибка при доступе).
- **Function Declaration** — всплывает целиком (можно вызвать «до»).
- **Function Expression** — не всплывает как функция (зависит от `var/let/const`).
