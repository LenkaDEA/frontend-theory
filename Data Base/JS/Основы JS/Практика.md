**3.** Что вернет выражение `[] == false`? Кратко распиши, как именно движок будет приводить здесь типы перед сравнением.
**Ответ**: 
Выражение: `[] == false`
1. **Шаг 1:** Один из операндов — `Boolean` (`false`). По правилам JS, булево значение приводится к числу. `false` становится **`0`**.
    - _Теперь выражение выглядит так:_ `[] == 0`
2. **Шаг 2:** Теперь мы сравниваем объект (`[]`) и число (`0`). Объект должен быть приведен к примитиву (алгоритм `ToPrimitive`).
    - Для массивов вызывается `.toString()`. `[].toString()` — это ** пустая строка `""`**.
    - _Теперь выражение выглядит так:_ `"" == 0`
3. **Шаг 3:** Сравниваем строку и число. Строка приводится к числу. Пустая строка `""` становится **`0`**.
    - _Теперь выражение выглядит так:_ `0 == 0`
4. **Шаг 4:** `0 === 0`. Результат: **`true`**.

> **Ответ:** `[] == false` вернет **`true`**.

**5.** В чем принципиальная разница между логическим ИЛИ (`||`) и оператором нулевого слияния (`??`)? Что выведет код ниже?

```js
const count1 = 0 || 5;
const count2 = 0 ?? 5;
```
**Ответ:** 
count1 = 5 ищет первое **«истинное» (truthy)** значение.
count2 = 0 ищет первое **«не пустое»** значение. Пустыми он считает **только `null` и `undefined`**.

**6.** У нас есть деструктуризация с rest-оператором. Является ли `rest` глубокой копией (deep copy)? Что выведет `console.log` в конце?


**7.** Что выведет вызов функции `foo` и почему?

```JavaScript
let x = 1;
function foo() {
  console.log(x);
  let x = 2;
}
foo();
```
**Ответ:** ~~выведет 1. т.к. 2 была объявлена после консоль лога. Дижок не нашел x и пошел искать выше.~~
Твоя логика («движок не нашел `x` и пошел выше») сработала бы, если бы внутри функции `foo` вообще не было объявления `let x = 2`. Но как только движок видит `let x` внутри блока, происходит следующее:

1. **Hoisting (Всплытие):** Движок при парсинге функции `foo` «замечает», что внутри есть своя локальная переменная `x`. Он «поднимает» объявление этой переменной в начало функции.
2. **Затенение (Shadowing):** Локальная `x` перекрывает (затеняет) внешнюю `x = 1`. Теперь внутри функции `foo` существует только своя, локальная `x`.
3. **TDZ (Временная мертвая зона):** Переменные `let` и `const` нельзя использовать до того, как выполнение кода дойдет до строки с их объявлением.
4. **Итог:** В момент вызова `console.log(x)` локальная переменная `x` уже «забронировала» имя в этой области видимости, но еще не была инициализирована. Обращение к ней в этот момент (внутри TDZ) вызывает ошибку, а не поход во внешнюю область видимости.

**8.** Классическая задача на Scope. Что окажется в консоли? Предложи **два** разных способа исправить код так, чтобы он вывел `0, 1, 2`.
```JavaScript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```
**Ответ:**
```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}

for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0, i);
}

for (var i = 0; i < 3; i++) { 
  (function(j) { 
    setTimeout(() => console.log(j), 0); }
  )(i);
```

**10.** Задача «со звездочкой» на комплексное понимание контекста и всплытия. Какое значение выведет `console.log(a)` в самом конце?
```JavaScript
var a = 1;

function update() {
  a = 10;
  return;
  function a() {}
}

update();
console.log(a);
```

**Ответ:** 
#### Шаг 1: Всплытие (Hoisting) внутри функции

Как только мы заходим в `update`, движок видит: `function a() {}`. Даже если она стоит после `return`, на этапе **компиляции** (парсинга) она **всплывает в самый верх функции**.

В итоге внутри `update` создается **локальная переменная** `a`, в которую записывается эта функция.

#### Шаг 2: Выполнение кода (Execution)

Теперь движок начинает выполнять код построчно:

1. Строка `a = 10;`. Движок смотрит: «Есть ли у меня локальная `a`?». Ответ: «Да, это та самая всплывшая функция».
2. **Движок перезаписывает локальную `a`**. Теперь локальная `a` равна `10`, а не функции.
3. **Глобальная `a` (которая равна 1) остается нетронутой!** Мы изменили только локальную переменную.
4. Происходит `return`.

#### Шаг 3: Финал

Мы выходим из функции. Локальная область видимости `update` уничтожается. Когда мы вызываем `console.log(a)`, мы обращаемся к **глобальной** `a`, которая как была `1`, так и осталась.
