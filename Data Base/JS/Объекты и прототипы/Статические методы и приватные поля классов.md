### 1. Статические методы и свойства (`static`)

Это методы и свойства, которые принадлежат самому **классу**, а не его экземплярам.

- **Как обращаться:** Только через имя класса (`User.compare()`), а не через `this` внутри экземпляра.
- **Для чего нужны:** Утилиты, фабричные методы (создание объектов), хранение общих настроек для всех объектов этого типа.
- **Наследование:** Статические свойства и методы **наследуются**. Если у `Parent` есть статический метод, он будет доступен и у `Child`.

```JavaScript
class User {
  static type = "GUEST"; // Статическое свойство

  static createAdmin() { // Фабричный метод
    return new User("Admin");
  }

  constructor(name) {
    this.name = name;
  }
}

const admin = User.createAdmin(); 
console.log(admin.type); // undefined (у экземпляра его нет)
console.log(User.type);  // "GUEST"
```

### 2. Приватные поля (`#`)

Это настоящая инкапсуляция на уровне движка. Приватные поля начинаются с символа `#`.

- **Доступность:** К ним невозможно обратиться извне класса. Попытка сделать это вызовет `SyntaxError`.
- **Где объявлять:** Приватные поля **обязательно** должны быть объявлены в начале класса.
- **Наследование:** Приватные поля **не наследуются** в привычном смысле — дочерний класс не имеет к ним доступа напрямую, только через публичные методы родителя.

```JavaScript
class BankAccount {
  #balance = 0; // Приватное поле

  deposit(amount) {
    this.#balance += amount;
  }

  get balance() {
    return this.#balance;
  }
}

const account = new BankAccount();
account.deposit(100);
console.log(account.#balance); // Ошибка!
```

### Что точно спросят на собеседовании (Senior-уровень)

1. **"В чем разница между `#private` и `private` в TypeScript?"**
    - _Ответ:_ `private` в TS — это «мягкая» проверка на этапе компиляции. В скомпилированном JS поле станет обычным публичным свойством. Символ `#` в JS — это «жесткая» приватность на уровне рантайма (движка), к полю физически нельзя получить доступ снаружи.

2. **"Можно ли использовать статические приватные поля?"**
    - _Ответ:_ Да, `static #count = 0` вполне валидно. Это поле будет доступно только внутри методов самого класса.

3. **"Как проверить, есть ли в объекте приватное поле, не вызывая ошибку?"**
    - _Ответ:_ Используется оператор `in`. Пример: `#field in obj`. Это вернет `true` или `false`.

4. **"Что будет с `this` в статическом методе?"**
    - _Ответ:_ В статическом методе `this` указывает на **сам класс** (функцию-конструктор), а не на объект-экземпляр. Это часто путает новичков.

5. **"Как приватные поля влияют на производительность?"**
    - _Ответ:_ Движкам (V8) сложнее оптимизировать доступ к приватным полям по сравнению с обычными свойствами из-за дополнительных проверок доступа, но в современных версиях разница практически нивелирована.
