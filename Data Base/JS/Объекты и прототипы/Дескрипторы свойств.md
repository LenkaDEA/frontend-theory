Дескриптор — это объект конфигурации свойства. Он говорит движку JS, как именно это свойство должно себя вести: можно ли его менять, удалять или видеть в циклах.
### 1. Два типа дескрипторов

Свойство может иметь либо **дескриптор данных**, либо **дескриптор доступа** (геттер/сеттер). Они не могут быть смешаны.
#### Дескриптор данных (Data Descriptor)

Содержит следующие флаги (по умолчанию при создании через `defineProperty` они все `false`!):

- **`value`**: само значение свойства.
- **`writable`**: если `true`, значение можно менять (иначе — «только для чтения»).
- **`enumerable`**: если `true`, свойство видно в циклах `for...in` и методе `Object.keys()`.
- **`configurable`**: если `true`, свойство можно удалить, а его дескриптор — изменить.

#### Дескриптор доступа (Accessor Descriptor)

Вместо `value` и `writable` используются функции:

- **`get`**: функция, которая срабатывает при чтении свойства.
- **`set`**: функция, которая срабатывает при записи.

### 2. Важные методы

- `Object.getOwnPropertyDescriptor(obj, prop)` — позволяет посмотреть текущие флаги свойства.
- `Object.defineProperty(obj, prop, descriptor)` — создает или изменяет свойство с конкретными флагами.

---
### Точки проверки на собеседовании (Interview Tips)

**1. "Ловушка" значений по умолчанию** Если ты создаешь свойство просто через `obj.a = 1`, то все флаги (`writable`, `enumerable`, `configurable`) автоматически будут `true`. Но если ты используешь `Object.defineProperty(obj, 'a', { value: 1 })`, то все остальные флаги по умолчанию будут **`false`**. Это часто просят предсказать в задачах на вывод кода.

**2. Неизменяемость объектов (Object Immortality)** Дескрипторы лежат в основе методов «заморозки» объектов. Тебя могут спросить разницу:

- **`Object.preventExtensions(obj)`**: запрещает добавлять новые свойства.
- **`Object.seal(obj)`**: запрещает добавлять/удалять свойства (ставит всем `configurable: false`), но существующие можно менять, если они `writable`.
- **`Object.freeze(obj)`**: «мёртвый» объект. Запрещает всё (ставит всем `configurable: false` и `writable: false`). _Важно:_ это поверхностная заморозка (вложенные объекты всё еще можно изменить).

**3. Почему нельзя смешивать?** Попытка указать одновременно `value` и `get` в одном дескрипторе приведет к ошибке `TypeError`. Свойство либо хранит данные, либо вычисляет их.

**4. Зачем нужен `enumerable: false`?** Обычно это используется для того, чтобы добавить объекту какие-то служебные методы или метаданные, которые не должны «вываливаться» наружу при переборе объекта (например, чтобы они не попали в `JSON.stringify` или `Object.keys`).

---
### Практический пример (на чем могут подловить):

```JavaScript
const user = {};
Object.defineProperty(user, 'id', {
  value: 123,
  writable: false,
  configurable: false
});

user.id = 456; // В обычном режиме проигнорируется, в 'use strict' — ошибка.
delete user.id; // false (не удалится)
console.log(user.id); // 123
```
