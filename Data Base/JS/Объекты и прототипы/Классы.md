### 1. Почему это «Синтаксический сахар»?

Классы в JS не вводят новую объектно-ориентированную модель. Это просто более лаконичная запись того, что мы раньше делали через функции-конструкторы и `prototype`.

Когда ты пишешь `class User { ... }`, под капотом происходит следующее:

1. Создается функция с именем `User`.
2. Тело метода `constructor` становится телом этой функции.
3. Все методы, описанные в классе (например, `sayHi()`), записываются в `User.prototype`.

### 2. Constructor и методы

- **`constructor`**: специальный метод для инициализации объекта. Он вызывается автоматически при `new`. Если ты его не напишешь, JS создаст пустой конструктор по умолчанию.
- **Методы**: в отличие от обычных функций, методы класса не имеют свойства `prototype` и всегда работают в строгом режиме (`use strict`).

### 3. Наследование и `super`

Это критически важная часть для интервью.

- **`extends`**: устанавливает связь между прототипами (прототипом `Child.prototype` становится `Parent.prototype`).

- **`super()`**: вызывает конструктор родителя.
        - **Правило №1:** В дочернем классе ты **обязан** вызвать `super()`, прежде чем обращаться к `this`. До вызова `super()` объекта `this` просто не существует.

- **`super.method()`**: позволяет вызвать метод родительского класса из метода дочернего (полезно при переопределении).

### 4. Геттеры и сеттеры (`get` / `set`)

Позволяют обращаться к методам как к обычным свойствам. Это удобно для инкапсуляции и валидации данных.

```JavaScript
class Square {
  constructor(side) {
    this._side = side; // '_' — конвенция для "приватных" полей (до ES2022)
  }
  get area() {
    return this._side ** 2;
  }
  set side(value) {
    if (value <= 0) throw new Error("Side must be positive");
    this._side = value;
  }
}

const s = new Square(5);
console.log(s.area); // 25 (вызов геттера без скобок)
s.side = 10;         // (вызов сеттера)
```

### Что точно спросят на собеседовании (Interview Killers)

1. **"В чем разница между классом и функцией-конструктором?"**

    - Классы нельзя вызвать без `new` (будет ошибка).
    - Классы не **hoisted** (нельзя создать экземпляр до объявления класса).
    - Методы класса всегда не перечисляемы (`enumerable: false`).
    - Весь код внутри класса всегда в `use strict`.

2. **"Что будет, если в конструкторе наследника не вызвать `super()`?"**
    - Будет `ReferenceError` при попытке доступа к `this`. Двигатель JS ожидает, что родитель сначала "соберет" объект.

3. **"Где лежат методы класса?"**
    - Методы (кроме статических) лежат в прототипе: `User.prototype.methodName`.

4. **"Как работают стрелочные функции в классах?"** (Частый вопрос про React-классы)
    - Если ты пишешь `handleClick = () => { ... }` внутри класса, этот метод попадет **в каждый конкретный экземпляр** (в `this`), а не в прототип. Это решает проблему с потерей `this`, но потребляет больше памяти, если объектов тысячи.
