### 1. Работа с Map

В `Map` мы всегда оперируем парой **ключ + значение**.

**Основные методы:**

```JavaScript
// 1. Инициализация
const map = new Map();

// Можно создать Map из массива массивов (Entries)
const userRoles = new Map([
  ['admin', 'Иван'],
  ['editor', 'Олег']
]);

// 2. Добавление и обновление (set)
// Метод set возвращает сам Map, поэтому можно делать «чейнинг»
map.set('1', 'string')
   .set(1, 'number')
   .set(true, 'boolean');

// 3. Получение (get)
console.log(map.get(1)); // 'number'
console.log(map.get('non-existent')); // undefined

// 4. Проверка наличия (has) и удаление (delete/clear)
console.log(map.has(true)); // true
map.delete(true);           // удаляет запись по ключу
console.log(map.size);      // количество элементов
map.clear();                // полная очистка
```

**Перебор (итерация):**

```JavaScript
const recipeMap = new Map([
  ['огурцы', 500],
  ['помидоры', 350]
]);

// Перебор по ключам
for (let vegetable of recipeMap.keys()) { ... }

// Перебор по значениям
for (let amount of recipeMap.values()) { ... }

// Перебор пар [key, value] (по умолчанию в for...of)
for (let entry of recipeMap) { 
  console.log(entry); // ['огурцы', 500]
}

// Встроенный forEach (порядок аргументов как в Array: value, key, map)
recipeMap.forEach((value, key) => {
  console.log(`${key}: ${value}`);
});
```

### 2. Работа с Set

В `Set` мы храним только **значения**.

**Основные методы:**

```JavaScript
// 1. Инициализация
const set = new Set();

// Часто создают из массива для фильтрации дублей
const numbers = new Set([1, 2, 3, 3, 2, 1]); // в сете будет только {1, 2, 3}

// 2. Добавление (add)
set.add(4);
set.add(5).add(6); // тоже поддерживает чейнинг

// 3. Проверка и удаление (has / delete)
console.log(set.has(1)); // true
set.delete(1);           // удаляет элемент
console.log(set.size);   // 5
set.clear();             // очистка
```

**Перебор:**

```JavaScript
const fruits = new Set(["apple", "banana", "mango"]);

for (let value of fruits) {
  console.log(value);
}

// forEach тоже есть (для совместимости с Map аргументы: value, valueAgain, set)
fruits.forEach((value, valueAgain) => {
  console.log(value);
});
```

### 🚩 Важный нюанс для собеседования:

Если тебя спросят: «Как превратить `Map` или `Set` обратно в массив?», отвечай уверенно:

1. **Spread-оператор:** `const arr = [...mySet];`
2. **Array.from:** `const arr = Array.from(myMap);`

### 1. Map (в сравнении с Object)

`Map` — это коллекция пар ключ-значение, как и `Object`. Но у них есть принципиальные архитектурные различия.

**Главные отличия (что спрашивают на собесах):**

- **Типы ключей (Самое важное):** В `Object` ключами могут быть только строки (`String`) и символы (`Symbol`). В `Map` ключом может быть **абсолютно любой тип данных**, включая функции, объекты, массивы и даже DOM-элементы.
    - _Пример с собеса:_ Если в объект передать другой объект в качестве ключа, он приведется к строке `"[object Object]"`. В `Map` он останется уникальной ссылкой на этот объект.

- **Определение размера:** У `Map` есть удобное встроенное свойство `map.size`. У объекта придется делать `Object.keys(obj).length`, что требует дополнительных вычислений ($O(n)$).

- **Итерируемость:** `Map` по умолчанию является итерируемым (iterable). Его можно сразу обходить через `for...of`. Объект напрямую не итерируется (нужны `Object.keys / values / entries`).

- **Порядок элементов:** `Map` строго гарантирует обход элементов в порядке их добавления. В объектах порядок ключей тоже стал предсказуемым (начиная с ES6), но там есть нюансы (целочисленные ключи всегда идут первыми).

- **Производительность:** `Map` внутренне оптимизирован для сценариев с **частым добавлением и удалением** пар ключ-значение. `Object` лучше подходит для статических структур данных или записей (records).

### 2. Set (в сравнении с Array)

`Set` — это коллекция **уникальных** значений любого типа.

**Главные отличия (что спрашивают на собесах):**

- **Уникальность «из коробки»:** В массиве могут быть дубликаты, в `Set` — никогда.
    - _Классический вопрос:_ Как быстро убрать дубликаты из массива? Ответ: `const unique = [...new Set(array)];`.

- **Скорость поиска и удаления:** Метод `set.has(value)` и `set.delete(value)` работают в среднем за константное время $O(1)$. В массиве аналогичные `array.includes(value)` или поиск для удаления через `indexOf` работают за $O(n)$ (линейное время). Для больших объемов данных `Set` работает значительно быстрее.

- **Индексация:** Массив — это индексированная коллекция. Вы можете получить элемент по индексу: `arr[0]`. В `Set` индексов нет, нельзя достать «второй элемент сетта». Доступ к элементам осуществляется только через проверку наличия (`has`) или итерацию.

### 💡 «Подводные камни» (Interview Gotchas)

Выпиши эти моменты отдельно, на них часто ловят джунов и мидлов:

1. **Алгоритм сравнения SameValueZero:** Как `Set` и `Map` понимают, что значения одинаковые? Они используют алгоритм _SameValueZero_. Он работает почти как строгое равенство `===`, но с одним важным отличием: **`NaN` считается равным `NaN`**. Поэтому в `Set` можно добавить только один `NaN`, а `Map` корректно найдет ключ `NaN`.

2. **Сравнение объектов по ссылке:** Если ты добавишь в `Set` два идентичных по структуре объекта: `set.add({a: 1}); set.add({a: 1});`, размер `Set` станет равен 2. Потому что это две разные ссылки в памяти. То же самое касается ключей в `Map`.
