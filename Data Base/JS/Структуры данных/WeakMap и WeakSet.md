### 1. Что это такое?

**WeakMap** и **WeakSet** — это «слабые» версии `Map` и `Set`. Их главная особенность в том, что они **не препятствуют сборке мусора** для объектов, которые в них хранятся.

---
### 2. Базовый синтаксис и ограничения

Здесь правил меньше, но они жестче.
#### WeakMap

- **Ключи:** Только объекты (и с недавних пор уникальные символы). Строку или число в качестве ключа использовать **нельзя**.
- **Значения:** Любые типы данных.

```JavaScript
let user = { name: "Ivan" };
const weakMap = new WeakMap();

weakMap.set(user, "some metadata"); // OK
weakMap.get(user); // "some metadata"

// weakMap.set("key", "value"); // ОШИБКА: Invalid value used as weak map key
```

#### WeakSet

- Хранит только объекты.

```JavaScript
let obj1 = { id: 1 };
const weakSet = new WeakSet();

weakSet.add(obj1); // OK
weakSet.has(obj1); // true
```

**Методы:** У обеих структур доступны только: `set/add`, `get` (только для WeakMap), `has`, `delete`. **Нет свойств `size`, нет методов `keys()`, `values()`, `entries()` и нет `forEach`.**

---
### 3. Особенности работы со Сборщиком Мусора (Garbage Collector)

Это самый важный блок для собеседования.

**В обычном `Map`:** Если объект используется как ключ, он будет храниться в памяти до тех пор, пока жив сам `Map`. Даже если в остальном коде на этот объект не осталось ссылок, `Map` будет держать его «за руку», не давая сборщику мусора его удалить. Это может привести к **утечкам памяти**.

**В `WeakMap`:** Ссылка на объект-ключ является «слабой». Если в коде больше нет других ссылок на этот объект (кроме как внутри `WeakMap`), сборщик мусора **удалит объект из памяти** вместе со всеми данными, которые были к нему привязаны в `WeakMap`.

> **Почему нельзя итерировать?** На собеседовании спросят: «Почему в WeakMap нет метода `.keys()`?». **Ответ:** Потому что сборщик мусора работает асинхронно и в фоновом режиме. Мы точно не знаем, в какой момент объект будет удален. Если бы итерация была возможна, то в один момент времени в коллекции было бы 5 элементов, а через секунду — 3, хотя мы ничего не удаляли вручную. Это сделало бы поведение кода непредсказуемым.

### 4. Реальные сценарии использования (Use Cases)

Зачем нам вообще это нужно?

1. **Дополнительные данные (Metadata) для объектов:** Допустим, ты работаешь с объектами пользователей, которые приходят из сторонней библиотеки. Тебе нужно хранить по ним какую-то информацию (например, время последнего клика), но ты не хочешь «засорять» сам объект или следить за его удалением. Используй `WeakMap`. Как только пользователь исчезнет из системы, его метаданные удалятся автоматически.

2. **Кеширование (Memoization):** Кеширование результатов выполнения функции для конкретного объекта. Когда объект будет уничтожен, кеш очистится сам.

3. **Приватные данные в классах (устаревает с приходом `#`):** Раньше `WeakMap` использовали для имитации `private` полей, где ключом был `this`.

4. **Хранение DOM-элементов:** Если мы привязываем данные к кнопке в DOM через `WeakMap`, то при удалении кнопки из DOM (`button.remove()`), данные о ней в `WeakMap` тоже перестанут занимать память.

### 🚩 Вопросы от «интервьюера»:

1. **«Что произойдет, если я сделаю `let obj = {a: 1};` положу его в WeakMap, а потом напишу `obj = null;`?»** 
   _Ответ:_ Объект станет доступен для сборщика мусора и через некоторое время будет удален из памяти, а запись в `WeakMap` исчезнет автоматически.
2. **«Почему нельзя использовать строку в качестве ключа в WeakMap?»**
   _Ответ:_ Потому что строки в JS — это примитивы, они неизменяемы и не удаляются сборщиком мусора так, как объекты. Смысл «слабой связи» теряется, так как строка «живет» по другим правилам.
