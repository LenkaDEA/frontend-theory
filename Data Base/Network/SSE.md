### Определение
Server-Sent Events (SSE) — это технология, позволяющая серверу отправлять данные (события) клиенту в одностороннем порядке (от сервера к клиенту) через одно долгоживущее HTTP-соединение.

### Зачем нужно и где используется
- **Зачем нужно:** Идеально подходит для ситуаций, когда клиенту нужно только _получать_ обновления в реальном времени, без необходимости часто _отправлять_ данные на сервер.
- **Где используется:** Трансляции спортивных матчей (счет, текстовые события), ленты новостей, графики котировок акций, статусы серверов или длительных задач, уведомления в реальном времени (например, "вам поставили лайк").

### Принцип работы
1. Клиент открывает соединение с сервером с помощью специального браузерного API — `EventSource`.
2. Запрос идет по обычному протоколу HTTP, но клиент указывает заголовок `Accept: text/event-stream`.
3. Сервер отвечает заголовком `Content-Type: text/event-stream` и оставляет соединение открытым.
4. Сервер начинает периодически отправлять текстовые данные в виде специальных блоков, разделенных двойным переводом строки `\n\n`.
5. Клиент получает эти данные по мере их поступления и вызывает соответствующие обработчики (на клиенте срабатывает событие `message`).
6. Соединение остается открытым до тех пор, пока клиент (`eventSource.close()`) или сервер его явно не закроет.

### 4. Важные моменты
- **Односторонняя связь:** Данные идут строго в одном направлении — от сервера к клиенту. Если клиенту нужно что-то отправить на сервер, он делает это параллельно обычным HTTP-запросом (`fetch`).
- **Автоматическое переподключение:** Огромный плюс SSE — браузер *сам* попытается восстановить соединение, если оно оборвется. Более того, он может передать ID последнего полученного сообщения, чтобы сервер дослал пропущенные события.
- **Только текст:** SSE поддерживает передачу только текстовых данных (обычно это JSON, переведенный в строку). Для стриминга бинарных данных не подходит.
- **Ограничение на количество соединений:** В старых реализациях HTTP/1.1 браузеры ограничивают количество одновременных подключений к одному домену (часто не более 6). Если открыть 6 вкладок с SSE, 7-я может зависнуть. Использование HTTP/2 решает эту проблему (лимит становится намного выше).
- **Работает поверх стандартного HTTP:** Легко настраивается, отлично проходит через прокси и фаерволы, не требует специальных портов (в отличие от кастомных TCP-решений).
