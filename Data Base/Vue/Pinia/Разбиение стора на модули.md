#### Архитектурная теория

В Vuex (и Redux) стейт представлял собой единое глобальное дерево (Root State). Чтобы организовать код, мы использовали "модули" (modules), которые вкладывались друг в друга, образуя иерархию (например, `store.state.cart.items`). Это создавало проблемы с типизацией и доступом к корневому стейту из вложенных модулей (`rootState`).

Pinia использует Плоскую архитектуру (Flat Architecture).

- _Как это работает:_ В Pinia нет понятия "вложенных модулей". Каждый стор, созданный через `defineStore`, является независимым, корневым стором. Они живут на одном уровне в глобальном реестре Pinia.
- _Связь сторов:_ Поскольку сторы независимы, "модульность" достигается просто за счет импорта одного стора внутри другого. Если стору `Cart` нужен стор `User` (чтобы проверить авторизацию перед покупкой), он просто импортирует `useUserStore` и вызывает его внутри своего геттера или экшена.

#### Аналогия с MobX / React

- MobX: В MobX мы часто создаем `RootStore`, который инициализирует дочерние сторы (`UserStore`, `CartStore`) и передает ссылку на себя (или на соседние сторы) в их конструкторы. В Pinia этот паттерн (RootStore) не нужен, так как функция `useStore()` сама по себе является синглтоном в рамках приложения Vue — она всегда возвращает один и тот же инстанс.
- React: Это похоже на использование нескольких независимых Context Providers (например, `<AuthProvider>` и `<CartProvider>`), где один хук (`useCart`) внутри себя вызывает другой хук (`useAuth`).

#### Best Practices & TypeScript

- Именование: Называй сторы по их доменной области (`useAuthStore`, `useProductStore`, `useUiStore`). Идентификатор (первый аргумент `defineStore`) должен быть уникальным (например, `'auth'`, `'products'`).
- Где вызывать `useStore()`:
    - _В компонентах:_ Вызывай на верхнем уровне функции `setup`.
    - _Внутри другого стора:_ Вызывай `useStore()` внутри геттера или экшена, а не на верхнем уровне файла. Это критически важно для предотвращения циклических зависимостей (Circular Dependencies) и проблем с инициализацией Pinia (когда стор пытается создаться до того, как Pinia была установлена в приложение).

#### Главный "подводный камень"

Циклические зависимости (Circular Dependencies). Представь ситуацию: `useAuthStore` импортирует `useCartStore` (чтобы очистить корзину при логауте), а `useCartStore` импортирует `useAuthStore` (чтобы проверить токен при добавлении товара). Если они вызовут `use...Store()` на верхнем уровне модуля, бандлер (Vite/Webpack) упадет с ошибкой циклического импорта, или один из сторов будет `undefined`.

_Решение:_ Ленивая инициализация (Lazy Evaluation). Вызывай `use...Store()` только в тот момент, когда он реально нужен (внутри функции экшена или геттера). В этот момент оба модуля уже будут загружены бандлером.

#### Пример кода

Покажу правильную организацию взаимодействия двух сторов, избегая циклических зависимостей.
```ts
// --- stores/auth.ts ---
import { defineStore } from 'pinia'
// Импортируем функцию, но НЕ вызываем ее здесь!
import { useCartStore } from './cart' 

export const useAuthStore = defineStore('auth', () => {
  const isAuthenticated = ref(true)
  const user = ref({ id: 1, name: 'John' })

  function logout() {
    isAuthenticated.value = false
    user.value = null
    
    // ✅ ПРАВИЛЬНО: Вызываем useCartStore внутри экшена.
    // В этот момент Pinia уже инициализирована, и циклический импорт не страшен.
    const cartStore = useCartStore()
    cartStore.clearCart() // Очищаем корзину при выходе
  }

  return { isAuthenticated, user, logout }
})
```

```ts
// --- stores/cart.ts ---
import { defineStore } from 'pinia'
import { computed, ref } from 'vue'
// Импортируем функцию, но НЕ вызываем ее здесь!
import { useAuthStore } from './auth'

export const useCartStore = defineStore('cart', () => {
  const items = ref([{ id: 101, price: 500 }])

  // ✅ ПРАВИЛЬНО: Вызываем useAuthStore внутри геттера.
  // Геттер ленивый, он выполнится только при обращении к нему.
  const canCheckout = computed(() => {
    const authStore = useAuthStore()
    return authStore.isAuthenticated && items.value.length > 0
  })

  function clearCart() {
    items.value = []
  }

  async function checkout() {
    // ✅ ПРАВИЛЬНО: Вызываем внутри экшена
    const authStore = useAuthStore()
    
    if (!authStore.isAuthenticated) {
      throw new Error('Необходимо авторизоваться!')
    }
    
    // Логика покупки...
    console.log(`Покупка оформлена на пользователя: ${authStore.user?.name}`)
    clearCart()
  }

  return { items, canCheckout, clearCart, checkout }
})
```
