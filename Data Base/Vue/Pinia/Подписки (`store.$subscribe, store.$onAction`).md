#### Архитектурная теория

Pinia предоставляет встроенные механизмы для наблюдения за жизненным циклом стора. Это паттерн Observer (Наблюдатель), реализованный на уровне самого инстанса Pinia.

1. `store.$subscribe(callback, options?)`
    - _Что делает:_ Отслеживает любые изменения стейта (state).
    - _Как работает:_ Под капотом это обертка над Vue-шным `watch()`, настроенная на глубокое (deep) отслеживание всего объекта стейта.
    - _Особенность:_ В отличие от обычного `watch`, `$subscribe` срабатывает _только один раз_ после завершения синхронной транзакции (патча), даже если внутри экшена ты изменил 10 разных свойств. Коллбэк получает объект `mutation` (информация о том, как изменился стейт: прямой `set`, `patch` объекта или функции) и сам `state`.
    
2. `store.$onAction(callback)`
    - _Что делает:_ Отслеживает вызовы методов-экшенов (actions), а не изменения данных.
    - _Как работает:_ Pinia оборачивает все твои экшены в прокси-функции. Когда ты вызываешь экшен, Pinia сначала триггерит подписчиков `$onAction`, передавая им имя экшена, переданные аргументы и хуки жизненного цикла самого экшена (`after`, `onError`).
    - _Особенность:_ Позволяет "вклиниться" в процесс выполнения экшена: узнать, когда он начался, когда успешно завершился (даже если он асинхронный!) или когда упал с ошибкой.

#### Аналогия с MobX / React

- `$subscribe`:
    - _MobX:_ Аналог `reaction` или `autorun` (или `spy` для отладки).
    - _React:_ Аналог `useEffect`, который зависит от всего стейта.
- `$onAction`:
    - _MobX:_ Аналог `spy` или middleware, перехватывающего вызовы `@action`.
    - _React:_ В React нет прямого аналога из коробки. В Redux это классические Middleware (например, для логирования каждого задиспатченного экшена).

#### Best Practices & TypeScript

- Отвязка при размонтировании (Unmounting): По умолчанию, если ты вызываешь `$subscribe` или `$onAction` внутри компонента (`setup`), Pinia автоматически удалит эту подписку, когда компонент размонтируется. Если ты хочешь, чтобы подписка жила вечно (например, глобальный логгер), нужно передать `{ detached: true }` вторым аргументом.
- Сценарии для `$subscribe`:
    - Синхронизация стейта с `localStorage` / `sessionStorage` / `IndexedDB`.
    - Отправка аналитики при изменении определенных данных.
- Сценарии для `$onAction`:
    - Глобальное логирование вызовов API (какой экшен с какими аргументами вызван).
    - Реализация паттерна Undo/Redo (сохранение истории действий).
    - Показ глобального лоадера или обработка ошибок для определенных экшенов.

#### Главный "подводный камень"

Зацикливание в `$subscribe`. Если внутри коллбэка `$subscribe` ты попытаешься мутировать _тот же самый стор_, ты вызовешь бесконечный цикл (изменение -> подписка -> изменение -> подписка). _Решение:_ Если нужно реагировать на изменение стейта изменением другого стейта, лучше используй `computed` (геттеры) или обычный `watch` на конкретное свойство, а не глобальный `$subscribe`.

#### Пример кода

Покажу два реальных сценария: авто-сохранение и логирование асинхронных операций.
```js
// components/SettingsPanel.vue
<script setup lang="ts">
import { useSettingsStore } from '@/stores/settings'

const settingsStore = useSettingsStore()

// --- Пример 1: $subscribe для LocalStorage ---
// Сработает после любого изменения в state
settingsStore.$subscribe((mutation, state) => {
  // mutation.type может быть 'direct' (прямое изменение), 'patch object' или 'patch function'
  console.log(`[Store: ${mutation.storeId}] State changed!`)
  
  // Сохраняем весь стейт в localStorage
  localStorage.setItem('app-settings', JSON.stringify(state))
}, { 
  detached: true // Подписка останется жить даже если компонент удалится
})


// --- Пример 2: $onAction для логирования и обработки ошибок ---
settingsStore.$onAction(({
  name,      // имя вызванного экшена (например, 'saveSettings')
  store,     // инстанс стора
  args,      // массив аргументов, переданных в экшен
  after,     // хук: вызывается после успешного завершения (или resolve Promise)
  onError    // хук: вызывается при ошибке (или reject Promise)
}) => {
  
  const startTime = Date.now()
  console.log(`🚀 Начало экшена: ${name} с аргументами:`, args)

  // Если экшен асинхронный, after дождется завершения Promise
  after((result) => {
    const duration = Date.now() - startTime
    console.log(`✅ Экшен ${name} успешно завершен за ${duration}ms. Результат:`, result)
  })

  // Перехват ошибок внутри экшена
  onError((error) => {
    console.warn(`❌ Ошибка в экшене ${name}:`, error)
    // Здесь можно отправить ошибку в Sentry
    // Sentry.captureException(error, { extra: { action: name, args } })
  })
})
</script>
```
