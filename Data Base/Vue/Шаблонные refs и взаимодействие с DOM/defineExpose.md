**`defineExpose`** — это специальный макрос компилятора во Vue 3 (доступен только при использовании `<script setup>`), который позволяет дочернему компоненту явно указать, какие свойства, переменные или методы он хочет сделать "публичными", то есть доступными для родительского компонента через `ref`.

В React ближайшим, но более громоздким аналогом является хук `useImperativeHandle` в связке с `forwardRef`.

### Как это работает

1. В дочернем компоненте (со `<script setup>`) ты объявляешь свои реактивные переменные и функции.
2. По умолчанию они "заперты" внутри этого компонента.
3. Ты вызываешь макрос `defineExpose({})` и передаешь в него объект.
4. Всё, что ты положишь в этот объект, станет доступно родителю, когда тот обратится к компоненту через `ref.value`.

### Нюансы реализации

*   **Это макрос, а не функция:** `defineExpose` не нужно импортировать из `'vue'`. Компилятор Vue сам понимает его во время сборки (так же, как `defineProps` или `defineEmits`).
*   **Инкапсуляция (безопасность):** Если ты не вызовешь `defineExpose`, родительский компонент, получив `ref` на ребенка, увидит только пустой объект. Он не сможет ни прочитать внутреннее состояние, ни вызвать внутренние функции. Это защищает компонент от нежелательного вмешательства извне.
*   **Реактивность сохраняется:** Если ты "экспозишь" (открываешь) реактивную переменную (созданную через `ref` или `reactive`), родитель сможет не только прочитать её, но и изменить, и компонент отреагирует на это.
*   **Использование с Options API:** Если ты пишешь компонент без `<script setup>` (например, используя функцию `setup()` или старый Options API), то компонент по умолчанию **открыт**. В таком случае `defineExpose` не используется, и родитель имеет доступ ко всему, что возвращает функция `setup()`.

### Примеры для понимания и запоминания

Давай починим наш пример с модальным окном из предыдущего шага.

#### Пример 1: Открываем метод для родителя

**Дочерний компонент: `Modal.vue`**
```vue
<script setup>
import { ref } from 'vue'

// Внутреннее состояние. Родитель о нем не знает и не может изменить напрямую.
const isVisible = ref(false)
const title = ref('Секретный заголовок')

// Внутренние методы
const open = () => {
  isVisible.value = true
}

const close = () => {
  isVisible.value = false
}

// РАЗРЕШАЕМ ДОСТУП: 
// Мы говорим: "Дорогой родитель, если ты обратишься ко мне через ref, 
// ты сможешь дернуть только за ручки 'open' и 'close'". 
// Переменные 'isVisible' и 'title' остаются спрятанными.
defineExpose({
  open,
  close
})
</script>

<template>
  <div v-if="isVisible" class="modal">
    <h2>{{ title }}</h2>
    <button @click="close">Закрыть внутри модалки</button>
  </div>
</template>
```

**Родительский компонент: `App.vue`**
```vue
<script setup>
import { ref } from 'vue'
import Modal from './Modal.vue'

// Создаем ссылку
const modalRef = ref(null)

const handleOpen = () => {
  // Успех! Метод open был разрешен в defineExpose.
  modalRef.value.open() 
  
  // ОШИБКА (undefined)! Мы не экспозили title.
  // console.log(modalRef.value.title) 
}
</script>

<template>
  <div>
    <button @click="handleOpen">Открыть модальное окно снаружи</button>
    <Modal ref="modalRef" />
  </div>
</template>
```

#### Пример 2: Открываем состояние (реактивную переменную)

Иногда нужно, чтобы родитель мог прочитать данные из ребенка. Например, мы сделали сложный компонент формы-калькулятора, и родителю нужен только итоговый результат.

**Дочерний компонент: `Calculator.vue`**
```vue
<script setup>
import { ref, computed } from 'vue'

const a = ref(0)
const b = ref(0)

// Допустим, это сложная логика
const result = computed(() => a.value + b.value)

// Разрешаем родителю только читать результат
defineExpose({
  result
})
</script>

<template>
  <div>
    <input v-model.number="a" type="number">
    <input v-model.number="b" type="number">
    <p>Сумма: {{ result }}</p>
  </div>
</template>
```

**Родительский компонент: `App.vue`**
```vue
<script setup>
import { ref } from 'vue'
import Calculator from './Calculator.vue'

const calcRef = ref(null)

const submitData = () => {
  // Родитель читает значение из ребенка
  // Обрати внимание: мы пишем calcRef.value.result, 
  // Vue автоматически "распаковывает" (unwrap) ref 'result', 
  // поэтому нам не нужно писать calcRef.value.result.value
  alert(`Я отправляю на сервер результат: ${calcRef.value.result}`)
}
</script>

<template>
  <div>
    <Calculator ref="calcRef" />
    <button @click="submitData">Отправить</button>
  </div>
</template>
```

### Резюме для собеседования
Если на собеседовании спросят: "Как получить доступ к методу дочернего компонента во Vue 3?", идеальный ответ звучит так:

> "Нужно повесить шаблонный `ref` на компонент в родителе. Но поскольку компоненты на `<script setup>` по умолчанию инкапсулированы (закрыты), в дочернем компоненте необходимо явно использовать макрос `defineExpose`, чтобы 'выставить наружу' нужные методы или реактивные переменные."
