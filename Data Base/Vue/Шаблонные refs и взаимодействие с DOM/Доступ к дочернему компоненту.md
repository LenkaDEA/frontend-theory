### Суть "доступа к методам" дочернего компонента

Представь, что у тебя есть дочерний компонент — модальное окно (`Modal.vue`), умная таблица или видеоплеер. Внутри этого дочернего компонента (в его секции `<script>`) ты написал функции, которые управляют его состоянием. 

Например, в видеоплеере есть функция `play()`, а в модалке — функция `open()` и `close()`.

"Доступ к методам" означает, что **Родительский компонент** может через `ref` получить ссылку на этот дочерний компонент и напрямую вызвать его внутреннюю функцию, как обычный метод объекта: `childRef.value.open()`. 

Вместо того чтобы передавать пропс `isOpen={true}` из родителя в ребенка (как это чаще делают в React), родитель просто дергает за "ниточку" (метод) внутри ребенка.

---

### Иллюстрация: Как это выглядит концептуально

Давай представим, что дочерние компоненты во Vue 3 были бы полностью открытыми (хотя с `<script setup>` это не так, о чем мы поговорим в теме `defineExpose`).

**Дочерний компонент (Modal.vue)** — *Допустим, у него есть метод `open`*
```javascript
// Внутренняя логика ребенка
const isVisible = ref(false)

// Метод, который мы хотим вызвать из родителя
const open = () => {
  isVisible.value = true
}
```

**Родительский компонент (App.vue)**
```vue
<script setup>
import { ref } from 'vue'
import Modal from './Modal.vue'

// 1. Создаем ссылку на компонент
const myModal = ref(null)

const handleButtonClick = () => {
  // 2. ДОСТУП К МЕТОДУ: Родитель напрямую вызывает функцию, 
  // которая была написана внутри Modal.vue
  myModal.value.open() 
}
</script>

<template>
  <button @click="handleButtonClick">Открыть модалку</button>
  
  <!-- Привязываем ref к компоненту -->
  <Modal ref="myModal" />
</template>
```

### Почему это важно знать для собеседования (сравнение с React)

*   **React-подход (Декларативный):** В React родитель обычно владеет состоянием (`const [isOpen, setIsOpen] = useState(false)`) и передает его вниз через пропсы (`<Modal isOpen={isOpen} />`). Ребенок пассивно реагирует на изменение пропса.
*   **Vue-подход (Допускается Императивный):** Во Vue тоже горячо приветствуется реактивный подход через пропсы (и это считается *best practice*). Но Vue исторически дает очень удобную возможность для **императивного** подхода: когда состояние (например, открыта ли модалка) живет внутри самого ребенка, а родитель просто дает ему команды (вызывает методы `open()` или `close()`).

### Что значит "закрыты по умолчанию"?

Как я упоминал ранее, если ты используешь современный синтаксис `<script setup>`, код из примера выше **работать не будет** и выбросит ошибку. 

По умолчанию Vue 3 "прячет" все внутренности компонента (все его переменные `const isVisible` и функции `const open`), чтобы родитель случайно не сломал логику ребенка. `myModal.value` вернет пустой прокси-объект, и вызов `myModal.value.open()` приведет к ошибке `TypeError: myModal.value.open is not a function`.

Чтобы родитель мог вызвать метод `open()`, дочерний компонент должен **явно разрешить** это.
