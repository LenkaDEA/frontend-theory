**`useTemplateRef`** — это новая встроенная функция (composable) во Vue 3.5+, предназначенная специально для связывания реактивных переменных в `<script>` с атрибутами `ref` в `<template>`. 

До Vue 3.5 для получения доступа к DOM/компонентам использовался обычный `ref()` (как мы разбирали в первой части). Теперь `useTemplateRef` является **рекомендуемым** (best practice) способом делать это.

### Как это работает

Процесс почти такой же, но с небольшим синтаксическим отличием:

1. В секции `<script setup>` мы импортируем `useTemplateRef` из `'vue'`.
2. Вызываем `useTemplateRef('строковыйКлюч')`. В качестве аргумента передаем строковое имя, которое мы собираемся использовать в шаблоне.
3. В секции `<template>` мы вешаем атрибут `ref="строковыйКлюч"`.

### Зачем это добавили? (Нюансы и проблемы старого подхода)

Чтобы понять всю прелесть `useTemplateRef`, нужно понять, **какие проблемы были у старого подхода с обычным `ref()`**.

**Проблема 1: Путаница в типах и назначениях**
В старом подходе мы писали `const myInput = ref(null)`. Глядя на эту строчку, нельзя сразу сказать: это просто реактивная переменная, хранящая `null`, или это "заготовка" для привязки к DOM-элементу? `useTemplateRef` делает код самодокументируемым: сразу ясно, что это ссылка на элемент в шаблоне.

**Проблема 2: Жесткая привязка имени переменной**
Раньше имя переменной в скрипте (`const myInput`) **обязано** должно было совпадать со значением атрибута в шаблоне (`ref="myInput"`). Если ты переименовывал переменную в скрипте, но забывал обновить шаблон — ссылка ломалась и возвращала `null`.
С `useTemplateRef` имя переменной не имеет значения, важен только **строковый ключ**, который ты передаешь.

**Проблема 3: Ад с TypeScript (главная причина)**
До Vue 3.5, если ты хотел строго типизировать `ref` для элемента, приходилось писать костыли, потому что изначально значение `null`:
```typescript
// Старый подход (TS)
// Нужно явно указывать тип HTMLInputElement | null и инициализировать null
const inputRef = ref<HTMLInputElement | null>(null)
```

`useTemplateRef` решает это намного изящнее.
```ts
// Vue сам добавит `| null` к возвращаемому типу "под капотом".
const inputRef = useTemplateRef<HTMLInputElement>('my-input')
```

### Примеры для понимания и запоминания

Давай перепишем наш первый пример (с автофокусом) на новый лад.

#### Пример 1: Базовое использование (Без TypeScript)

```vue
<script setup>
import { useTemplateRef, onMounted } from 'vue'

// 1. Используем новую функцию. 
// 'my-input-element' - это строковый ключ, который будет искать Vue в шаблоне.
// Имя переменной (inputRef) может быть ЛЮБЫМ.
const inputRef = useTemplateRef('my-input-element')

onMounted(() => {
  // 2. Доступ точно такой же, через .value
  inputRef.value.focus()
})
</script>

<template>
  <div>
    <!-- 3. Здесь указываем строковый ключ из шага 1 -->
    <input ref="my-input-element" placeholder="Сюда будет фокус" />
  </div>
</template>
```
*Обрати внимание: мы избавились от `ref(null)`.*

#### Пример 2: Преимущество переименования
Допустим, у нас длинное и неудобное имя в шаблоне:
```vue
<script setup>
import { useTemplateRef, onMounted } from 'vue'

// Мы можем назвать переменную коротко (btn), 
// но привязать её к длинному ключу в шаблоне
const btn = useTemplateRef('very-long-and-complex-button-ref-name')

onMounted(() => {
  console.log(btn.value) // Выведет кнопку
})
</script>

<template>
  <button ref="very-long-and-complex-button-ref-name">Клик</button>
</template>
```

#### Пример 3: Идеально для TypeScript (бонус для мидла)
Если на собеседовании ты упомянешь типизацию, это будет огромный плюс.

```vue
<script setup lang="ts">
import { useTemplateRef, onMounted } from 'vue'

// Теперь TS точно знает, что это ссылка на инпут, 
// и тебе не нужно писать | null или инициализировать его нулем.
const inputRef = useTemplateRef<HTMLInputElement>('my-input')

// Если мы ссылаемся на компонент:
// import MyComponent from './MyComponent.vue'
// const compRef = useTemplateRef<InstanceType<typeof MyComponent>>('my-comp')

onMounted(() => {
  // TS сам понимает, что inputRef.value может быть null (до монтирования),
  // поэтому подскажет использовать опциональную цепочку (?.)
  inputRef.value?.focus()
})
</script>

<template>
  <input ref="my-input" />
</template>
```

> "Для работы с шаблонными ссылками я предпочитаю использовать новый `useTemplateRef()`. В отличие от старого подхода с обычным `ref(null)`, он разделяет имя переменной и имя атрибута в шаблоне (через строковый ключ), делает код более читаемым (сразу понятен интент) и значительно упрощает типизацию в TypeScript."
