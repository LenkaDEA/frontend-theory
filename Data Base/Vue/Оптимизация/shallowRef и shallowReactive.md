Эти API позволяют отказаться от глубокой реактивности в пользу поверхностной (shallow).

#### ⚙️ Механика «под капотом»
*   **`shallowRef`**: Создает объект с геттером и сеттером для свойства `.value`, но **не трогает** то, что лежит внутри. Если ты положишь туда объект, Vue не будет рекурсивно превращать его свойства в Proxy. Реактивность сработает *только* при полном переприсваивании `myShallowRef.value = newValue`.
*   **`shallowReactive`**: Оборачивает в `Proxy` только **первый (верхний) уровень** свойств объекта. Мутация `obj.firstLevel = 'new'` вызовет обновление интерфейса, но мутация `obj.firstLevel.nested = 'new'` пройдет незамеченной для системы реактивности Vue.

#### ⚛️ Аналог из React (для понимания)
*   **`shallowRef`** — это практически 1-в-1 классический **`useState`** в React! В React, если у тебя в стейте лежит объект, ты не можешь просто поменять `state.user.name = 'Ivan'` — React этого не увидит. Тебе нужно передать новую ссылку: `setState({ ...state, user: { ...state.user, name: 'Ivan' } })`. `shallowRef` заставляет тебя работать с данными во Vue точно так же — через иммутабельность и замену ссылки на объект целиком.
*   **`useRef`** (частично): Если ты хранишь в `shallowRef` инстанс сторонней библиотеки (например, график Chart.js) и никогда не переприсваиваешь `.value`, он ведет себя как `useRef` — просто хранилище мутабельных данных без влияния на рендер.

#### 🎯 Идеальный Use Case
1.  **Огромные массивы данных (Data Tables, Charts)**: Ты получаешь с бэкенда массив из 10 000 объектов для отрисовки графика или таблицы. Тебе не нужно реактивно отслеживать изменение каждого поля в каждом объекте (ты не собираешься их редактировать поштучно). Использование `shallowRef` сэкономит мегабайты оперативной памяти и миллисекунды при инициализации, так как Vue не будет создавать 10 000 Proxy-объектов.
2.  **Инстансы сторонних библиотек**: Хранение экземпляров Three.js, Leaflet карт, ECharts, WebSocket соединений. Эти объекты имеют свой внутренний стейт, и попытка Vue обернуть их в Proxy часто приводит к багам (библиотека перестает узнавать свои же объекты) и жутким тормозам.

#### ⚠️ Критический нюанс / Опасность
**"Призрачные" обновления (Phantom Updates)**. Это самая частая боль при работе с `shallowRef`.
Представь, что ты мутируешь вложенное свойство: `myShallowRef.value.name = 'Ivan'`. Как мы знаем, Vue не обновит DOM. **НО!** Если в этот же момент *любая другая* реактивная переменная в этом компоненте изменится и вызовет ре-рендер компонента, Vue возьмет актуальное состояние `myShallowRef` (где имя уже 'Ivan') и отрисует его. 
Получается плавающий баг: интерфейс обновляется не тогда, когда изменились данные, а когда "повезет" из-за соседних стейтов.

*Решение*: Если используешь `shallowRef`, строго соблюдай иммутабельность (как в React) или используй утилиту `triggerRef(myShallowRef)`, чтобы принудительно сказать Vue: "Я там внутри что-то поменял, обнови DOM".

#### 💻 Пример кода

```html
<script setup lang="ts">
import { shallowRef, triggerRef } from 'vue'

// Допустим, это тяжелая структура данных с бэкенда
interface HeavyData {
  id: string
  metrics: Record<string, number>
  // ... еще 50 полей
}

// Используем shallowRef вместо ref
const chartData = shallowRef<HeavyData[]>([])

const fetchMetrics = async () => {
  const response = await api.getMetrics()
  // Реактивность сработает, так как мы полностью перезаписываем .value
  // Но Vue не будет обходить массив и оборачивать каждый объект в Proxy!
  chartData.value = response.data
}

const updateSpecificMetric = (id: string, newValue: number) => {
  const item = chartData.value.find(d => d.id === id)
  if (item) {
    // МУТАЦИЯ! Vue этого не заметит, так как ref поверхностный
    item.metrics.clicks = newValue 
    
    // Принудительно дергаем систему реактивности, чтобы обновить UI
    // Это гораздо дешевле, чем делать весь массив глубоко реактивным
    triggerRef(chartData) 
  }
}
</script>

<template>
  <div>
    <button @click="fetchMetrics">Load Data</button>
    <!-- Рендер большого списка -->
    <div v-for="data in chartData" :key="data.id">
      {{ data.id }}: {{ data.metrics.clicks }}
    </div>
  </div>
</template>
```
