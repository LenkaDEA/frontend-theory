Эти две директивы работают на уровне шаблона (template) и служат для оптимизации процесса рендеринга (Virtual DOM).

#### ⚙️ Механика «под капотом»
Во Vue 3 шаблоны компилируются в render-функции. Компилятор Vue очень умный и старается сделать максимум работы на этапе сборки (AOT-компиляция).

*   **`v-once`**: Когда компилятор видит эту директиву, он генерирует VNode (виртуальный узел) для этого элемента и его потомков только *один раз* при первичном монтировании (mount). Результат кэшируется. При последующих обновлениях компонента (re-renders), алгоритм сверки (patching) видит флаг кэша и **полностью пропускает** это поддерево. Vue даже не будет создавать трекеры реактивности (effects) для переменных, используемых внутри этого блока.
*   **`v-memo="[deps]"`** (появился во Vue 3.2): Это динамический аналог `v-once`. Компилятор генерирует код, который сохраняет массив зависимостей `deps` и кэшированный VNode. При ре-рендере Vue делает поверхностное сравнение (shallow compare, аналог `Object.is`) старого и нового массива зависимостей. Если зависимости не изменились, Vue берет VNode из кэша и пропускает фазу patch для всего поддерева.

#### ⚛️ Аналог из React (для понимания)
*   **`v-once`**: В React нет прямого синтаксического аналога. Ближе всего по смыслу — это вынос статического JSX за пределы компонента (чтобы он не пересоздавался) или использование `React.memo` с функцией `areEqual`, которая всегда возвращает `true` `() => true`.
*   **`v-memo`**: Это очень похоже на **`useMemo`** (когда мы оборачиваем кусок JSX в `useMemo`, чтобы не рендерить его заново) или на **`React.memo`** для дочерних компонентов.
*   **Концептуальная разница**: В React, чтобы избежать лишнего рендера списка, тебе *обязательно* нужно выносить элемент списка в отдельный компонент и оборачивать его в `React.memo`. Во Vue благодаря `v-memo` ты можешь мемоизировать тяжелый кусок DOM прямо внутри текущего шаблона, не плодя микро-компоненты.

#### 🎯 Идеальный Use Case
*   **`v-once`**: Огромный блок статического контента (например, сложная SVG-иллюстрация на 1000 нод, длинное пользовательское соглашение), который находится внутри компонента, часто меняющего свое состояние (например, рядом тикает таймер или идет анимация по скроллу).
*   **`v-memo`**: Рендеринг больших списков (1000+ элементов) через `v-for`, где состояние меняется только у одного элемента. Например, список элементов, где мы можем выбрать один (active). Без `v-memo` при смене `selectedId` Vue будет пересоздавать VNodes для всех 1000 элементов (хотя patch алгоритм обновит DOM только для двух). С `v-memo="[item.id === selectedId]"` Vue перерисует ровно два элемента: тот, с которого сняли выделение, и тот, на который кликнули.

#### ⚠️ Критический нюанс / Опасность
1.  **Преждевременная оптимизация**: Virtual DOM во Vue 3 невероятно быстрый благодаря механизму Patch Flags (компилятор помечает, какие именно атрибуты могут меняться, и Vue проверяет только их). Использование `v-memo` на простых `<div>` создаст больше накладных расходов на проверку массива зависимостей, чем сэкономит времени на рендере.
2.  **Мутации объектов в `v-memo`**: Массив зависимостей проверяется поверхностно (shallow). Если ты передашь туда сложный объект `v-memo="[user]"` и мутируешь его свойство `user.name = 'Ivan'`, мемоизация не сбросится (ссылка на объект осталась прежней), и интерфейс не обновится! Это классический выстрел в ногу, очень похожий на забытую зависимость в `useEffect` или мутацию стейта в React.

#### 💻 Пример кода

```vue
<script setup lang="ts">
import { ref } from 'vue'

interface User {
  id: number
  name: string
  role: string
}

const users = ref<User[]>(Array.from({ length: 1000 }, (_, i) => ({
  id: i,
  name: `User ${i}`,
  role: 'guest'
})))

const selectedUserId = ref<number | null>(null)

const selectUser = (id: number) => {
  selectedUserId.value = id
}
</script>

<template>
  <div>
    <!-- v-once: Этот тяжелый SVG отрендерится один раз и навсегда -->
    <div v-once class="heavy-decoration">
      <svg>...</svg> 
      <p>Статический текст, который никогда не изменится</p>
    </div>

    <!-- v-memo: При клике перерендерится только старый и новый выбранный элемент -->
    <ul class="user-list">
      <li 
        v-for="user in users" 
        :key="user.id"
        v-memo="[user.id === selectedUserId]"
        :class="{ active: user.id === selectedUserId }"
        @click="selectUser(user.id)"
      >
        <div class="avatar">...</div>
        <div class="info">
          <h3>{{ user.name }}</h3>
          <span>{{ user.role }}</span>
        </div>
      </li>
    </ul>
  </div>
</template>
```
