Эта утилита ставит на объект своеобразную «прививку от реактивности».

#### ⚙️ Механика «под капотом»
Когда ты передаешь объект в `markRaw(obj)`, Vue мутирует этот оригинальный объект, добавляя в него скрытое, неперечислимое свойство `__v_skip: true`. 

В дальнейшем, когда система реактивности Vue (функции `reactive` или `ref`) рекурсивно обходит дерево объектов, чтобы обернуть их в `Proxy`, она натыкается на этот флаг. Увидев `__v_skip: true`, Vue говорит: «Ага, этот объект трогать нельзя» — и оставляет его как есть, сохраняя оригинальную ссылку и не создавая для него трекеров зависимостей.

#### ⚛️ Аналог из React (для понимания)
*   В React нет прямого аналога, потому что React по умолчанию не делает данные реактивными глубоко. 
*   Ближе всего по смыслу — это использование **`useRef`** для хранения инстансов библиотек внутри компонента, чтобы они не участвовали в цикле рендеринга.
*   Если представить, что `useState` в React автоматически делал бы глубокий клон и вешал бы геттеры/сеттеры на все вложенные свойства (как делает Vue), то `markRaw` был бы способом сказать: «Вот этот конкретный вложенный объект внутри стейта не трогай».

#### 🎯 Идеальный Use Case
1.  **Динамические компоненты (`<component :is="...">`)**: Это самый частый и важный кейс во Vue 3. Компоненты во Vue — это просто большие объекты с функциями рендера, хуками и т.д. Если ты положишь компонент в `ref` или `reactive` (например, для реализации системы табов), Vue попытается сделать весь объект компонента реактивным! Это вызывает сильные тормоза и предупреждения в консоли. Обернув компонент в `markRaw`, ты защищаешь его от Proxy.
2.  **Инстансы тяжелых классов внутри общего стейта**: У тебя есть `reactive` стейт приложения, и одно из его полей — это инстанс `WebSocket`, `MapboxGL.Map` или `new AudioContext()`. Этим объектам категорически нельзя становиться Proxy, иначе их внутренние механизмы сломаются (потеряется контекст `this` внутри их приватных методов).

#### ⚠️ Критический нюанс / Опасность
1.  **Мутация оригинала**: `markRaw` мутирует *исходный* объект. Если ты сделаешь `const rawObj = markRaw(myObj)`, то `myObj` тоже получит флаг `__v_skip`.
2.  **Поздно пить боржоми**: `markRaw` **не работает** на объектах, которые *уже* стали реактивными. Если ты сделаешь `markRaw(reactive(obj))`, это ничего не даст — объект уже является Proxy. `markRaw` нужно применять к сырому объекту *до* того, как он попадет в реактивную систему.
3.  **Вложенность в сырых объектах**: Если внутри объекта, обернутого в `markRaw`, лежит другой объект, и ты вытащишь этот вложенный объект и положишь его в `reactive` — он станет реактивным! `markRaw` защищает сам объект, но не делает глубокую защиту для его свойств, если их извлечь.

#### 💻 Пример кода

Разберем классический пример с динамическими табами, где `markRaw` спасает от падения производительности.

```html
<script setup lang="ts">
import { ref, markRaw, Component } from 'vue'
import DashboardTab from './DashboardTab.vue'
import SettingsTab from './SettingsTab.vue'
import ProfileTab from './ProfileTab.vue'

// Описываем интерфейс для таба
interface Tab {
  id: string
  name: string
  // Тип Component из Vue
  component: Component 
}

// Если не использовать markRaw, Vue попытается рекурсивно 
// обойти весь код компонентов и сделать его реактивным.
// markRaw говорит: "Это просто статический объект компонента, не лезь в него".
const tabs = ref<Tab[]>([
  { id: 'dash', name: 'Dashboard', component: markRaw(DashboardTab) },
  { id: 'set', name: 'Settings', component: markRaw(SettingsTab) },
  { id: 'prof', name: 'Profile', component: markRaw(ProfileTab) }
])

const currentTab = ref<Tab>(tabs.value[0])
</script>

<template>
  <div class="tabs-container">
    <div class="tab-headers">
      <button 
        v-for="tab in tabs" 
        :key="tab.id"
        @click="currentTab = tab"
      >
        {{ tab.name }}
      </button>
    </div>

    <!-- Динамический рендер компонента -->
    <div class="tab-content">
      <component :is="currentTab.component" />
    </div>
  </div>
</template>
```
