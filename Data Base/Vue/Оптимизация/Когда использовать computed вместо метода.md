### `computed` vs Обычный метод (function) в `<template>`

#### ⚙️ Механика «под капотом»
*   **`computed`**: Когда ты создаешь `computed`, Vue создает специальный объект-эффект (Reactive Effect). При первом обращении к `computed`, Vue выполняет функцию, запоминает результат (кэширует) и **автоматически подписывается** на все реактивные переменные (Proxy), которые были прочитаны внутри этой функции.
    *   Пока зависимости не изменились, `computed` при каждом обращении мгновенно отдает закэшированный результат.
    *   Если зависимость меняется, Vue помечает `computed` флагом `dirty: true` (грязный). Пересчет произойдет *лениво* — только когда кто-то (например, шаблон) снова запросит значение этого `computed`.
*   **Метод (function)**: Если ты вызываешь функцию прямо в шаблоне `{{ calculateSomething() }}`, она не имеет механизма кэширования. **При любом ре-рендере компонента** (даже если изменилась совершенно другая, не связанная с функцией реактивная переменная), алгоритм Virtual DOM заново вызовет эту функцию, чтобы получить актуальное значение для отрисовки.

#### ⚛️ Аналог из React (для понимания)
*   **`computed`** — это **`useMemo`** на максималках. Концептуально это одно и то же: мемоизация вычислений. Но во Vue тебе *не нужно писать массив зависимостей*. Vue через Proxy сам знает, какие переменные использовались внутри `computed`, и обновит кэш только при их изменении. Это исключает баги React, когда ты забыл добавить переменную в массив зависимостей `useMemo`.
*   **Метод в шаблоне** — это просто вызов обычной функции внутри тела функционального компонента React. При каждом вызове компонента (ре-рендере) функция отрабатывает заново.

#### 🎯 Идеальный Use Case
*   **Используй `computed` (в 95% случаев):** Для любых производных данных. Фильтрация списков, сортировка, сложные математические вычисления, сборка строки из нескольких реактивных переменных.
*   **Используй методы (function):**
    1.  **Обработчики событий** (`@click="submitForm"`).
    2.  **Когда нужно передать аргумент**. `computed` по своей природе — это геттер, он не принимает аргументы (ты обращаешься к нему как `myComputed.value`). Если тебе нужно отформатировать дату для каждого элемента в `v-for`, тебе придется использовать метод: `{{ formatDate(item.date) }}`.

#### ⚠️ Критический нюанс / Опасность
1.  **Сайд-эффекты в `computed`**: Это смертный грех во Vue. `computed` должен быть **чистой функцией** (Pure Function). Внутри `computed` нельзя делать асинхронные запросы (`fetch`), мутировать DOM или изменять другие реактивные переменные. Если нужен сайд-эффект на изменение данных — используй `watch`.
2.  **Убийство производительности методами**: Если у тебя есть тяжелый метод `{{ getHeavyCalculatedValue() }}` в шаблоне, и в этом же компоненте есть инпут, в который пользователь быстро печатает текст (связанный через `v-model` с другой переменной). При каждом нажатии клавиши компонент будет ре-рендериться, и тяжелый метод будет выполняться снова и снова, блокируя Main Thread и вызывая лаги при вводе.
3.  **Антипаттерн "computed возвращает функцию"**: Иногда разработчики делают так: `const format = computed(() => (id) => id + 1)`. Это работает, но **кэширование ломается**. Vue закэширует саму *функцию*, но вызов этой функции в шаблоне `{{ format(1) }}` будет происходить при каждом ре-рендере.

#### 💻 Пример кода

В этом примере мы наглядно увидим, почему метод — это плохо для вычислений, если в компоненте есть независимый стейт (счетчик).

```html
<script setup lang="ts">
import { ref, computed } from 'vue'

const users = ref([
  { id: 1, name: 'Alice', active: true },
  { id: 2, name: 'Bob', active: false },
  { id: 3, name: 'Charlie', active: true },
])

// Независимый стейт, который часто меняется
const counter = ref(0)

// ✅ ПРАВИЛЬНО: computed
// Выполнится один раз. При изменении counter пересчета НЕ будет.
const activeUsers = computed(() => {
  console.log('Вызван computed: activeUsers') // Увидишь в консоли только 1 раз
  return users.value.filter(u => u.active)
})

// ❌ НЕПРАВИЛЬНО для вычислений: метод
// Будет выполняться при КАЖДОМ клике на кнопку "Increment", 
// хотя список пользователей не менялся!
const getActiveUsersMethod = () => {
  console.log('Вызван метод: getActiveUsersMethod') // Будет спамить в консоль при каждом клике
  return users.value.filter(u => u.active)
}

// ✅ ПРАВИЛЬНО для методов: форматирование с аргументом
// (Но если форматирование очень тяжелое, лучше вынести логику на уровень подготовки данных)
const formatName = (name: string) => {
  return name.toUpperCase()
}
</script>

<template>
  <div>
    <!-- Изменение этого счетчика вызывает ре-рендер всего компонента -->
    <button @click="counter++">Increment: {{ counter }}</button>

    <div class="lists">
      <!-- Берет из кэша, работает мгновенно -->
      <ul>
        <li v-for="user in activeUsers" :key="user.id">
          {{ formatName(user.name) }}
        </li>
      </ul>

      <!-- Заново фильтрует массив при каждом клике на счетчик -->
      <ul>
        <li v-for="user in getActiveUsersMethod()" :key="user.id">
          {{ user.name }}
        </li>
      </ul>
    </div>
  </div>
</template>
```
