#### 📝 Определение
Валидация форм — это процесс проверки данных, введенных пользователем, на соответствие определенным правилам (обязательность, формат email, минимальная длина и т.д.) перед их отправкой на сервер.

Во Vue, в отличие от Angular (где есть встроенные реактивные формы), нет встроенного сложного механизма валидации "из коробки". Vue предоставляет реактивность, а логику валидации разработчики либо пишут сами, либо используют специализированные библиотеки.

#### ⚖️ Сравнение с React
Подходы к валидации в React и Vue **очень похожи**, так как обе библиотеки фокусируются на UI, оставляя работу с формами сторонним решениям.

*   **React:** Чаще всего используют связку **React Hook Form** (управление состоянием) + **Yup / Zod** (схемы валидации) или Formik.
*   **Vue:** Чаще всего используют **VeeValidate** (управление состоянием и UI) + **Yup / Zod** (схемы валидации) или **Vuelidate** (валидация на основе моделей).

Если ты знаешь React Hook Form + Zod, то VeeValidate + Zod покажется тебе братом-близнецом.

#### 🛠 Как использовать (Два основных подхода)

На собеседовании важно показать, что ты знаешь оба пути: ручную валидацию (для простых форм) и использование библиотек (для сложных).

##### Подход 1: Ручная валидация (без библиотек)
Используется для простых форм (1-2 поля), где тащить тяжелую библиотеку нет смысла. Мы просто используем `ref` и `computed`.

```html
<script setup>
import { ref, computed } from 'vue'

const email = ref('')
const isSubmitted = ref(false)

// Вычисляемое свойство для ошибки
const emailError = computed(() => {
  if (!isSubmitted.value) return '' // Не показываем ошибку до попытки отправки
  if (!email.value) return 'Email обязателен'
  if (!email.value.includes('@')) return 'Неверный формат email'
  return ''
})

const submitForm = () => {
  isSubmitted.value = true
  if (!emailError.value) {
    console.log('Форма отправлена!', email.value)
  }
}
</script>

<template>
  <form @submit.prevent="submitForm">
    <div>
      <input v-model="email" type="text" placeholder="Введите email" />
      <span v-if="emailError" style="color: red">{{ emailError }}</span>
    </div>
    <button type="submit">Отправить</button>
  </form>
</template>
```

##### Подход 2: Использование VeeValidate + Zod (Стандарт индустрии)
Это самый современный и популярный стек для Vue 3 (Composition API). Очень похоже на React Hook Form.

*Нужно установить: `npm install vee-validate zod @vee-validate/zod`*

```html
<script setup>
import { useForm, useField } from 'vee-validate'
import { toTypedSchema } from '@vee-validate/zod'
import * as z from 'zod'

// 1. Описываем схему валидации (как в React)
const validationSchema = toTypedSchema(
  z.object({
    email: z.string().min(1, 'Email обязателен').email('Неверный формат'),
    password: z.string().min(6, 'Минимум 6 символов')
  })
)

// 2. Инициализируем форму
const { handleSubmit, errors } = useForm({
  validationSchema,
})

// 3. Регистрируем поля (связываем их с формой)
// value - это реактивная ссылка для v-model, errorMessage - текст ошибки
const { value: email } = useField('email')
const { value: password } = useField('password')

// 4. Обработчик успешной отправки
const onSubmit = handleSubmit((values) => {
  console.log('Отправляем на сервер:', values)
})
</script>

<template>
  <form @submit="onSubmit">
    <div>
      <!-- Используем v-model с переменной из useField -->
      <input v-model="email" type="text" placeholder="Email" />
      <!-- Показываем ошибку из объекта errors -->
      <span v-if="errors.email" style="color: red">{{ errors.email }}</span>
    </div>

    <div>
      <input v-model="password" type="password" placeholder="Пароль" />
      <span v-if="errors.password" style="color: red">{{ errors.password }}</span>
    </div>

    <button type="submit">Войти</button>
  </form>
</template>
```

#### ⚠️ Особенности и ловушки (Pitfalls) для собеседования

1. **Момент срабатывания валидации (Validation triggers):**
   Частый вопрос: "Когда нужно показывать ошибку?".
   *Плохо:* Показывать ошибку сразу, как только пользователь начал печатать первый символ (это бесит).
   *Хорошо:* Показывать ошибку после потери фокуса (`@blur`) ИЛИ после первой неудачной попытки отправки формы (`submit`). В ручном подходе мы делали это через флаг `isSubmitted`. Библиотеки вроде VeeValidate умеют настраивать это поведение (например, режим `eager` или `lazy`).

2. **Связка кастомных компонентов и библиотек валидации:**
   Если ты используешь VeeValidate и свой кастомный `CustomCheckbox.vue` (из предыдущих тем), тебе нужно убедиться, что кастомный компонент правильно работает с `v-model`. Функция `useField('fieldName')` из VeeValidate возвращает реактивное `value`, которое ты просто прокидываешь в свой компонент: `<CustomCheckbox v-model="agreedValue" />`. Если твой компонент написан правильно (через `defineModel` или классический `modelValue`), валидация заработает магическим образом.

3. **Vuelidate vs VeeValidate:**
   На собеседовании могут спросить, какие библиотеки ты знаешь.
   *   **Vuelidate:** Валидирует *данные* (модели). Ты описываешь правила для своих `ref` или `reactive` объектов. Меньше привязан к шаблону.
   *   **VeeValidate:** Валидирует *поля формы* (UI). Больше похож на React Hook Form. В Vue 3 с Composition API VeeValidate стал де-факто стандартом, особенно в связке с Zod или Yup.
