#### 📝 Определение
`defineModel` — это новый макрос (появился в Vue 3.4), который кардинально упрощает создание компонентов, работающих с `v-model`. 

Он возвращает **реактивную ссылку (ref)**. Когда ты читаешь эту ссылку, ты получаешь значение из родительского компонента. Когда ты записываешь в эту ссылку новое значение, Vue *автоматически* отправляет событие родителю, чтобы обновить данные там.

#### ⚖️ Сравнение с React
В React такого нет вообще. Тебе всегда придется вручную принимать `value` и вызывать `onChange`. 
`defineModel` во Vue делает так, что внутри дочернего компонента ты работаешь с пропсом от родителя так, **как будто это обычная локальная переменная состояния** (как `useState`), но при ее изменении автоматически обновляется состояние в родителе!

#### 🛠 Как использовать (Код)

Давай перепишем наш `CustomCheckbox.vue` из предыдущей задачи, используя `defineModel`.

**Было (До Vue 3.4):**
```html
<script setup>
defineProps(['modelValue', 'label'])
defineEmits(['update:modelValue'])
</script>

<template>
  <input 
    type="checkbox" 
    :checked="modelValue" 
    @change="$emit('update:modelValue', $event.target.checked)"
  />
</template>
```

**Стало (С `defineModel`):**
```html
<script setup>
// 1. Обычные пропсы (label) объявляем как обычно
defineProps(['label'])

// 2. Магия! Создаем реактивную ссылку, связанную с v-model родителя
const isChecked = defineModel() 
</script>

<template>
  <label>
    <!-- 3. Просто используем v-model прямо на нативном инпуте! -->
    <input 
      type="checkbox" 
      v-model="isChecked"
    />
    <span>{{ label }}</span>
  </label>
</template>
```

**Что здесь произошло?**
1. `const isChecked = defineModel()` автоматически под капотом объявил пропс `modelValue` и событие `update:modelValue`.
2. В шаблоне мы просто повесили `v-model="isChecked"` на нативный `<input>`. 
3. Когда пользователь кликает на чекбокс, нативный инпут меняет значение `isChecked`. А так как `isChecked` создан через `defineModel`, Vue перехватывает это изменение и *сам* отправляет `$emit('update:modelValue', newValue)` родителю.

#### ⚠️ Особенности и ловушки (Pitfalls) для собеседования

1. **`defineModel` — это макрос компилятора:**
   Как и `defineProps`, его не нужно импортировать из `vue`. Он доступен глобально внутри `<script setup>`.

2. **Именованные модели:**
   Если в родителе ты используешь именованный v-model: `<CustomForm v-model:title="myTitle" />`, то в дочернем компоненте ты передаешь имя в макрос:
   `const title = defineModel('title')`

3. **Опции (типы, дефолтные значения):**
   Ты можешь передать настройки вторым аргументом (или первым, если модель не именованная):
   ```javascript
   const count = defineModel({ type: Number, default: 0 })
   const title = defineModel('title', { type: String, required: true })
   ```

4. **Ловушка с мутацией объектов (Важно!):**
   Если через `defineModel` передается объект или массив, и ты мутируешь его свойства напрямую (например, `userModel.value.name = 'Иван'`), это **не вызовет** событие `update:modelValue` в родителе. Родительский объект мутирует (потому что в JS объекты передаются по ссылке), но Vue может не отследить это изменение корректно в контексте `v-model`. 
   *Решение:* Если нужно обновить объект целиком, присваивай новое значение: `userModel.value = { ...userModel.value, name: 'Иван' }`.
