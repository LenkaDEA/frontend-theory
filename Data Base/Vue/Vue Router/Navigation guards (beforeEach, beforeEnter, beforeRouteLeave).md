**Navigation Guards (Навигационные хуки / Защитники маршрутов)** — это мощнейшая фича Vue Router. На собеседованиях эту тему спрашивают почти всегда, особенно когда речь заходит про авторизацию (как запретить доступ неавторизованному пользователю).

В React Router v6 нет прямого встроенного аналога, который работал бы точно так же из коробки. В React мы обычно делаем компоненты-обертки вроде `<ProtectedRoute>`, которые внутри себя используют `useEffect` и `useNavigate` для редиректа, или используем `loader` (если работаем с Data Routers). Во Vue же перехват навигации встроен прямо в роутер.

Vue предоставляет три уровня хуков:
1. **Глобальные** (срабатывают при любом переходе).
2. **Для конкретного маршрута** (срабатывают только при заходе на определенный роут).
3. **Внутри компонента** (находятся в `setup` или опциях самого Vue-компонента).

### 1. Глобальный хук: `router.beforeEach`

Это самый популярный хук. Он вызывается **перед каждым** изменением маршрута в приложении. Именно здесь обычно пишут логику проверки авторизации.

```javascript
// router/index.js
import { createRouter, createWebHistory } from 'vue-router'
// ... инициализация routes и router

router.beforeEach((to, from, next) => {
  // to - объект маршрута, КУДА мы идем (куда кликнули)
  // from - объект маршрута, ОТКУДА мы идем
  
  const isAuthenticated = checkAuth() // Твоя функция проверки токена

  if (to.name !== 'Login' && !isAuthenticated) {
    // Если идем не на страницу логина и не авторизованы -> редирект
    return { name: 'Login' } 
    // В старых версиях Vue (v3) часто использовали next({ name: 'Login' })
    // В Vue Router 4 (для Vue 3) предпочтительно просто возвращать объект
  }
  
  // Если вернем true или undefined, навигация продолжится
  return true 
})
```

**Важный нюанс для собеса про аргумент `next`:**
Раньше (во Vue 2 / Vue Router 3) было обязательно вызывать функцию `next()`, чтобы переход состоялся. В новой версии (Vue Router 4) от `next` рекомендуют отказываться: вместо вызова `next('/login')` нужно просто делать `return '/login'`, а чтобы продолжить путь — ничего не возвращать или вернуть `true`. Это избавляет от частой ошибки, когда `next()` случайно вызывали дважды в одном хуке.

### 2. Хук на уровне маршрута: `beforeEnter`

Иногда нам не нужно проверять логику глобально для всего приложения. Мы хотим защитить только один конкретный маршрут (или ветку маршрутов). Для этого мы определяем `beforeEnter` прямо в массиве `routes`.

```javascript
const routes = [
  {
    path: '/admin',
    component: AdminDashboard,
    // Сработает ТОЛЬКО при переходе на /admin
    beforeEnter: (to, from) => {
      const user = getUser()
      if (user.role !== 'admin') {
        return { path: '/403-forbidden' } // Отказываем в доступе
      }
    }
  }
]
```
Этот хук удобен, когда логика касается только одной конкретной страницы (например, проверка прав админа).

### 3. Внутрикомпонентные хуки: `onBeforeRouteLeave` и `onBeforeRouteUpdate`

Эти хуки используются прямо внутри `script setup` компонента.

**`onBeforeRouteLeave` (Перехват ухода со страницы)**
Классический юзкейс: пользователь заполнял длинную форму, случайно нажал ссылку или кнопку "Назад", и мы хотим спросить его: "Вы уверены? Несохраненные данные будут потеряны!".

```html
<script setup>
import { onBeforeRouteLeave } from 'vue-router'
import { ref } from 'vue'

const hasUnsavedChanges = ref(true)

onBeforeRouteLeave((to, from) => {
  if (hasUnsavedChanges.value) {
    const answer = window.confirm('У вас есть несохраненные изменения. Вы точно хотите уйти?')
    // Если пользователь нажал "Отмена", возвращаем false, чтобы отменить навигацию
    if (!answer) return false
  }
})
</script>
```

**`onBeforeRouteUpdate`**
Мы уже упоминали его в теме про [динамические параметры](Динамические%20маршруты%20и%20параметры%20(id).md). Он срабатывает, когда компонент переиспользуется при изменении параметра в URL (например, переход с `/users/1` на `/users/2`).

```html
<script setup>
import { onBeforeRouteUpdate } from 'vue-router'

onBeforeRouteUpdate(async (to, from) => {
  // Загружаем данные нового пользователя, не покидая компонент
  userData.value = await fetchUser(to.params.id)
})
</script>
```

### 🔥 Секретный вопрос на собесе: Порядок выполнения (Resolution Flow)

На синьорских собесах любят спрашивать: "В каком порядке сработают хуки, если у нас есть глобальный `beforeEach`, роутовый `beforeEnter` и внутрикомпонентный `beforeRouteLeave` (на старой странице)?"

Правильный ответ (упрощенно):
1. Сначала срабатывает хук **ухода** со старой страницы: `onBeforeRouteLeave` (мы должны убедиться, что вообще можем её покинуть).
2. Затем **глобальный** хук: `router.beforeEach` (проверяем глобальные права, например, авторизацию).
3. Затем хук **конкретного маршрута**: `beforeEnter` (проверяем права конкретной страницы).
4. Затем хук **внутри компонента, куда мы идем**: (если это Options API, то `beforeRouteEnter`, в setup он не нужен).
5. И напоследок **глобальный** хук завершения: `router.afterEach` (здесь уже нельзя отменить навигацию, обычно тут меняют title страницы или отправляют аналитику).

---

**Резюме для собеса по этой теме:**
1. Guards — это способ перехватить, отменить или перенаправить навигацию.
2. В Vue Router 4 лучше использовать `return` (true / false / объект маршрута) вместо вызова `next()`.
3. Три уровня защиты: глобально (`beforeEach`), на уровне роута (`beforeEnter`), внутри компонента (`onBeforeRouteLeave`).
4. В React этого "из коробки" в таком виде нет, там используются `<ProtectedRoute>` или фичи новых Data Routers (v6.4+).
