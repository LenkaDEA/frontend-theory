На собеседованиях этот вопрос могут задать так: *"Как отвязать компонент страницы от роутера?"* или *"Как сделать так, чтобы компонент не знал, что его открыли через URL?"*.

### Передача пропсов через маршруты

#### Проблема (Зачем это нужно)

Вспомним тему про динамические параметры (`:id`). Обычно мы получаем `id` вот так:

```html
<!-- UserComponent.vue -->
<script setup>
import { useRoute } from 'vue-router'

const route = useRoute()
const userId = route.params.id // Компонент жестко привязан к роутеру!
</script>
```

**В чем минус такого подхода?**
Этот компонент `UserComponent` теперь **невозможно** использовать где-то еще, кроме как через роутер. 
Представь, что тебе понадобилось отрендерить этот же профиль внутри модального окна на другой странице. Роутер там не задействован, параметра `route.params.id` нет, и компонент сломается. 

В React ты бы тоже столкнулась с этим: если внутри компонента вызван хук `useParams()`, компонент зависит от контекста роутера.

#### Решение во Vue: Отправка параметров как Props

Vue Router позволяет сказать: *"Эй, роутер! Возьми параметры из URL (`route.params`) и передай их в компонент как обычные Vue-пропсы!"*

**Шаг 1: Включаем фичу в конфигурации маршрута**
Мы просто добавляем свойство `props: true` в объект маршрута:

```javascript
const routes = [
  { 
    path: '/user/:id', 
    component: UserComponent,
    props: true // Включаем магию!
  }
]
```

**Шаг 2: Принимаем данные в компоненте**
Теперь мы полностью убираем импорт `useRoute` из компонента. Мы принимаем `id` через стандартный механизм `defineProps` (как будто нам его передал родительский компонент).

```html
<!-- UserComponent.vue -->
<script setup>
// Больше никакого useRoute!

const props = defineProps({
  id: String // Получаем id прямо из URL как пропс
})

console.log(props.id) 
</script>
```

#### Почему это круто? (Ответ для собеседования)
1. **Переиспользуемость:** Теперь `UserComponent` ничего не знает про Vue Router. Его можно использовать и как отдельную страницу (роутер сам передаст `id`), и вставить в любое другое место приложения (передав `<UserComponent id="123" />` руками).
2. **Тестируемость:** Тестировать компонент, который принимает пропсы, в 10 раз проще, чем мокать объект глобального роутера в тестах (Jest/Vitest).

#### Продвинутые способы передачи пропсов (для синьорских вопросов)

Свойство `props` в роутере может быть не только `true/false`, но и объектом или даже функцией!

**1. Статические пропсы (Объект)**
Если мы хотим передать компоненту какие-то захардкоженные данные в зависимости от маршрута:

```javascript
const routes = [
  { 
    path: '/promotion', 
    component: PromotionPage,
    props: { showBanner: true, discount: 50 } 
  }
]
```
В компоненте мы получим пропсы `showBanner` и `discount`.

**2. Динамические пропсы (Функция)**
Это самый мощный вариант. Функция принимает текущий объект `route` и возвращает объект пропсов.
Используется, когда нужно как-то модифицировать данные из URL перед передачей (например, привести строку к числу) или взять данные из `query` (URL параметров после `?`).

```javascript
const routes = [
  { 
    path: '/search', 
    component: SearchResults,
    // Вытаскиваем 'q' из query (например /search?q=vue) и передаем как пропс 'queryText'
    props: (route) => ({ queryText: route.query.q }) 
  }
]
```

### Итоговое сравнение Vue Router vs React Router (Резюме для собеседования)

Если в конце собеседования тебя спросят: *"Ты перешла с React, какие у тебя впечатления от Vue Router?"*, вот отличный ответ, который покажет глубину понимания:

*"Мне показалось, что Vue Router более интегрирован в сам фреймворк. 
1. В React Router мы работаем с JSX-компонентами (передаем `<Component />`), а во Vue — с объектами конфигурации. 
2. Во Vue из коробки шикарно решена проблема переиспользуемости компонентов страниц благодаря передаче параметров через `props: true`. В React для этого пришлось бы писать функции-обертки (HOC) над хуком `useParams`.
3. Система Navigation Guards (`beforeEach`, `beforeEnter`) во Vue централизована и очень удобна для проверки авторизации. В React для этого обычно приходится писать кастомные компоненты типа `<ProtectedRoute>`.
4. Встроенная поддержка именованных маршрутов (`name`) во Vue делает навигацию более устойчивой к рефакторингу URL, в отличие от React, где чаще используются строковые пути."*
