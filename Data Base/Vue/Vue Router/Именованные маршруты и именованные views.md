#### Именованные маршруты (Named Routes)

Вместо того чтобы полагаться на URL-строку (которая может измениться), мы даем маршруту уникальное имя. Это делает код более устойчивым к рефакторингу.

**Как задать:**
Просто добавляем свойство `name` в объект конфигурации:

```javascript
const routes = [
  { 
    path: '/user/:id/profile', 
    name: 'UserProfile', // Даем уникальное имя
    component: UserProfile 
  }
]
```

**Как использовать:**

В ссылках (`router-link`):
```html
<!-- Плохо (хардкод URL) -->
<router-link :to="`/user/${user.id}/profile`">Профиль</router-link>

<!-- Хорошо (используем имя) -->
<router-link :to="{ name: 'UserProfile', params: { id: user.id } }">
  Профиль
</router-link>
```

В программной навигации:
```javascript
// Передаем объект с именем
router.push({ name: 'UserProfile', params: { id: user.id } })
```

**Сравнение с React:**
В React Router (v6) свойства `name` у маршрутов нет. Там навигация почти всегда строится вокруг строковых URL. Если пути сложные, в React обычно создают свои функции-хелперы (например, `generatePath(ROUTES.USER_PROFILE, { id })`), но во Vue это часть самого фреймворка.

#### Именованные views (Named Views)

Это более редкая, но мощная тема, которую обожают спрашивать на собеседованиях, чтобы проверить глубину знаний Vue Router.

**Сценарий:** 
Представь классическую страницу (например, дашборд или сложный профиль). У тебя есть боковая колонка (Sidebar) и основная область (Main). В зависимости от маршрута, ты хочешь менять **одновременно оба компонента** (и в сайдбаре, и в главной области), оставаясь на одном уровне вложенности.

С обычным `<router-view>` так не получится, потому что он рендерит только один компонент. Здесь на помощь приходят Named Views.

**Как это работает:**

1. **В разметке (Layout):** Мы создаем несколько тегов `<router-view>`, и даем им атрибут `name`. Тот, что без имени, по умолчанию называется `default`.

```html
<template>
  <div class="layout">
    <!-- Именованный view (например, для левой колонки) -->
    <aside>
      <router-view name="SidebarView"></router-view>
    </aside>

    <!-- Дефолтный view (для основного контента) -->
    <main>
      <router-view></router-view>
    </main>
  </div>
</template>
```

2. **В конфигурации роутера:** Вместо свойства `component` (в единственном числе), мы используем свойство `components` (во множественном) и передаем объект. Ключи этого объекта должны совпадать с именами `<router-view>`.

```javascript
const routes = [
  {
    path: '/settings',
    // Обрати внимание: componentS (с буквой "s" на конце)
    components: {
      default: SettingsMain,        // Отрендерится в <router-view> (без имени)
      SidebarView: SettingsSidebar  // Отрендерится в <router-view name="SidebarView">
    }
  },
  {
    path: '/profile',
    components: {
      default: ProfileMain,
      SidebarView: ProfileSidebar
    }
  }
]
```

**Что происходит?**
Когда пользователь переходит на `/settings`, роутер смотрит на `components`. Он видит компонент `SettingsSidebar` и кладет его в левую колонку (`name="SidebarView"`), а компонент `SettingsMain` кладет в правую.
При переходе на `/profile` обе колонки синхронно обновятся на новые компоненты.

**Сравнение с React:**
В React нет концепции "именованных Outlet". Там похожую задачу решают либо через сложный стейт, либо передавая компоненты через пропсы в Layout, либо используя контекст. Решение Vue здесь выглядит гораздо чище и декларативнее.

---

**Резюме для собеса по этой теме:**
1. **Named Routes (`name`)** спасают от сломанных ссылок при рефакторинге URL-путей. Передаем объект `{ name: '...', params: {...} }` вместо строк.
2. **Named Views (`name` у тега `<router-view>`)** нужны, когда на одном маршруте нужно отобразить **сразу несколько независимых компонентов** на одном уровне (например, сложный layout с динамическим сайдбаром и хедером).
3. В конфиге для Named Views используется свойство `components` (объект), а не `component`.
