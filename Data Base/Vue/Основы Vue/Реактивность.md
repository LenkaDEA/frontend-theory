### Концепция и Теория

**Какую задачу это решает?**
Реактивность Vue позволяет связывать переменные с DOM или другими вычислениями так, чтобы при изменении переменной UI обновлялся автоматически, причем максимально точечно.

**Как работает «под капотом»:**
В основе Vue 3 лежат нативные JavaScript **Proxy**. 
- Когда вы создаете реактивный объект, Vue оборачивает его в Proxy.
- В Proxy переопределены методы (traps) `get` и `set`.
- **Трекинг зависимостей (Track):** Когда компонент рендерится (или выполняется вычисляемое свойство/наблюдатель) и читает свойство через `get`, Vue «запоминает», что этот компонент зависит от данного свойства.
- **Уведомление (Trigger):** Когда вы меняете значение, срабатывает `set`. Proxy сообщает Vue: «Эй, я изменился, перерисуй всех, кто меня читал!».
- Поскольку Proxy работают только с объектами, для примитивов (числа, строки, булевые значения) Vue использует классы с геттерами и сеттерами — это и есть `ref`, который прячет примитив внутрь объекта под ключ `.value`.

### Синтаксис и База

Все эти функции импортируются из `vue` и используются внутри `<script setup>`.

- **`ref(value)`** — универсальный инструмент. Оборачивает значение (примитив или объект) в специальный объект с единственным свойством `.value`. 
	- *В скрипте:* всегда обращаемся через `.value`.
	- *В шаблоне (`<template>`):* Vue автоматически «распаковывает» его, писать `.value` не нужно.

- **`reactive(object)`** — делает реактивным целый объект (или массив) и все его вложенные свойства (глубокая реактивность). Работает только с объектами. Не требует `.value`.

- **`shallowRef(value)` / `shallowReactive(object)`** — «поверхностные» версии. Vue будет отслеживать только перезапись верхнего уровня (например, `myRef.value = newObj`), но не будет следить за изменениями внутри объекта (`myRef.value.deepProp = 1` не вызовет рендер). Используется для оптимизации производительности (например, при работе с большими массивами данных или сторонними библиотеками).

- **`toRefs(reactiveObj)`** — превращает каждое свойство реактивного объекта в отдельный `ref`. Жизненно необходимо, если вы хотите деструктурировать реактивный объект.

- **`toRef(reactiveObj, 'prop')`** — то же самое, но для одного конкретного свойства.

### Сравнение с React (Аналогии и Отличия)

* **`ref` и `reactive` — это `useState` (или `useReducer`).** Но если в React состояние **иммутабельно** (мы должны вызывать `setState(newValue)`), то во Vue оно **мутабельно**. Мы просто пишем `count.value++` или `user.name = 'John'`, и Vue сам всё понимает.

* **`useRef` vs `ref`:** В React `useRef` используется для хранения мутабельных данных, которые *не вызывают* рендер, или для доступа к DOM. Во Vue `ref` делает и то, и другое: он *вызывает* рендер при изменении, но также используется для доступа к DOM-элементам.

* **Рендеринг и виртуальный DOM:**
	* **В React:** При вызове `setState` React по умолчанию перерендеривает весь компонент и всех его детей (сверху вниз). Функция компонента выполняется целиком заново.

	* **Во Vue:** Блок `<script setup>` выполняется **только один раз** при создании компонента. Vue точно знает, какая именно переменная изменилась, и точечно обновляет только те части шаблона, которые от неё зависят. Это называется *fine-grained reactivity* (мелкогранулярная реактивность).

* **Никаких массивов зависимостей!** Вам не нужно писать `[a, b]` как в `useEffect` или `useCallback`. Vue сам через Proxy видит, какие переменные были прочитаны, и строит граф зависимостей под капотом.

### Важные нюансы (Где можно выстрелить в ногу)

1. **Потеря реактивности при деструктуризации:**
   Если сделать `const { name, age } = reactive({ name: 'Bob', age: 20 })`, то `name` и `age` станут обычными строками/числами и **навсегда потеряют связь** с Vue. 
   *Решение:* использовать `toRefs`: `const { name, age } = toRefs(myReactiveObj)`.

2. **Перезапись реактивного объекта целиком:**
   Если вы напишете `let state = reactive({ a: 1 }); state = { a: 2 };`, вы уничтожите Proxy. Новая переменная `state` больше не будет реактивной.
   *Решение:* Либо мутировать свойства внутри (`state.a = 2`), либо использовать `ref` и заменять его `.value` целиком (`stateRef.value = { a: 2 }`), либо использовать `Object.assign(state, { a: 2 })`.

3. **Забытый `.value`:**
   Самая частая ошибка новичков — пытаться сложить два `ref` в скрипте напрямую: `const sum = a + b` вместо `const sum = a.value + b.value`. (Зато в шаблоне `.value` писать нельзя!).

4. **Выбор между `ref` и `reactive`:**
   В сообществе Vue нет жесткого правила. Но современный тренд (и рекомендация создателя Vue Эвана Ю) — **использовать `ref` для всего**, даже для объектов. Это избавляет от проблем с деструктуризацией и перезаписью объектов, а наличие `.value` в коде явно сигнализирует: «Это реактивная переменная, а не обычная».

### Пример для заметок

```vue
<script setup>
import { ref, reactive, toRefs } from 'vue'

// Vue 3 - пример работы ref с объектом 
const user = ref({ name: 'Алиса', age: 25 });

// Мутируем напрямую:
user.value.name = 'Боб'; 

// --- 1. ref (для примитивов и объектов) ---
const count = ref(0) // В скрипте обязательно .value!

const increment = () => {
  count.value++ // Мутируем напрямую, в React было бы setCount(c => c + 1)
}

// --- 2. reactive (только для объектов) ---
const user = reactive({
  name: 'Иван',
  role: 'admin'
})

const changeName = () => {
  user.name = 'Петр' // Без .value, прямое изменение свойства
}

// --- 3. toRefs (спасение при деструктуризации) ---
const settings = reactive({
  theme: 'light',
  language: 'ru'
})

// Если бы мы сделали просто const { theme } = settings, тема бы не обновлялась
const { theme, language } = toRefs(settings)

const toggleTheme = () => {
  // Поскольку theme теперь это ref, мы обращаемся к нему через .value
  theme.value = theme.value === 'light' ? 'dark' : 'light'
  
  // Альтернативно можно менять и исходный объект:
  // settings.theme = settings.theme === 'light' ? 'dark' : 'light'
}
</script>

<template>
  <div class="reactivity-demo">
    <!-- Для ref в шаблоне .value подставляется автоматически -->
    <h3>Счетчик (ref): {{ count }}</h3>
    <button @click="increment">Увеличить счетчик</button>

    <!-- Работаем с реактивным объектом напрямую -->
    <h3>Пользователь (reactive)</h3>
    <p>Имя: {{ user.name }}, Роль: {{ user.role }}</p>
    <button @click="changeName">Сменить имя</button>

    <!-- Деструктурированные значения сохранили реактивность благодаря toRefs -->
    <h3>Деструктуризация (toRefs)</h3>
    <p>Настройки: тема {{ theme }}, язык {{ language }}</p>
    <button @click="toggleTheme">Сменить тему</button>
  </div>
</template>
```
