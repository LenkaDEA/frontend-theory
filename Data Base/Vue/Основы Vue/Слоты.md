### Концепция и Теория

**Какую задачу это решает?**
Слоты решают задачу композиции UI. Они позволяют родительскому компоненту «внедрять» свой HTML или другие компоненты в строго определенные места внутри дочернего компонента (например, передать текст кнопки, заголовок модального окна или шаблон для элемента списка).

**Как работает «под капотом»:**
На этапе компиляции Vue превращает слоты в функции, возвращающие VNodes (виртуальные DOM-узлы). 
Когда дочерний компонент рендерится, он вызывает эти функции-слоты, чтобы получить куски Virtual DOM от родителя и вставить их в нужное место. 
Именно поэтому во Vue слоты строго отделены от обычных пропсов (данных).

---

### Синтаксис и База

Во Vue есть 3 вида слотов, от простого к сложному:

1. **Default (Дефолтный слот):**
	- В ребенке пишем тег `<slot></slot>`.
	- Родитель просто пишет контент между открывающим и закрывающим тегом дочернего компонента.

2. **Named (Именованные слоты):**
	- В ребенке пишем `<slot name="header"></slot>`.
	- Родитель оборачивает контент в тег `<template v-slot:header>` (или использует шорткат `#header`).

3. **Scoped (Слоты с областью видимости):**
	- В ребенке мы передаем данные в слот, как пропсы: `<slot :item="user" name="userCard"></slot>`.
	- Родитель принимает эти данные в шаблоне: `<template #userCard="slotProps">` (обычно сразу деструктурируют: `<template #userCard="{ item }">`).

---

### Сравнение с React (Аналогии и Отличия)

Это самое важное место для понимания:

* **Дефолтный слот = `props.children`**
  В React вы пишете `<div>{props.children}</div>`. Во Vue вы пишете `<div><slot></slot></div>`.

* **Именованные слоты = Передача JSX в пропсы**
  В React: `<Modal header={<MyHeader />} footer={<MyFooter />} />`.
  Во Vue мы не передаем верстку в атрибуты! Мы используем тег `<template>` с директивой `#имя_слота`. Это делает разметку гораздо более читаемой, так как HTML не смешивается с JS-логикой.

* **Scoped слоты = Паттерн Render Props**
  В React, если ребенку нужно поделиться данными с родителем для рендера, мы передаем функцию: 
  `<List renderItem={(item) => <Card data={item} />} />`.
  Во Vue это решается через Scoped Slots. Ребенок выкидывает данные «наружу» через атрибуты тега `<slot>`, а родитель ловит их в переменные внутри `<template>`.

---
### Важные нюансы (Где можно выстрелить в ногу)

1. **Область видимости (Scope):**
   Золотое правило Vue: *Всё, что находится в шаблоне родителя, компилируется в области видимости родителя.* 
   Если вы передаете в дефолтный слот переменную `{{ title }}`, она будет искаться в `<script>` родителя, а не ребенка! Чтобы получить данные ребенка, **обязательно** нужны Scoped слоты.

2. **Резервный контент (Fallback):**
   Внутрь тега `<slot>` в дочернем компоненте можно положить дефолтную верстку: `<slot>Текст по умолчанию</slot>`. Она отрисуется только если родитель ничего не передал в этот слот.

3. **Шорткат `#`:**
   Никто не пишет `v-slot:header`. Все используют сокращение `#header`. Для дефолтного слота, если вы хотите получить из него данные (scoped), пишут `#default="{ data }"`.

4. **Доступ к слотам из JS:**
   Если вам в скрипте ребенка нужно проверить, передал ли родитель что-то в слот (например, чтобы скрыть обертку), можно использовать хелпер `useSlots()` из `vue`.

### Пример для заметок

Создадим мощный компонент `CustomList`, который использует все три вида слотов.

**CustomList.vue (Дочерний компонент - разработчик API)**
```vue
<template>
  <div class="custom-list">
    <!-- ИМЕНОВАННЫЙ СЛОТ: Заголовок списка. Если не передали - рендерим <h2> -->
    <header class="list-header">
      <slot name="header">
        <h2>Дефолтный заголовок</h2> <!-- Fallback контент -->
      </slot>
    </header>

    <ul>
      <li v-for="item in items" :key="item.id">
        <!-- 
          SCOPED СЛОТ: Передаем каждый item наверх родителю.
          Даем слоту имя "item", чтобы родитель мог стилизовать каждый элемент списка.
        -->
        <slot name="item" :itemData="item" :index="index">
          <!-- Fallback, если родитель не захотел кастомизировать элементы -->
          {{ item.name }}
        </slot>
      </li>
    </ul>

    <!-- ДЕФОЛТНЫЙ СЛОТ: Подвал списка -->
    <footer class="list-footer">
      <slot></slot> 
    </footer>
  </div>
</template>

<script setup>
defineProps({
  items: Array
})
</script>
```

**App.vue (Родительский компонент - потребитель)**
```vue
<template>
  <div class="app">
    <!-- Передаем данные (props) через :items -->
    <CustomList :items="users">
      
      <!-- 1. Заполняем именованный слот "header" -->
      <template #header>
        <h1>Список крутых разработчиков</h1>
      </template>

      <!-- 
        2. Заполняем scoped-слот "item".
        Деструктурируем то, что ребенок передал в :itemData и :index
        Это полный аналог Render Props из React!
      -->
      <template #item="{ itemData, index }">
        <div class="user-card">
          <span class="badge">#{{ index + 1 }}</span>
          <strong>{{ itemData.name }}</strong> ({{ itemData.role }})
          <!-- У нас есть доступ к стейту родителя (currentTheme)! -->
          <span v-if="currentTheme === 'dark'">🌙</span>
        </div>
      </template>

      <!-- 
        3. Заполняем дефолтный слот (всё, что без <template>, 
        или <template #default>) летит в <slot></slot> 
      -->
      <p>Всего пользователей: {{ users.length }}</p>
      
    </CustomList>
  </div>
</template>

<script setup>
import { ref } from 'vue'
import CustomList from './CustomList.vue'

const currentTheme = ref('dark')

const users = ref([
  { id: 1, name: 'Dan Abramov', role: 'React' },
  { id: 2, name: 'Evan You', role: 'Vue' }
])
</script>
```

**Итог для React-разработчика:**
Слоты во Vue — это способ разделить «чистые данные» (которые мы кидаем в `props`) и «куски UI» (которые мы кидаем в `slots`). Благодаря `<template #name>` разметка выглядит как обычный HTML-дерево, без необходимости писать странные конструкции вроде `renderItem={() => <div>...</div>}` внутри атрибутов.
