### Концепция и Теория

**Какую задачу это решает?**
Обеспечивает изоляцию компонентов и однонаправленный поток данных (one-way data flow). Родитель передает данные дочернему компоненту (Props), а дочерний сообщает родителю о том, что что-то произошло (Emits), чтобы родитель сам изменил данные.

**Как работает «под капотом»:**
- `defineProps` и `defineEmits` — это **макросы компилятора**. Это не обычные функции JS! 

- Когда Vue компилирует ваш файл `.vue`, он находит эти макросы и превращает их в настройки компонента. Поэтому их **не нужно импортировать** из `'vue'`.

- Vue оборачивает объект пропсов в `shallowReactive`. Это значит, что сам объект пропсов реактивный (когда родитель меняет пропс, дочерний компонент перерисовывается), но изменять свойства внутри дочернего компонента напрямую нельзя.

### Синтаксис и База

**Пропсы (`defineProps`):**
```javascript
// Внутри <script setup> (импорт не нужен)
const props = defineProps({
  title: String,
  count: {
    type: Number,
    default: 0,
    required: true
  }
})
```
*В шаблоне:* можно писать просто `{{ title }}`, Vue сам поймет, что это из пропсов.
*В скрипте:* обращаемся строго через объект `props.title`.

**Эмиты (`defineEmits`):**
```javascript
// Декларируем, какие события этот компонент может "выстреливать" наверх
const emit = defineEmits(['update', 'delete'])

// Использование в функции:
const handleDelete = () => {
  emit('delete', 123) // 123 — это payload (данные, которые полетят родителю)
}
```

### Сравнение с React (Аналогии и Отличия)

* **Коллбеки в пропсах vs Эмиты (Критическое отличие!)**
	* **В React:** Чтобы ребенок изменил состояние родителя, родитель передает функцию вниз: `<Child onUpdate={handleUpdate} />`. В Child мы получаем `props.onUpdate` и вызываем её.
	
	* **Во Vue:** Передавать функции в пропсы — **антипаттерн**. Вместо этого Child вызывает `emit('update', data)`. А родитель слушает это событие в шаблоне через `@` (сокращение от `v-on`): `<Child @update="handleUpdate" />`.

* **Иммутабельность пропсов:**
	* И в React, и во Vue пропсы доступны **только для чтения**. Если вы попытаетесь сделать `props.title = 'Новый'`, Vue выдаст предупреждение в консоли, а React крашнется или проигнорирует (если не strict mode).

* **Деструктуризация (Большая боль React-разработчиков):**
	* **В React:** Мы обожаем делать `const { title, count } = props;`.
	
	* **Во Vue:** Традиционно деструктуризация пропсов **убивала реактивность**. Если сделать `const { title } = defineProps(...)`, то `title` станет обычной строкой и не обновится, когда родитель поменяет значение. 
  *(Примечание: в самом свежем Vue 3.5 эту проблему наконец-то решили на уровне компилятора, и деструктуризация стала безопасной, но в большинстве старых проектов вам всё ещё придется писать `props.title` или использовать `toRefs(props)`).*

### Важные нюансы (Где можно выстрелить в ногу)

1. **Импорт макросов:** Не пишите `import { defineProps } from 'vue'`. Это вызовет ошибку линтера/компилятора. Они доступны глобально внутри `<script setup>`.

2. **Kebab-case vs CamelCase:**
   В JS (внутри скрипта) принято использовать camelCase (`myPropName`). 
   А вот в HTML-шаблоне Vue автоматически переводит их в kebab-case. 
   Передавать пропс надо так: `<Child my-prop-name="Текст" />`.
   Слушать эмит надо так: `<Child @my-custom-event="handler" />`.

3. **Мутация пропсов-объектов:**
   Хоть Vue и запрещает мутировать `props.title = 'a'`, он не сможет запретить вам изменить свойство внутри переданного объекта: `props.user.name = 'a'`. **Никогда так не делайте!** Это нарушает однонаправленный поток данных. Всегда эмитьте событие наверх, чтобы родитель сам поменял объект.

### Пример для заметок

В этом примере мы создадим Родителя и Ребенка, чтобы показать их взаимодействие.

**ChildComponent.vue (Дочерний компонент)**
```vue

<script setup>
// 1. Объявляем пропсы (без импорта!)
const props = defineProps({
  title: String,
  count: {
    type: Number,
    default: 0
  }
})

// 2. Объявляем эмиты
const emit = defineEmits(['update-count', 'reset'])

const increase = () => {
  // Нельзя делать props.count++! 
  // Мы сообщаем родителю: "Я хочу обновить счетчик, вот новое значение"
  emit('update-count', props.count + 1)
}
</script>

<template>
  <div class="card">
    <!-- В шаблоне к пропсам можно обращаться напрямую -->
    <h3>{{ title }}</h3>
    <p>Счетчик: {{ count }}</p>
    
    <!-- Можно вызывать emit прямо из шаблона через встроенный $emit -->
    <button @click="$emit('reset')">Сбросить (из шаблона)</button>
    
    <!-- А можно через функцию в скрипте -->
    <button @click="increase">Увеличить (из скрипта)</button>
  </div>
</template>
```

**ParentComponent.vue (Родительский компонент)**
```vue
<script setup>
import { ref } from 'vue'
import ChildComponent from './ChildComponent.vue'

// Состояние хранится у родителя
const mainCount = ref(0)

// Функция, которая обрабатывает эмит от ребенка
const handleUpdate = (newValue) => {
  //newValue — это тот самый (props.count + 1), который мы передали в emit
  mainCount.value = newValue 
}
</script>

<template>
  <div class="parent">
    <h2>Родительский стейт: {{ mainCount }}</h2>
    
    <!-- 
      :title и :count — это передача пропсов (эквивалент title={...} в React).
      @update-count и @reset — это подписка на эмиты (эквивалент onUpdateCount={...} в React).
    -->
    <ChildComponent 
      title="Мой первый пропс" 
      :count="mainCount"
      @update-count="handleUpdate"
      @reset="mainCount = 0"
    />
  </div>
</template>
```

**Резюме для React-разработчика:**
Забудьте про `props.onClick()`. Во Vue ребенок кричит в рупор: `emit('click')`, а родитель сам решает, слушать ему этот крик через `@click="..."` или нет.
