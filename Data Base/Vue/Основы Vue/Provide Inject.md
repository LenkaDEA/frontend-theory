### Концепция и Теория

**Какую задачу это решает?**
Эта пара функций решает проблему «проп-дриллинга» (prop drilling) — ситуации, когда вам нужно передать данные от компонента-прадедушки к компоненту-правнуку сквозь цепочку промежуточных компонентов, которым эти данные вообще не нужны. 

**Как работает «под капотом»:**
Каждый экземпляр компонента во Vue имеет свой внутренний объект для хранения «предоставленных» (provided) значений.
- Когда вы вызываете `provide(key, value)`, Vue записывает это значение в этот внутренний объект текущего компонента.
- Когда глубоко вложенный компонент вызывает `inject(key)`, Vue начинает подниматься вверх по дереву компонентов (как по прототипному наследованию в JS) и ищет первое совпадение по ключу.
- Если передать в `provide` реактивную переменную (например, `ref`), то связь сохранится, и компонент-потребитель будет автоматически перерисовываться при её изменении.

### Синтаксис и База

Функции импортируются из `vue` и используются в `<script setup>`.

**Провайдер (Родитель/Предок):**
```javascript
import { provide, ref } from 'vue'

const theme = ref('dark')
// Первый аргумент — ключ (строка или Symbol), второй — значение
provide('themeKey', theme) 
```

**Потребитель (Любой потомок ниже по дереву):**
```javascript
import { inject } from 'vue'

// Ищем значение по ключу. Второй аргумент (опционально) — значение по умолчанию
const theme = inject('themeKey', 'light') 
```

### Сравнение с React (Аналогии и Отличия)

- **`provide / inject` = `Context API` + `useContext`.**

- **Отсутствие компонента-обертки:** 
	- **В React:** Вам нужно создать контекст (`createContext`), а затем физически обернуть дерево в JSX-компонент: `<ThemeContext.Provider value={theme}> ... </ThemeContext.Provider>`.
	- **Во Vue:** Никаких оберток в шаблоне! Вы просто пишете `provide()` прямо внутри скрипта любого компонента. С этого момента этот компонент становится провайдером для всех своих детей.

- *Ключи доступа (Критическое отличие):**
	- **В React:** Ключом является сам объект контекста (вы передаете его в `useContext(MyContext)`).
	- **Во Vue:** Ключом выступает обычная **строка** (например, `'themeKey'`) или **Symbol** (чтобы избежать конфликта имен).

### Важные нюансы (Где можно выстрелить в ногу)

1. **Мутация данных не там, где надо:**
   Если вы прокинули реактивный объект вниз, потомок может случайно его изменить (`theme.value = 'light'`). Это сломает предсказуемость кода, так как вы не поймете, кто именно из глубоких потомков изменил стейт.
   *Правило хорошего тона (Best Practice):* Мутировать стейт должен **только тот компонент, который его создал (провайдер)**. 
   *Решение:* Передавайте вниз данные, обернутые в `readonly()`, а для изменений передавайте отдельную функцию-мутатор (прямо как в React вы передаете стейт и сеттер в value контекста).

2. **Использование строковых ключей в больших проектах:**
   В маленьких приложениях писать `provide('user', data)` нормально. Но в больших строковые ключи могут пересечься. Там принято использовать `Symbol` и выносить их в отдельный файл (например, `keys.js`).

### Пример для заметок

В этом примере мы создадим корневой компонент, промежуточный (который ничего не знает о данных) и глубоко вложенный.

**App.vue (Провайдер - "Дедушка")**
```vue
<template>
  <div class="app">
    <h1>Корневой компонент</h1>
    <!-- Обратите внимание: мы НЕ передаем пропсы в MiddleComponent! -->
    <MiddleComponent />
  </div>
</template>

<script setup>
import { ref, provide, readonly } from 'vue'
import MiddleComponent from './MiddleComponent.vue'

// 1. Создаем реактивное состояние
const currentUser = ref({ name: 'Алиса', role: 'admin' })

// 2. Создаем функцию для изменения этого состояния (мутатор)
const updateName = (newName) => {
  currentUser.value.name = newName
}

// 3. Провайдим данные. 
// Оборачиваем в readonly, чтобы дети не могли сделать user.value.name = 'Боб' напрямую.
provide('user', readonly(currentUser))

// 4. Провайдим функцию-мутатор
provide('updateUser', updateName)
</script>
```

**MiddleComponent.vue ("Родитель" - Промежуточное звено)**
```vue
<template>
  <div class="middle">
    <!-- Я просто рендерю детей, пропсы через меня не идут -->
    <DeepChildComponent />
  </div>
</template>

<script setup>
import DeepChildComponent from './DeepChildComponent.vue'
</script>
```

**DeepChildComponent.vue (Потребитель - "Внук")**
```vue
<template>
  <div class="child">
    <!-- Vue автоматически "распакует" ref в шаблоне -->
    <p>Привет, {{ user.name }} (Роль: {{ user.role }})</p>
    
    <button @click="changeName">Сменить имя</button>
  </div>
</template>

<script setup>
import { inject } from 'vue'

// 1. Получаем (инжектим) данные. 
// Второй аргумент — fallback на случай, если провайдер не найден
const user = inject('user', { name: 'Гость' })

// 2. Инжектим функцию-мутатор
const updateNameFn = inject('updateUser')

const changeName = () => {
  // Вызываем функцию дедушки. 
  // Мы не мутируем user напрямую, мы просим дедушку сделать это!
  if (updateNameFn) {
    updateNameFn('Боб (изменено внуком)')
  }
}
</script>
```

**Резюме для React-разработчика:**
Provide/Inject — это легковесный, встроенный Context API без лишнего визуального шума в шаблоне (`<Provider>`). Используйте его, когда данные нужны "где-то глубоко внизу", но не забывайте про `readonly()`, чтобы не получить спагетти-код из мутаций!
