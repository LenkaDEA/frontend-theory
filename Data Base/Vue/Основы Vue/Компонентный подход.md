## Компонентный подход: SFC и архитектура

### Концепция и Теория

Vue базируется на **Single File Components (SFC)** — файлах `.vue`, которые объединяют логику, разметку и стили.

**Как это работает «под капотом»:**

В отличие от React, где компонент — это просто функция, возвращающая дерево объектов (VNode), Vue-компонент проходит через **компилятор шаблонов**.

1. Компилятор анализирует ваш `<template>` и превращает его в высокооптимизированную рендер-функцию.

2. При компиляции Vue расставляет «патч-флаги» (битовые маски). Он заранее знает, какая часть текста динамическая, а какая — статичная.

3. **Результат:** При обновлении данных Vue не делает полный diff всего поддерева (как React), а прыгает сразу к динамическим узлам.

### Синтаксис и База

В Vue 3 стандартом является `<script setup>`. Это синтаксический сахар, который делает код лаконичным и автоматически пробрасывает все объявленные переменные в шаблон.

Фрагмент кода

```
<script setup>
// Вся логика тут. Импорты, переменные и функции доступны в template автоматически.
import MyChild from './MyChild.vue';
const title = "Hello Vue";
</script>

<template>
  <div>
    <h1>{{ title }}</h1>
    <MyChild />
  </div>
</template>

<style scoped>
/* Стили применятся только к этому компоненту */
</style>
```

### Сравнение с React

|**Фича**|**React**|**Vue 3**|
|---|---|---|
|**Формат**|JSX (JS внутри JS)|SFC (HTML-like шаблоны)|
|**Обновление**|Перезапуск всей функции компонента|Вызов только зависимого эффекта (Proxy)|
|**Стили**|СSS-in-JS, CSS Modules|Встроенный атрибут `scoped`|
|**Умные/Глупые**|Контейнеры vs Компоненты (HOC/Hooks)|Аналогично, разделение по ответственности|

**Принципиальная разница в жизненном цикле:**

В React каждое изменение стейта — это «перерисовать всё заново» (если нет `memo`). В Vue изменение реактивной переменной вызывает только те части кода, которые от нее зависят. Функция внутри `<script setup>` выполняется **один раз** при инициализации, а не при каждом рендере.

---
### Важные нюансы

1. **Потеря реактивности:** Самая частая ошибка React-разработчика — деструктуризация пропсов или реактивных объектов.
    - _Нельзя:_ `const { name } = props;` — связь с источником разорвется.
    - _Нужно:_ использовать `toRefs(props)` или обращаться напрямую `props.name`.

2. **Стили:** `scoped` работает через добавление уникального data-атрибута элементам. Это удобнее, чем CSS Modules, но нужно помнить про селектор `:deep()`, если нужно стилизовать дочерний компонент из родителя.

### Умный vs Глупый компоненты

**Smart Component (UserContainer.vue)** — отвечает за данные.

```
<script setup>
import { ref, onMounted } from 'vue';
import UserCard from './UserCard.vue';

const user = ref(null);
const isLoading = ref(true);

onMounted(async () => {
  const res = await fetch('https://api.example.com/user/1');
  user.value = await res.json();
  isLoading.value = false;
});

const handleUpdate = (newName) => {
  if (user.value) user.value.name = newName;
};
</script>

<template>
  <div v-if="isLoading">Загрузка...</div>
  <UserCard 
    v-else 
    :name="user.name" 
    @update-name="handleUpdate" 
  />
</template>
```

**Dumb Component (UserCard.vue)** — только отображение и UI.

Фрагмент кода

```
<script setup>
// Аналог PropTypes/TypeScript interfaces в React
defineProps({
  name: String
});

// Объявляем события, которые компонент может генерировать
const emit = defineEmits(['update-name']);

const changeName = () => {
  emit('update-name', 'Новое Имя');
};
</script>

<template>
  <div class="card">
    <h3>Пользователь: {{ name }}</h3>
    <button @click="changeName">Изменить имя</button>
  </div>
</template>

<style scoped>
.card { border: 1px solid #ccc; padding: 1rem; }
</style>
```
