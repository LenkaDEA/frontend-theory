### Концепция и Теория

Жизненный цикл решает задачу управления побочными эффектами (подписки, таймеры, запросы) в строго определенные моменты.

**Как это работает «под капотом»:**

Когда Vue создает компонент, он инициализирует экземпляр (internal instance). В процессе рендеринга и патчинга DOM, Vue вызывает внутренние функции-коллбэки. Эти функции «зарегистрированы» внутри текущего экземпляра компонента. Именно поэтому хуки можно вызывать только синхронно внутри `<script setup>`: Vue должен понимать, к какому именно компоненту привязать этот `onMounted`.

### Синтаксис и База

В Composition API все хуки импортируются из `vue` и принимают callback-функцию.

```JS
<script setup>
import { onMounted, onUnmounted, onUpdated } from 'vue';

onMounted(() => {
  console.log('Компонент вмонтирован в DOM');
});

onUnmounted(() => {
  console.log('Компонент удален, чистим хвосты');
});
</script>
```

**Основные хуки:**

https://ru.vuejs.org/api/composition-api-lifecycle.html

- `onBeforeMount` / `onMounted`: Перед и после появления в DOM.

- `onBeforeUpdate` / `onUpdated`: Перед и после изменения данных, вызвавших перерендер.

- `onBeforeUnmount` / `onUnmounted`: Перед и после удаления компонента.

- `onActivated` / `onDeactivated`: Для компонентов внутри `<KeepAlive>`.

### Сравнение с React

В React есть один универсальный `useEffect`, поведение которого зависит от массива зависимостей. Во Vue хуки **семантически разделены**.

|**Стадия**|**React**|**Vue 3**|
|---|---|---|
|**Mount**|`useEffect(() => {...}, [])`|`onMounted(() => {...})`|
|**Unmount**|`useEffect(() => { return () => {...} }, [])`|`onUnmounted(() => {...})`|
|**Update**|`useEffect(() => {...})` (каждый раз)|`onUpdated(() => {...})`|
|**Specific Change**|`useEffect(() => {...}, [data])`|`watch(data, () => {...})` (это не хук ЖЦ)|

**Принципиальная разница:**

1. **Явность:** Во Vue нет нужды возвращать функцию для очистки из `onMounted`. Для этого есть отдельный `onUnmounted`.

2. **Частота вызовов:** В React код внутри `useEffect` может запускаться многократно при изменении зависимостей. В Vue `onMounted` гарантированно запустится **один раз** за всю жизнь компонента.

3. **Синхронность:** Хуки во Vue регистрируются один раз при инициализации. Вам не нужно беспокоиться о том, что хук «пересоздается» на каждом рендере.

### Важные нюансы

1. **Где `created`?** В Composition API хуков `beforeCreate` и `created` нет. Весь код внутри `<script setup>` и есть этап создания компонента.

2. **Синхронный вызов:** Нельзя оборачивать хуки в `setTimeout` или `async` функции.

    - _Плохо:_ `setTimeout(() => { onMounted(...) }, 100);` — Vue потеряет контекст экземпляра и хук не отработает.

3. **SSR:** Большинство хуков (кроме `beforeCreate` / `created` аналогов) **не запускаются** на сервере. `onMounted` работает только в браузере.

### Пример для заметок: Логика таймера

Этот пример показывает классический паттерн: установка ресурса при старте и его очистка при уходе.

```js
<script setup>
import { ref, onMounted, onUnmounted } from 'vue';

const seconds = ref(0);
let timer = null;

// Аналог componentDidMount
onMounted(() => {
  console.log('Таймер запущен');
  timer = setInterval(() => {
    seconds.value++;
  }, 1000);
});

// Аналог componentWillUnmount
onUnmounted(() => {
  console.log('Таймер остановлен, память очищена');
  clearInterval(timer);
});
</script>

<template>
  <div>
    <p>Вы находитесь здесь уже {{ seconds }} секунд.</p>
  </div>
</template>
```
