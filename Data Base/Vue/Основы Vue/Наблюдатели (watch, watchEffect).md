### Концепция и Теория

**Какую задачу решает:** Позволяет выполнить произвольный код в ответ на изменение конкретного реактивного состояния.

**Как работает «под капотом»:** Vue регистрирует переданную вами функцию (эффект) и связывает ее с указанными реактивными источниками. Когда Proxy-объект сообщает об изменении (срабатывает сеттер), Vue ставит этот эффект в очередь микрозадач (чтобы избежать лишних срабатываний, если вы меняете несколько переменных подряд). После обновления компонента эффект выполняется.

В Vue 3 есть два основных инструмента для этого, и у них разная философия:

- `watch`: **Явный**. Вы сами говорите, за чем следить. Выполняется лениво (только при изменении).

- `watchEffect`: **Неявный**. Сам понимает, за чем следить, анализируя код внутри. Выполняется сразу при инициализации.

### Синтаксис и База

**1. `watch` (Явное наблюдение)**

Принимает два аргумента: источник данных и коллбэк. Коллбэк получает новое и старое значения.

```vue
<script setup>
import { ref, watch } from 'vue';

const userId = ref(1);

// Следим за конкретной переменной
watch(userId, (newValue, oldValue) => {
  console.log(`ID изменился с ${oldValue} на ${newValue}`);
  // Делаем fetch запрос...
});
</script>
```

**2. `watchEffect` (Автоматическое отслеживание)**

Принимает только одну функцию. Запускается немедленно, запоминает все реактивные переменные внутри себя и перезапускается при их изменении.

```vue
<script setup>
import { ref, watchEffect } from 'vue';

const count = ref(0);

// Сработает сразу (выведет 0), а затем при каждом изменении count
watchEffect(() => {
  console.log(`Текущий счетчик: ${count.value}`);
});
</script>
```

### Сравнение с React

Оба наблюдателя — это аналоги `useEffect`, но с разделенными обязанностями. В React `useEffect` делает всё: и реагирует на изменения, и монтирует, и демонтирует. Vue разделяет хуки ЖЦ и хуки реактивности.

|**Фича**|**React (useEffect)**|**Vue 3 (watch / watchEffect)**|
|---|---|---|
|**Явность**|Нужно писать массив зависимостей|`watch` — явный, `watchEffect` — авто-зависимости (как `useMemo`/`computed`)|
|**Доступ к prev state**|Нужен кастомный хук (`usePrevious`)|`watch` дает `oldValue` из коробки|
|**Первый запуск**|Всегда запускается при mount|`watch` — ленивый (ждет изменений). `watchEffect` — запускается сразу.|
|**Чистота эффекта**|Заменяет собой lifecycle hooks|Используется **только** для реакции на данные|

**Принципиальная разница:** * В `useEffect` забыть добавить переменную в массив зависимостей — это классический баг. Во Vue `watchEffect` никогда не забудет зависимость.

- С другой стороны, `watch` во Vue дает точечный контроль: можно зависеть от изменения переменной `A`, но внутри коллбэка читать переменную `B`, не вызывая бесконечный цикл (в React линтер заставил бы добавить `B` в зависимости).

### Важные нюансы

1. **Слежение за свойствами объекта (Геттеры в watch):** Если вы хотите следить не за всем реактивным объектом, а только за одним его полем, нужно передать геттер (функцию).
	- _Нельзя:_ `watch(user.age, ...)`
	- _Можно:_ `watch(() => user.age, ...)`

2. **Глубокое слежение (`deep: true`):** Если вы передаете в `watch` объект `reactive` или массив, он неявно становится глубоким (отслеживает все вложенные мутации). Но если это объект внутри `ref`, нужно явно передать опцию `{ deep: true }`. Это тяжелая операция, используйте осторожно.

3. **Моментальный запуск `watch` (`immediate: true`):** Если вам нужно, чтобы `watch` сработал при инициализации компонента (как `useEffect`), передайте третьим аргументом `{ immediate: true }`.

4. **Время выполнения (Flush Timing):** По умолчанию наблюдатели срабатывают **до** обновления DOM. Если вам внутри `watch` нужен доступ к уже обновленному DOM (например, измерить высоту элемента), используйте `{ flush: 'post' }` (или хук `watchPostEffect`).

### Пример для заметок: Сохранение черновика

Хороший пример, показывающий разницу в применении:

```vue
<script setup>
import { ref, reactive, watch, watchEffect } from 'vue';

const postId = ref(1);
const postContent = reactive({
  title: '',
  body: ''
});
const isSaving = ref(false);

// Пример 1: ЯВНЫЙ watch (Загрузка данных при смене ID)
// Нам нужно старое значение, и мы не хотим триггерить это при смене title
watch(postId, async (newId, oldId) => {
  console.log(`Переходим со статьи ${oldId} на ${newId}`);
  // fetchPost(newId)...
});

// Пример 2: АВТОМАТИЧЕСКИЙ watchEffect (Автосохранение черновика)
// Нам неважно, что именно изменилось (title или body), просто сохраняем
watchEffect(() => {
  // Вызовется сразу при маунте и каждый раз при мутации postContent
  const draft = JSON.stringify(postContent);
  localStorage.setItem('draft', draft);
  console.log('Черновик автосохранен:', draft);
});

// Пример 3: Глубокий watch с опциями
watch(
  () => postContent,
  (newVal) => {
    isSaving.value = true;
    // Имитация отправки на бэкенд
    setTimeout(() => { isSaving.value = false; }, 500);
  },
  { deep: true } // Обязательно, так как мы возвращаем объект из геттера
);
</script>

<template>
  <div class="editor">
    <p>Редактируем пост ID: {{ postId }}</p>
    <button @click="postId++">Следующий пост</button>
    
    <hr />
    
    <input v-model="postContent.title" placeholder="Заголовок" />
    <textarea v-model="postContent.body" placeholder="Текст"></textarea>
    
    <p v-if="isSaving">Сохранение на сервер...</p>
  </div>
</template>
```
