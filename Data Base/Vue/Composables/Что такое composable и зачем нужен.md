### Техническое определение: Что это такое?

На базовом уровне Composable — это обычная JavaScript/TypeScript функция, которая использует встроенные реактивные API Vue (такие как `ref`, `reactive`, `computed`, `watch`) для инкапсуляции и переиспользования логики.

Их называют "stateful logic functions" (функции с сохранением состояния), потому что в отличие от обычных утилитарных функций (например, форматирования даты), композаблы управляют собственным реактивным состоянием и могут привязываться к жизненному циклу компонента (через `onMounted`, `onUnmounted` и т.д.).

По сути, это фабрика, которая создает изолированный кусочек реактивного состояния и методы для его изменения, а затем возвращает их компоненту.

### Проблема и решение: Options API vs Composition API

Чтобы понять ценность Composables, нужно посмотреть на то, как Vue работал раньше (и может работать сейчас) с Options API.

В Options API код компонента жестко структурирован по "опциям": `data()` для состояния, `methods` для функций, `computed` для вычисляемых свойств, `watch` для эффектов и хуки жизненного цикла.

- Проблема: Когда компонент разрастается и начинает отвечать за 3-4 разные фичи (например, поиск, пагинация и сортировка), логика _одной_ фичи размазывается по всему файлу. Состояние поиска лежит в `data`, его обработчик в `methods`, а эффект в `watch`. Это делает код трудночитаемым (эффект "спагетти-кода") и почти невозможным для переиспользования без костылей вроде Mixins (которые приносили конфликты имен и неявные зависимости).
- Решение (Composition API): Позволяет группировать код не по _типу опции_, а по _логической фиче_. Всю логику поиска (состояние, методы, эффекты) можно написать в одном месте, а затем вынести в отдельную функцию — Composable (например, `useSearch()`).

### Сравнение с React Hooks: Главное концептуальное отличие

Это самый важный момент для React-разработчика. Внешне `useMouse()` во Vue выглядит точно так же, как `useMouse()` в React. Но их жизненный цикл кардинально отличается.

- В React: Функция компонента — это и есть render-функция. Хуки вызываются на каждый рендер. Из-за этого React полагается на порядок вызова хуков (отсюда строгие "Rules of Hooks" — нельзя использовать хуки в `if` или `for`). Также из-за постоянных перерисовок возникают проблемы "stale closures" (замыкания на старые данные), что вынуждает нас постоянно использовать `useCallback`, `useMemo` и тщательно следить за массивами зависимостей (dependency arrays).

- Во Vue 3: Функция `setup()` (или блок `<script setup>`) — это не render-функция. Это функция-инициализатор, которая вызывается ровно один раз при создании компонента.
    - Композабл, вызванный внутри `setup`, отрабатывает единожды.
    - Он создает реактивные связи (через Proxy).
    - Когда состояние меняется, Vue точечно обновляет DOM, но _сама функция `setup` и твои композаблы больше не перезапускаются_.

Следствия для тебя как разработчика:

1. Во Vue нет "Rules of Hooks". Ты технически можешь вызвать композабл внутри условия (хотя для жизненного цикла это плохая практика).
2. Тебе не нужны `useMemo`, `useCallback` или массивы зависимостей `[a, b]`. Vue автоматически отслеживает зависимости на основе того, какие реактивные переменные (refs) были прочитаны внутри эффекта или вычисляемого свойства.
3. Нет проблемы "stale closures". Переменные всегда актуальны, потому что ты обращаешься к объекту-ссылке (`myVar.value`), а не к значению из прошлого рендера.

### Преимущества: Переиспользование и читаемость

Благодаря тому, что Composition API отвязывает логику от контекста компонента (магического `this`, который был в Options API), Composables дают огромные преимущества:

- Идеальное переиспользование: Ты можешь вынести любую логику (работа с API, веб-сокетами, локальным хранилищем, подписками на события окна) в отдельный файл `useSomething.ts`. Этот код становится полностью независимым от UI.
- Читаемость крупных компонентов: Сложный компонент на 1000 строк превращается в элегантный оркестратор:

```vue
<script setup>
import { useSearch } from './composables/useSearch'
import { usePagination } from './composables/usePagination'

// Вся сложная логика скрыта внутри, компонент только связывает данные
const { searchQuery, results, performSearch } = useSearch()
const { currentPage, nextPage } = usePagination(results)
</script>
```
- Отличная поддержка TypeScript: В отличие от Options API, где типизация `this` всегда была головной болью, Composables — это просто функции, которые принимают аргументы и возвращают объекты. TypeScript понимает их идеально "из коробки" без дополнительных усилий.

Резюме для React-разработчика: Composables — это как React Hooks, из которых убрали всю боль, связанную с жизненным циклом рендеринга, мемоизацией и массивами зависимостей, оставив только чистую реактивность и инкапсуляцию логики.
