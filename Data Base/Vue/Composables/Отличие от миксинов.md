### Проблема Mixins: Неявность и Коллизии

Миксин во Vue 2 — это объект, содержащий опции компонента (`data`, `methods`, `mounted` и т.д.), который "вмешивается" (merges) в целевой компонент.

Неявные источники данных (Implicit Sources) Представь компонент, который использует три миксина:

```js
export default {
  mixins: [SearchMixin, PaginationMixin, SortMixin],
  mounted() {
    this.fetchData(); // Откуда взялся этот метод?
    console.log(this.isLoading); // А это состояние из какого миксина?
  }
}
```

Глядя на код компонента, невозможно сказать, откуда пришли `fetchData` или `isLoading`. Тебе нужно открыть файлы всех трех миксинов и прочитать их реализацию. В крупных проектах это превращается в детективное расследование, сильно замедляя разработку и рефакторинг.

Коллизии имен (Name Collisions) Что произойдет, если и `SearchMixin`, и `PaginationMixin` объявляют в `data` переменную `isLoading` или метод `reset()`? Vue попытается слить их вместе (merge strategies). В случае с методами могут вызваться оба (что часто приводит к двойным запросам к API), а в случае с состоянием — одно значение тихо перезапишет другое. Это порождает непредсказуемые, трудноотловимые баги. Разработчикам приходилось придумывать странные префиксы (например, `this.search_isLoading`), чтобы избежать конфликтов.

### Решение в Composables: Явный импорт и деструктуризация

Composables решают эти проблемы, опираясь на стандартные механизмы JavaScript (ES Modules), а не на магию фреймворка.

Вместо слияния объектов мы вызываем функции и явно забираем то, что нам нужно:

```js
import { useSearch } from './useSearch'
import { usePagination } from './usePagination'

export default {
  setup() {
    // 1. Явный источник: мы точно видим, откуда пришел isLoading
    const { isLoading, fetchData } = useSearch()
    
    // 2. Решение коллизий: нативная возможность JS переименовать переменную
    const { isLoading: isPaginationLoading, reset } = usePagination()

    return { isLoading, fetchData, isPaginationLoading, reset }
  }
}
```

_(В `<script setup>` возвращать переменные не нужно, они доступны в шаблоне автоматически, но суть остается той же)._

Здесь нет скрытого слияния. Если два композабла возвращают одинаковые имена, IDE и компилятор JS сразу выдадут ошибку о дублировании переменных, заставляя тебя явно разрешить конфликт через алиасы (`isLoading: isPaginationLoading`).

### Прозрачность кода: Отслеживание переменных в шаблоне

Разница в прозрачности особенно ярко проявляется при чтении шаблонов (`<template>`).

С миксинами:

```vue
<template>
  <button @click="resetFilters" :disabled="isProcessing">
    {{ searchQuery }}
  </button>
</template>
```

<template>

<button @click="resetFilters" :disabled="isProcessing">

{{ searchQuery }}

</button>

</template>

Если ты новый разработчик на проекте, ты смотришь на `isProcessing` и не понимаешь, где оно определено. В самом компоненте его нет. Ты ищешь по миксинам. IDE часто не может помочь (Cmd/Ctrl + Click не работает), потому что контекст `this` собирается динамически во время выполнения.

С композаблами:

<template>

<button @click="resetFilters" :disabled="isProcessing">

{{ searchQuery }}

</button>

</template>
```vue
<template>
  <button @click="resetFilters" :disabled="isProcessing">
    {{ searchQuery }}
  </button>
</template>

<script setup>
import { useSearch } from './useSearch'
// Cmd/Ctrl + Click на isProcessing в шаблоне приведет тебя прямо на эту строку:
const { searchQuery, isProcessing, resetFilters } = useSearch()
</script>
```

Связь между шаблоном и логикой становится абсолютно прозрачной. Поток данных однонаправленный: от импорта -> к деструктуризации -> в шаблон.

### Типизация: Почему TypeScript ненавидит миксины

Это, пожалуй, главный гвоздь в крышку гроба миксинов для современных проектов.

Миксины и TypeScript: Миксины работают за счет мутации контекста `this`. Для TypeScript динамическое изменение формы объекта `this` во время выполнения — это кошмар. Чтобы типизировать миксин во Vue 2, приходилось писать сложные `Intersection Types` (`Component & MixinA & MixinB`) или использовать громоздкий `Vue.extend()`. Даже при этом автокомплит часто ломался, а типы выводились некорректно. Разработчики тратили больше времени на борьбу с TS, чем на написание фич.

Composables и TypeScript: Композаблы — это просто функции. TypeScript идеально понимает функции.

```js
function useSearch(): { searchQuery: Ref<string>, isProcessing: Ref<boolean> } {
  // ...
}
```

Когда ты вызываешь `const { isProcessing } = useSearch()`, TypeScript автоматически выводит тип `Ref<boolean>` для `isProcessing`. Никакой магии, никаких сложных манипуляций с `this`. Типизация работает "из коробки", автокомплит в IDE мгновенный и точный.

Итог: Composables превратили переиспользование логики во Vue из "черной магии" фреймворка в предсказуемый, строго типизированный и легко читаемый JavaScript-код.
