Написание качественных Composables во Vue 3 — это искусство создания гибких, переиспользуемых и безопасных с точки зрения типов абстракций. Поскольку ты уже знаком с паттернами React, многие вещи покажутся тебе логичным развитием идей хуков, но с учетом особенностей реактивности Vue.

Вот подробный разбор лучших практик (Best Practices) и паттернов.

### Конвенции: Префикс `use...` и возвращаемые данные

Префикс `use...` Как и в React, во Vue принято называть композаблы с префикса `use` (например, `useUser`, `useFetch`). Это не просто дань моде, а важный сигнал для других разработчиков:

- Эта функция содержит stateful logic (состояние).
- Она использует реактивные API Vue (refs, reactive, watch).
- Ее нужно вызывать синхронно внутри функции `setup()` (или в `<script setup>`), чтобы она могла корректно привязаться к текущему инстансу компонента.

Возвращаемые данные: Объекты vs Массивы В React мы часто возвращаем кортежи (массивы) из хуков: `const [value, setValue] = useState()`. Это удобно для переименования переменных "на лету". Во Vue Best Practice — возвращать объекты.

Почему?

1. Масштабируемость: Композаблы во Vue часто возвращают много сущностей (состояние, методы, флаги загрузки, ошибки). Запоминать порядок элементов в массиве из 5-6 элементов — мучение.
2. Деструктуризация: С объектами ты берешь только то, что нужно. Переименование тоже делается легко: `const { data: userData, isLoading } = useUser()`.
3. Реактивность: Возвращая объект с `ref`-ами, ты сохраняешь их реактивность при деструктуризации в компоненте.

### Гибкость аргументов: Паттерн `toValue` (или `unref`)

Хороший композабл должен быть универсальным. Представь функцию `useFetch(url)`. Пользователь может захотеть передать туда:

1. Обычную строку: `useFetch('https://api.com/users')`
2. Реактивную ссылку (ref), которая может измениться: `useFetch(userIdRef)`
3. Геттер (функцию), вычисляющую значение: `useFetch(() => '/users/' + props.id)`

Чтобы композабл "проглатывал" все три варианта, во Vue 3.3+ добавили утилиту `toValue()` (в более старых версиях использовался `unref()`, но он не поддерживал геттеры).

В TypeScript для типизации таких аргументов используется тип `MaybeRefOrGetter<T>`. Это позволяет внутри композабла всегда получать актуальное значение, независимо от того, что передал разработчик, и при необходимости "навесить" на него `watch`.

### Жизненный цикл внутри: `onMounted`, `watch` и инкапсуляция

Да, использовать хуки жизненного цикла внутри композаблов не просто можно, а нужно! Это основа их инкапсуляции.

Когда ты вызываешь `onMounted` или `onUnmounted` внутри композабла, Vue автоматически привязывает их к компоненту, в `setup()` которого был вызван этот композабл.

Как это влияет на инкапсуляцию: Тебе больше не нужно "протекать" деталями реализации в компонент. Например, если композабл слушает события окна (`window.addEventListener`), он сам же должен их отписать в `onUnmounted`. Компонент, вызывающий `useWindowSize()`, вообще не должен знать, что там внутри вешаются какие-то слушатели. Он просто получает реактивные ширину и высоту.

_Важное правило:_ Чтобы Vue понял, к какому компоненту привязать `onMounted`, композабл должен быть вызван синхронно в корне `setup()`. Если вызвать его внутри `setTimeout` или после `await` (без правильной настройки), Vue потеряет контекст текущего компонента.

### Пример на TypeScript: Создаем `useFetch`

Давай напишем мощный, типизированный композабл для работы с API, который объединяет все вышеописанные паттерны. Он будет принимать гибкий URL, управлять состоянием и автоматически перезапрашивать данные при изменении URL.


```ts
import { ref, watchEffect, toValue, type MaybeRefOrGetter } from 'vue'

// Интерфейс возвращаемого объекта
export interface UseFetchReturn<T> {
  data: import('vue').Ref<T | null>
  error: import('vue').Ref<Error | null>
  isLoading: import('vue').Ref<boolean>
  execute: () => Promise<void>
}

export function useFetch<T>(url: MaybeRefOrGetter<string>): UseFetchReturn<T> {
  // 1. Инициализация реактивного состояния
  const data = ref<T | null>(null)
  const error = ref<Error | null>(null)
  const isLoading = ref<boolean>(false)

  // 2. Метод для выполнения запроса
  const execute = async () => {
    // Сбрасываем состояние перед новым запросом
    isLoading.value = true
    error.value = null
    
    try {
      // toValue(url) "распакует" ref, вызовет геттер или просто вернет строку
      const currentUrl = toValue(url)
      
      const response = await fetch(currentUrl)
      if (!response.ok) {
        throw new Error(`HTTP error! status: ${response.status}`)
      }
      
      // Присваиваем данные в .value (особенность работы с ref)
      // Приведение типа необходимо, так как TS не знает, что вернет API
      data.value = (await response.json()) as T
    } catch (err) {
      error.value = err instanceof Error ? err : new Error(String(err))
    } finally {
      isLoading.value = false
    }
  }

  // 3. Реактивное отслеживание зависимостей
  // watchEffect автоматически соберет зависимости (в данном случае toValue(url))
  // и перезапустит функцию, если реактивный url изменится.
  watchEffect(() => {
    execute()
  })

  // 4. Возвращаем объект (Best Practice)
  return {
    data,
    error,
    isLoading,
    execute
  }
}
```

Как это используется в компоненте:

```ts
<script setup lang="ts">
import { ref, computed } from 'vue'
import { useFetch } from './composables/useFetch'

interface User {
  id: number
  name: string
}

const userId = ref(1)

// Передаем геттер. Если userId изменится, useFetch автоматически сделает новый запрос!
const { data: user, isLoading, error } = useFetch<User>(() => `https://api.example.com/users/${userId.value}`)

const nextUser = () => {
  userId.value++
}
</script>

<template>
  <div>
    <button @click="nextUser">Следующий пользователь</button>
    
    <div v-if="isLoading">Загрузка...</div>
    <div v-else-if="error">Ошибка: {{ error.message }}</div>
    <div v-else-if="user">
      <h1>{{ user.name }} (ID: {{ user.id }})</h1>
    </div>
  </div>
</template>
```

Этот паттерн делает код невероятно чистым: компонент отвечает только за UI и минимальную бизнес-логику (переключение ID), а вся сложность работы с сетью, состоянием гонки и жизненным циклом надежно инкапсулирована внутри `useFetch`.
